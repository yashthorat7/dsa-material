## What are we solving?

Given a string `s`, return `true` if the `s` can be palindrome after deleting **at most one character** from it.

The question is: **when encountering the first mismatch `s[left] != s[right]`, how do we branch to test whether deleting `s[left]` or `s[right]` yields a valid palindrome?**

**Example 1:**
```
Input:  s = "aba"
Output: true
```

**Example 2:**
```
Input:  s = "abca"
Output: true
Explanation: You could delete the character 'c'.
```

**Example 3:**
```
Input:  s = "abc"
Output: false
```

**Constraints:**
- $1 \le s.\text{length} \le 10^5$
- `s` consists of lowercase English letters.

## Approach 1 — Two Pointers with 1-Mismatch Branching ✅

**Key insight:** Walk Two Pointers `left = 0`, `right = s.size() - 1`.
If `s[left] == s[right]`, continue `left++`, `right--`.
On the first mismatch `s[left] != s[right]`:
We have exactly two choices:
1. Skip `s[left]` and check if `s[left+1..right]` is a palindrome.
2. Skip `s[right]` and check if `s[left..right-1]` is a palindrome.
If either is a palindrome, return `true`. Otherwise return `false`.

```
s = "abca"
left=0 ('a'), right=3 ('a') -> match! left=1, right=2
left=1 ('b'), right=2 ('c') -> MISMATCH!
Branch 1: check substring [2..2] ("c") -> palindrome! -> return true ✓
```

```cpp
class Solution {
public:
    bool validPalindrome(string s) {
        int left = 0, right = s.size() - 1;
        while (left < right) {
            if (s[left] != s[right]) {
                return isPal(s, left + 1, right) || isPal(s, left, right - 1);
            }
            left++;
            right--;
        }
        return true;
    }
private:
    bool isPal(const string& s, int l, int r) {
        while (l < r) {
            if (s[l] != s[r]) return false;
            l++;
            r--;
        }
        return true;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(1)$ |

> **This is the one.** Linear single branch verification.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Already a palindrome `"racecar"` | Triggering skip logic | Loop finishes without mismatch, returns `true` |
| Cannot form palindrome with 1 deletion `"abcde"` | Infinite loop | Both branches fail, returns `false` |
| Two characters `"ab"` | Off-by-one bounds | Deleting either produces single char palindrome, returns `true` |

---

## Pattern Takeaway

When allowed **at most 1 modification/deletion**, proceed greedily until the first conflict, then branch into independent checks for the remaining subproblem.
