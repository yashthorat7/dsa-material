## What are we solving?

You are given an array of integers `nums`. There is a sliding window of size $k$ which moves from the very left of the array to the very right. You can only see the $k$ numbers in the window. Each time the sliding window moves right by one position.

Return the **max sliding window** (the maximum value in each window).

```
 nums = [ 1, 3, -1, -3, 5, 3, 6, 7 ],  k = 3
 
 Window Position                Window Max
 -------------------------      ----------
 [ 1   3  -1] -3   5   3   6   7     -> 3
   1  [3  -1  -3]  5   3   6   7     -> 3
   1   3 [-1  -3   5]  3   6   7     -> 5
   1   3  -1 [-3   5   3]  6   7     -> 5
   1   3  -1  -3  [5   3   6]  7     -> 6
   1   3  -1  -3   5  [3   6   7]    -> 7
 
 Output: [ 3, 3, 5, 5, 6, 7 ]
```

### Input & Output Contract
- **Input:**
  - `nums`: `vector<int>` ($1 \le n \le 10^5$, $-10^4 \le \text{nums}[i] \le 10^4$).
  - `k`: `int` window width ($1 \le k \le n$).
- **Output:**
  - `vector<int>` of size $n - k + 1$ containing the maximum of each sliding window.

### The Core Challenge
A naive scan over each window takes $O(n \cdot k) = 10^{10}$ operations (massive TLE).  
Using a Max-Heap takes $O(n \log n)$.  
To achieve **optimal $O(n)$ linear time**, we maintain a **Monotonic Decreasing Deque of Indices**:
- Any element in the window that is **smaller than a newer element** can never be the maximum in any current or future window and can be popped immediately!

---

**Example 1:**
```
Input:  nums = [1,3,-1,-3,5,3,6,7], k = 3
Output: [3,3,5,5,6,7]
```

**Example 2:**
```
Input:  nums = [1], k = 1
Output: [1]
```

**Constraints:**
- $1 \le \text{nums.length} \le 10^5$
- $-10^4 \le \text{nums}[i] \le 10^4$
- $1 \le k \le \text{nums.length}$

## Approach 1 — Max-Heap with Lazy Deletion ($O(n \log n)$)

### Intuition
Maintain a max-heap storing pairs `{nums[i], i}`. On each window slide, push the incoming element and pop elements from the top of the heap whose indices are out of the current window (`top.index <= i - k`).

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        priority_queue<pair<int, int>> pq;
        vector<int> result;
        
        for (int i = 0; i < nums.size(); i++) {
            pq.push({nums[i], i});
            if (i >= k - 1) {
                // Lazily evict elements that are outside the current window
                while (pq.top().second <= i - k) {
                    pq.pop();
                }
                result.push_back(pq.top().first);
            }
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n \log n)$ | Each element is pushed and popped at most once in a heap of size up to $n$. |
| **Space** | $O(n)$ | Max-heap stores up to $n$ elements. |

## Approach 2 — Monotonic Decreasing Deque of Indices ✅

### Key Insight
Maintain a double-ended queue `dq` storing **array indices** in strictly decreasing order of their corresponding values:
1. **Evict Expired Front:** If `dq.front() <= i - k`, the index at the front has slid out of the active window $\implies$ `dq.pop_front()`.
2. **Enforce Monotonicity at Back:** While `!dq.empty() && nums[dq.back()] <= nums[i]`, pop `dq.pop_back()`.
   - *Why?* The new element `nums[i]` is both greater (or equal) and newer than `nums[dq.back()]`, rendering `nums[dq.back()]` obsolete forever!
3. **Push New Index:** `dq.push_back(i)`.
4. **Collect Maximum:** Once the initial window has filled ($i \ge k - 1$), the front of the deque `nums[dq.front()]` is guaranteed to be the window maximum!

```
nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3

i=0 (1):  dq = [0]
i=1 (3):  3 > 1 -> pop 0 -> dq = [1]
i=2 (-1): -1 < 3 -> dq = [1, 2] -> window 0 max = nums[1] = 3
i=3 (-3): -3 < -1 -> dq = [1, 2, 3] -> window 1 max = nums[1] = 3
i=4 (5):  front index 1 is expired (1 <= 4-3=1) -> pop_front!
          5 > -3 and 5 > -1 -> pop 3, pop 2 -> dq = [4] -> window 2 max = 5
i=5 (3):  3 < 5 -> dq = [4, 5] -> window 3 max = 5
i=6 (6):  6 > 3 and 6 > 5 -> pop 5, pop 4 -> dq = [6] -> window 4 max = 6
i=7 (7):  7 > 6 -> pop 6 -> dq = [7] -> window 5 max = 7

Result: [ 3, 3, 5, 5, 6, 7 ] ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        int n = nums.size();
        deque<int> dq; // Monotonic deque storing array indices
        vector<int> result;
        result.reserve(n - k + 1);
        
        for (int i = 0; i < n; i++) {
            // 1. Evict index that has fallen out of current window
            if (!dq.empty() && dq.front() <= i - k) {
                dq.pop_front();
            }
            
            // 2. Discard all elements from back that are <= nums[i]
            while (!dq.empty() && nums[dq.back()] <= nums[i]) {
                dq.pop_back();
            }
            
            // 3. Push current index to back
            dq.push_back(i);
            
            // 4. Record maximum once first window of size k is formed
            if (i >= k - 1) {
                result.push_back(nums[dq.front()]);
            }
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Each index is pushed into `dq` once and popped at most once (amortized $O(1)$ per step). |
| **Space** | $O(k)$ | Deque stores at most $k$ indices at any moment. |

> **This is the one.** Clean, robust, optimal $O(n)$ sliding window maximum.

## Approach 3 — Prefix & Suffix Block Partitioning ($O(n)$ Time)

### Intuition
Divide the array into blocks of size $k$. Compute `prefixMax` from start to end within each block, and `suffixMax` from end to start within each block. The maximum in sliding window $[i \dots i + k - 1]$ is $\max(\text{suffixMax}[i], \text{prefixMax}[i + k - 1])$.

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        int n = nums.size();
        if (n == 0 || k == 0) return {};
        if (k == 1) return nums;
        
        vector<int> prefix(n), suffix(n);
        prefix[0] = nums[0];
        suffix[n - 1] = nums[n - 1];
        
        for (int i = 1; i < n; i++) {
            // Block boundaries: reset at multiples of k
            prefix[i] = (i % k == 0) ? nums[i] : max(prefix[i - 1], nums[i]);
            
            int j = n - 1 - i;
            suffix[j] = ((j + 1) % k == 0) ? nums[j] : max(suffix[j + 1], nums[j]);
        }
        
        vector<int> result(n - k + 1);
        for (int i = 0; i <= n - k; i++) {
            result[i] = max(suffix[i], prefix[i + k - 1]);
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Three linear passes across array. |
| **Space** | $O(n)$ | Prefix and suffix max arrays. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Window Size `k = 1`** | `nums = [1, 2, 3], k = 1` | Loop indexing | Returns `[1, 2, 3]` directly. |
| **Strictly Decreasing Array** | `[5, 4, 3, 2, 1], k = 2` | Stale index accumulation | `dq.front() <= i - k` evicts expired elements on schedule. |
| **All Identical Elements** | `[2, 2, 2, 2], k = 2` | Duplicate retention | `nums[dq.back()] <= nums[i]` pops older duplicates, maintaining 1 index. |
