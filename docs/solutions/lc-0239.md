## What are we solving?

You are given an array of integers `nums`, there is a sliding window of size `k` which is moving from the very left of the array to the very right. You can only see the `k` numbers in the window. Each time the sliding window moves right by one position.

Return the **max sliding window**.

The challenge is: **how does a monotonic decreasing deque maintain the maximum element in $O(1)$ amortized time per window slide?**

**Example 1:**
```
Input:  nums = [1,3,-1,-3,5,3,6,7], k = 3
Output: [3,3,5,5,6,7]
Explanation: Window position                Max
---------------               -----
[1  3  -1] -3  5  3  6  7       3
 1 [3  -1  -3] 5  3  6  7       3
 1  3 [-1  -3  5] 3  6  7       5
 1  3  -1 [-3  5  3] 6  7       5
 1  3  -1  -3 [5  3  6] 7       6
 1  3  -1  -3  5 [3  6  7]      7
```

**Example 2:**
```
Input:  nums = [1], k = 1
Output: [1]
```

**Constraints:**
- $1 \le \text{nums.length} \le 10^5$
- $-10^4 \le \text{nums}[i] \le 10^4$
- $1 \le k \le \text{nums.length}$

## Approach 1 — Monotonic Decreasing Deque ✅

**Key insight:**
Maintain a `deque<int>` of indices in **strictly decreasing order of values**.
For each index `i`:
1. **Remove expired indices from front:** If `dq.front() <= i - k`, pop front.
2. **Maintain monotonicity from back:** While `!dq.empty() && nums[dq.back()] <= nums[i]`, pop back (these elements are smaller and older than `nums[i]`, so they can never be the maximum again!).
3. Push current index `i` to back of deque.
4. If `i >= k - 1`, record `result.push_back(nums[dq.front()])`.

```
nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
dq stores indices:

i=0 (1): dq = [0]
i=1 (3): 3 > 1 -> pop 0 -> dq = [1]
i=2 (-1): -1 < 3 -> dq = [1, 2] -> window [0..2] max = nums[1] = 3
i=3 (-3): -3 < -1 -> dq = [1, 2, 3] -> window [1..3] max = nums[1] = 3
i=4 (5): dq.front()=1 <= 4-3=1 -> pop front! 5 > -3, -1 -> pop 3, 2 -> dq = [4] -> max = 5
i=5 (3): dq = [4, 5] -> max = 5
i=6 (6): 6 > 3, 5 -> pop 5, 4 -> dq = [6] -> max = 6
i=7 (7): 7 > 6 -> pop 6 -> dq = [7] -> max = 7

Result: [3, 3, 5, 5, 6, 7] ✓
```

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        deque<int> dq; // stores indices
        vector<int> result;
        
        for (int i = 0; i < nums.size(); i++) {
            // 1. Remove elements outside window
            if (!dq.empty() && dq.front() <= i - k) {
                dq.pop_front();
            }
            
            // 2. Maintain decreasing order
            while (!dq.empty() && nums[dq.back()] <= nums[i]) {
                dq.pop_back();
            }
            
            dq.push_back(i);
            
            // 3. Record window max
            if (i >= k - 1) {
                result.push_back(nums[dq.front()]);
            }
        }
        
        return result;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ (each element pushed and popped at most once) | $O(k)$ for the deque |

> **This is the one.** Optimal $O(n)$ sliding window maximum.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| `k = 1` | Window size 1 | Returns original array directly |
| Strictly decreasing array `[5, 4, 3, 2, 1]` | Deque capacity | Indices naturally drop off from front as window slides |
| All identical elements `[2, 2, 2, 2]` | `<=` comparison popping valid elements | `nums[dq.back()] <= nums[i]` pops older duplicates, keeps most recent index at back |

---

## Pattern Takeaway

A **Monotonic Decreasing Deque** discards elements that are both smaller and older than incoming candidates, keeping the current maximum at `dq.front()` in amortized $O(1)$.
