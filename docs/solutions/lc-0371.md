## What are we solving?

Given two integers `a` and `b`, return the sum of the two integers without using the operators `+` and `-`.

The question is: **how do half-adder digital circuits use XOR for addition and AND with left shift for carry?**

**Example 1:**
```
Input:  a = 1, b = 2
Output: 3
```

**Example 2:**
```
Input:  a = 2, b = 3
Output: 5
```

**Constraints:**
- $-1000 \le a, b \le 1000$

## Approach 1 — Bitwise Half-Adder Simulation ✅

**Key insight:**
- `a ^ b` computes the sum without carry (like adding binary bits $1+0=1, 0+0=0, 1+1=0$).
- `(a & b) << 1` computes the carry (1+1 produces carry 1 shifted to next bit).
- Repeat until carry `b` becomes 0.
Note: Cast to `unsigned int` in C++ to prevent signed integer overflow on negative left shifts.

```
a = 2 (0010₂), b = 3 (0011₂)
Iteration 1:
  sum = a ^ b = 0010 ^ 0011 = 0001₂ (1)
  carry = (a & b) << 1 = (0010 & 0011) << 1 = 0010 << 1 = 0100₂ (4)
  a = 1, b = 4
Iteration 2:
  sum = 1 ^ 4 = 0101₂ (5)
  carry = (1 & 4) << 1 = 0
  a = 5, b = 0 -> DONE!

Result: 5 ✓
```

```cpp
class Solution {
public:
    int getSum(int a, int b) {
        while (b != 0) {
            unsigned int carry = (unsigned int)(a & b) << 1;
            a = a ^ b;
            b = carry;
        }
        return a;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(1)$ (at most 32 carry propagations) | $O(1)$ |

> **This is the one.** Pure bitwise logic without arithmetic operators.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Negative integers `a = -1, b = 1` | Undefined signed left shift in C++ | Casting `(a & b)` to `unsigned int` avoids undefined behavior |
| `b = 0` | Loop termination | Returns `a` directly |

---

## Pattern Takeaway

Digital adder logic in software: **Sum without carry = `a ^ b`**, **Carry = `(a & b) << 1`**.
