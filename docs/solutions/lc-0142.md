## What are we solving?

Given the `head` of a linked list, return the node where the **cycle begins**. If there is no cycle, return `null`.

You must not modify the linked list and must use **$O(1)$ extra memory**.

**Example 1:**
```
Input:  head = [3,2,0,-4], pos = 1
Output: tail connects to node index 1
```

**Example 2:**
```
Input:  head = [1,2], pos = 0
Output: tail connects to node index 0
```

**Example 3:**
```
Input:  head = [1], pos = -1
Output: no cycle
```

**Constraints:**
- The number of the nodes in the list is in the range $[0, 10^4]$.
- $-10^5 \le \text{Node.val} \le 10^5$
- `pos` is `-1` or a valid index in the linked-list.

## Approach 1 — Mathematical Phase Intersection ✅

**Key insight:**
Let $L_1$ be distance from head to cycle entrance, and $L_2$ be distance from entrance to meeting point.
- Distance by slow: $d_s = L_1 + L_2$
- Distance by fast: $d_f = L_1 + L_2 + k \cdot C = 2 \cdot d_s$
$\implies L_1 + L_2 = k \cdot C \implies L_1 = k \cdot C - L_2$.
This means: **the distance from head to cycle entrance equals the distance from meeting point to cycle entrance!**
Reset `slow = head`. Move both `slow` and `fast` 1 step at a time until they meet. The meeting node is the cycle start.

```
3 -> 2 -> 0 -> -4 (loops back to 2)
1. Find meeting point: slow and fast meet at node -4.
2. Reset slow = head (3), keep fast at -4.
3. Move both 1 step:
   slow = 2, fast = 2 -> COLLISION at node 2!

Result: Node 2 is the cycle entrance ✓
```

```cpp
class Solution {
public:
    ListNode *detectCycle(ListNode *head) {
        ListNode* slow = head;
        ListNode* fast = head;
        
        while (fast && fast->next) {
            slow = slow->next;
            fast = fast->next->next;
            if (slow == fast) {
                // Phase 2: find entrance
                ListNode* ptr1 = head;
                ListNode* ptr2 = slow;
                while (ptr1 != ptr2) {
                    ptr1 = ptr1->next;
                    ptr2 = ptr2->next;
                }
                return ptr1;
            }
        }
        
        return nullptr;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(1)$ |

> **This is the one.** Elegant mathematical cycle entrance derivation.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| No cycle | Infinite loop | Returns `nullptr` when fast hits end |
| Cycle starts at head `pos = 0` | Meeting at head | `ptr1` and `ptr2` start equal and return head immediately |

---

## Pattern Takeaway

Mathematical identity: **$L_1 = k \cdot C - L_2$**. Walking from `head` and `meeting_point` simultaneously at 1x speed intersects precisely at the cycle entrance.
