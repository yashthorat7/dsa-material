## What are we solving?

Given two sorted arrays `nums1` and `nums2` of size `m` and `n` respectively, return the **median** of the two sorted arrays.

The overall run time complexity must be **$O(\log(m+n))$** or better.

```
 nums1 = [1, 3]        (length m = 2)
 nums2 = [2]           (length n = 1)
 
 Merged: [1, 2, 3]     (total = 3, odd) -> Median = 2.0
 
 nums1 = [1, 2]        (length m = 2)
 nums2 = [3, 4]        (length n = 2)
 
 Merged: [1, 2, 3, 4]  (total = 4, even) -> Median = (2 + 3) / 2.0 = 2.5
```

### Input & Output Contract
- **Input:**
  - `nums1`: `vector<int>` sorted in non-decreasing order ($0 \le m \le 1000$).
  - `nums2`: `vector<int>` sorted in non-decreasing order ($0 \le n \le 1000$).
  - Total length: $1 \le m + n \le 2000$, elements in range $[-10^6, 10^6]$.
- **Output:**
  - `double` representing the exact floating-point median value.

### The Core Challenge
The median partitions the combined elements into two equal halves such that every element in the left half is $\le$ every element in the right half:
- If $(m + n)$ is **odd**, median is $\max(\text{Left Half})$.
- If $(m + n)$ is **even**, median is $\frac{\max(\text{Left Half}) + \min(\text{Right Half})}{2.0}$.

Merging takes $O(m+n)$. To achieve $O(\log(\min(m, n)))$, we must use **Binary Search** to find the partition cut directly in the shorter array!

---

**Example 1:**
```
Input:  nums1 = [1,3], nums2 = [2]
Output: 2.00000
Explanation: merged array = [1,2,3] and median is 2.
```

**Example 2:**
```
Input:  nums1 = [1,2], nums2 = [3,4]
Output: 2.50000
Explanation: merged array = [1,2,3,4] and median is (2 + 3) / 2 = 2.5.
```

**Constraints:**
- $\text{nums1.length} == m$, $\text{nums2.length} == n$
- $0 \le m, n \le 1000$
- $1 \le m + n \le 2000$
- $-10^6 \le \text{nums1}[i], \text{nums2}[i] \le 10^6$

## Approach 1 — Merge and Sort (Brute Force)

### Intuition
Concatenate both vectors into a single array of length $(m+n)$, sort it using `sort`, and pick the middle element(s).

### C++ Implementation
```cpp
class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        vector<int> merged = nums1;
        merged.insert(merged.end(), nums2.begin(), nums2.end());
        sort(merged.begin(), merged.end());
        
        int total = merged.size();
        if (total % 2 == 1) {
            return merged[total / 2];
        } else {
            return (merged[total / 2 - 1] + merged[total / 2]) / 2.0;
        }
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O((m+n) \log(m+n))$ | Sorting combined length $(m+n)$. |
| **Space** | $O(m+n)$ | Allocates a new vector of size $m+n$. |

> **Verdict:** Too slow and consumes $O(m+n)$ memory.

## Approach 2 — Two-Pointer Virtual Merge ($O(m+n)$ Linear Scan)

### Intuition
Since both arrays are already sorted, we can use two pointers `p1` and `p2` to simulate merging up to the midpoint index $(m+n)/2$ without allocating a full merged array.

### C++ Implementation
```cpp
class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        int m = nums1.size(), n = nums2.size();
        int total = m + n;
        int p1 = 0, p2 = 0;
        int m1 = 0, m2 = 0;
        
        for (int count = 0; count <= total / 2; count++) {
            m2 = m1; // m2 stores previous element for even total
            if (p1 < m && (p2 >= n || nums1[p1] <= nums2[p2])) {
                m1 = nums1[p1++];
            } else {
                m1 = nums2[p2++];
            }
        }
        
        if (total % 2 == 1) {
            return m1;
        } else {
            return (m1 + m2) / 2.0;
        }
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(m+n)$ | Iterates $(m+n)/2$ steps. |
| **Space** | $O(1)$ | Pure stack variables. |

> **Verdict:** Fast and $O(1)$ space, but still linear $O(m+n)$ rather than logarithmic.

## Approach 3 — Binary Search on Partition Cut of Shorter Array ✅

### Key Insight
Instead of picking elements, we **search for the correct partition cut** in the shorter array `nums1` (`0 <= cut1 <= m`):
- Total elements required in the combined left partition: $\text{leftTotal} = \frac{m + n + 1}{2}$.
- Once `cut1` is chosen in `nums1`, the remaining elements in the left partition must come from `nums2`:
  $$\text{cut2} = \text{leftTotal} - \text{cut1}$$

Define the 4 partition boundaries:
- $L_1 = \text{nums1}[\text{cut1} - 1]$ (or $-\infty$ if $\text{cut1} == 0$)
- $R_1 = \text{nums1}[\text{cut1}]$ (or $+\infty$ if $\text{cut1} == m$)
- $L_2 = \text{nums2}[\text{cut2} - 1]$ (or $-\infty$ if $\text{cut2} == 0$)
- $R_2 = \text{nums2}[\text{cut2}]$ (or $+\infty$ if $\text{cut2} == n$)

```
                  nums1:  [ ... L1 ]  |  [ R1 ... ]
                  nums2:  [ ... L2 ]  |  [ R2 ... ]
```

**Validity Condition:** The partition is valid if and only if:
$$L_1 \le R_2 \quad \text{and} \quad L_2 \le R_1$$

- If $L_1 > R_2$: `cut1` is too far right $\rightarrow$ move left: `high = cut1 - 1`.
- If $L_2 > R_1$: `cut1` is too far left $\rightarrow$ move right: `low = cut1 + 1`.
- Once valid:
  - If $(m + n)$ is odd $\rightarrow$ $\mathbf{\max(L_1, L_2)}$.
  - If $(m + n)$ is even $\rightarrow$ $\mathbf{\frac{\max(L_1, L_2) + \min(R_1, R_2)}{2.0}}$.

```
nums1 = [1, 3] (m=2), nums2 = [2] (n=1), total=3 (odd), leftTotal = (3+1)/2 = 2
Ensure nums1 is shorter: swap -> nums1 = [2] (m=1), nums2 = [1, 3] (n=2)

low = 0, high = 1
cut1 = (0 + 1) / 2 = 0
cut2 = 2 - 0 = 2

L1 = -∞,   R1 = nums1[0] = 2
L2 = nums2[1] = 3,  R2 = +∞
Check: L2(3) <= R1(2) is FALSE -> cut1 too small! -> low = cut1 + 1 = 1

cut1 = 1, cut2 = 2 - 1 = 1
L1 = nums1[0] = 2, R1 = +∞
L2 = nums2[0] = 1, R2 = nums2[1] = 3
Check: L1(2) <= R2(3) [YES], L2(1) <= R1(∞) [YES] -> VALID!

Odd length: return max(L1, L2) = max(2, 1) = 2.0 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        // Guarantee binary search is performed on the shorter array
        if (nums1.size() > nums2.size()) {
            return findMedianSortedArrays(nums2, nums1);
        }
        
        int m = nums1.size();
        int n = nums2.size();
        int low = 0, high = m;
        int leftTotal = (m + n + 1) / 2;
        
        while (low <= high) {
            int cut1 = low + (high - low) / 2;
            int cut2 = leftTotal - cut1;
            
            int l1 = (cut1 == 0) ? INT_MIN : nums1[cut1 - 1];
            int r1 = (cut1 == m) ? INT_MAX : nums1[cut1];
            int l2 = (cut2 == 0) ? INT_MIN : nums2[cut2 - 1];
            int r2 = (cut2 == n) ? INT_MAX : nums2[cut2];
            
            if (l1 <= r2 && l2 <= r1) {
                // Correct partition reached
                if ((m + n) % 2 == 1) {
                    return max(l1, l2);
                } else {
                    return (max(l1, l2) + min(r1, r2)) / 2.0;
                }
            } else if (l1 > r2) {
                high = cut1 - 1; // Move cut1 left
            } else {
                low = cut1 + 1;  // Move cut1 right
            }
        }
        
        return 0.0;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\log(\min(m, n)))$ | Binary search runs strictly on the shorter array $[0..m]$ where $m \le n$. |
| **Space** | $O(1)$ | Pure index variables and boundary scalar checks. |

> **This is the one.** Mathematically optimal $O(\log(\min(m, n)))$ runtime and $O(1)$ memory.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **One Empty Array** | `nums1 = [], nums2 = [1]` | Out of bounds access | `cut1 = 0`, $L_1 = \text{INT\_MIN}, R_1 = \text{INT\_MAX}$; correctly outputs 1.0. |
| **Disjoint Ranges** | `[1, 2]` and `[3, 4]` | Extreme cuts at 0 or $m$ | `INT_MIN` and `INT_MAX` sentinels prevent special casing at edges. |
| **Identical Elements** | `[1, 1]` and `[1, 1]` | Non-strict inequalities | Uses `<=` comparisons throughout. |

---

## Pattern Takeaways

1. **Partition Binary Search:**  
   When looking for a quantile across multiple sorted arrays, binary search the **partition boundary** of the smaller array rather than the values themselves.
2. **The Sentinel Pattern:**  
   Using `INT_MIN` and `INT_MAX` for out-of-bound cuts turns 16 edge cases into 1 clean unified formula.
