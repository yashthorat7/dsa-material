## What are we solving?

You are given an array of strings `tokens` that represents an arithmetic expression in **Reverse Polish Notation** (Postfix Notation).

Evaluate the expression and return an integer representing its total evaluated value.

Note that:
- The valid operators are `'+'`, `'-'`, `'*'`, and `'/'`.
- Each operand may be an integer or another expression.
- The division between two integers always **truncates toward zero**.
- There will not be any division by zero.
- The input represents a valid arithmetic expression in reverse polish notation.

```
 Infix:   (2 + 1) * 3
 Postfix: ["2", "1", "+", "3", "*"]
 
 Step 1: "2", "1", "+"  ==> (2 + 1) = 3
 Step 2: "3", "3", "*"  ==> (3 * 3) = 9
 
 Output: 9
```

### Input & Output Contract
- **Input:**
  - `tokens`: `vector<string>` of length $1 \le n \le 10^4$, where each token is an operator (`+`, `-`, `*`, `/`) or an integer string in range $[-200, 200]$.
- **Output:**
  - `int` representing the calculated result (fits within a 32-bit signed integer).

### The Core Challenge
In Reverse Polish Notation, operands are pushed onto a LIFO stack. When an operator is encountered, it operates on the **two most recent operands**:
- The **first popped element** is the **right operand** ($b$).
- The **second popped element** is the **left operand** ($a$).
- The result ($a \text{ op } b$) is pushed back onto the stack.
Order of operands is critical for non-commutative operations like subtraction ($a - b$) and division ($a / b$).

---

**Example 1:**
```
Input:  tokens = ["2","1","+","3","*"]
Output: 9
Explanation: ((2 + 1) * 3) = 9
```

**Example 2:**
```
Input:  tokens = ["4","13","5","/","+"]
Output: 6
Explanation: (4 + (13 / 5)) = 6
```

**Example 3:**
```
Input:  tokens = ["10","6","9","3","+","-11","*","/","*","17","+","5","+"]
Output: 22
```

**Constraints:**
- $1 \le \text{tokens.length} \le 10^4$
- `tokens[i]` is either an operator: `"+"`, `"-"`, `"*"`, or `"/"`, or an integer in the range `[-200, 200]`.

## Approach 1 — Operand Stack Evaluation with 64-bit Overflow Safety ✅

### Key Insight
1. Maintain an operand stack `stack<long long> st`.
2. Iterate through each token string:
   - If `token` is an operator:
     - Pop `long long b = st.top()`, then `st.pop()`.
     - Pop `long long a = st.top()`, then `st.pop()`.
     - Compute:
       - `+` $\rightarrow a + b$
       - `-` $\rightarrow a - b$
       - `*` $\rightarrow a \times b$
       - `/` $\rightarrow a / b$
     - Push the result back onto `st`.
   - Else: Parse string to number via `stoll(token)` and push onto `st`.
3. At the end, the stack contains exactly 1 element: `st.top()`.

```
tokens = ["4", "13", "5", "/", "+"]

Token "4":  operand -> push 4   -> Stack: [4]
Token "13": operand -> push 13  -> Stack: [4, 13]
Token "5":  operand -> push 5   -> Stack: [4, 13, 5]
Token "/":  operator -> pop b=5, pop a=13 -> 13 / 5 = 2 -> push 2 -> Stack: [4, 2]
Token "+":  operator -> pop b=2, pop a=4  -> 4 + 2 = 6  -> push 6 -> Stack: [6]

Result: 6 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int evalRPN(vector<string>& tokens) {
        stack<long long> st;
        
        for (const string& token : tokens) {
            if (token == "+" || token == "-" || token == "*" || token == "/") {
                long long b = st.top(); st.pop(); // Right operand
                long long a = st.top(); st.pop(); // Left operand
                
                if (token == "+") st.push(a + b);
                else if (token == "-") st.push(a - b);
                else if (token == "*") st.push(a * b);
                else if (token == "/") st.push(a / b); // C++ truncates towards zero natively
            } else {
                st.push(stoll(token));
            }
        }
        
        return static_cast<int>(st.top());
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Single pass over $n$ tokens; each element is pushed and popped at most once. |
| **Space** | $O(n)$ | Stack stores at most $n/2 + 1$ intermediate operands. |

> **This is the one.** Clean, robust, using `long long` to prevent intermediate multiplication overflows.

## Approach 2 — Lambda Dispatch Table / Map

### Intuition
In modern C++, register operator functions in a lookup table `unordered_map<string, function<long long(long long, long long)>>` to achieve extensible, clean modular dispatch.

### C++ Implementation
```cpp
class Solution {
public:
    int evalRPN(vector<string>& tokens) {
        stack<long long> st;
        const unordered_map<string, function<long long(long long, long long)>> ops = {
            {"+", plus<long long>()},
            {"-", minus<long long>()},
            {"*", multiplies<long long>()},
            {"/", divides<long long>()}
        };
        
        for (const string& token : tokens) {
            if (ops.count(token)) {
                long long b = st.top(); st.pop();
                long long a = st.top(); st.pop();
                st.push(ops.at(token)(a, b));
            } else {
                st.push(stoll(token));
            }
        }
        
        return static_cast<int>(st.top());
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Constant-time lambda lookups per token. |
| **Space** | $O(n)$ | Stack and dispatch table. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Negative Division** | `["-13", "5", "/"]` | Floor vs truncate toward zero | C++ standard integer division `/` natively truncates towards zero (`-13 / 5 = -2`). |
| **Subtraction Operand Order** | `["4", "3", "-"]` | Subtracting in reverse ($3 - 4 = -1$) | First popped is $b=3$, second is $a=4$; computes $a - b = 4 - 3 = 1$. |
| **Single Number** | `["42"]` | Loop with zero operators | Pushes 42, loop finishes, returns 42. |
| **Intermediate Multiplicative Overflow** | Large products during chained calculations | 32-bit `int` overflow | `stack<long long>` protects intermediate states. |

## Pattern Takeaways

1. **The Postfix Invariant:**  
   In postfix evaluation, operators never need precedence rules or parentheses — evaluation order is strictly defined by arrival time on the operand stack.
2. **First-Popped is Right Operand:**  
   Remember: `b = pop()` (right), `a = pop()` (left), result is `a - b` or `a / b`.
