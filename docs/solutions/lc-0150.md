## What are we solving?

You are given an array of strings `tokens` that represents an arithmetic expression in a **Reverse Polish Notation** (Postfix Notation).

Evaluate the expression. Return an integer that represents the value of the expression.

Note that:
- The valid operators are `'+'`, `'-'`, `'*'`, and `'/'`.
- Each operand may be an integer or another expression.
- The division between two integers always **truncates toward zero**.
- The given RPN expression is always valid.

**Example 1:**
```
Input:  tokens = ["2","1","+","3","*"]
Output: 9
Explanation: ((2 + 1) * 3) = 9
```

**Example 2:**
```
Input:  tokens = ["4","13","5","/","+"]
Output: 6
Explanation: (4 + (13 / 5)) = 6
```

**Example 3:**
```
Input:  tokens = ["10","6","9","3","+","-11","*","/","*","17","+","5","+"]
Output: 22
```

**Constraints:**
- $1 \le \text{tokens.length} \le 10^4$
- `tokens[i]` is either an operator: `"+"`, `"-"`, `"*"`, or `"/"`, or an integer in the range `[-200, 200]`.

## Approach 1 — Operand Stack Evaluation ✅

**Key insight:**
1. Maintain an operand stack `st`.
2. For each token:
   - If it is an operator (`+`, `-`, `*`, `/`):
     - Pop `b = st.top()`, then pop `a = st.top()` (note order: `a` is left operand, `b` is right operand).
     - Compute result `a op b` and push back onto `st`.
   - Else (it's a number): convert to integer `stoi(token)` and push onto `st`.
3. Return `st.top()`.

```
tokens = ["4", "13", "5", "/", "+"]

"4"  -> push 4  -> stack: [4]
"13" -> push 13 -> stack: [4, 13]
"5"  -> push 5  -> stack: [4, 13, 5]
"/"  -> pop b=5, a=13 -> 13 / 5 = 2 -> push 2 -> stack: [4, 2]
"+"  -> pop b=2, a=4  -> 4 + 2 = 6 -> push 6 -> stack: [6]

Result: 6 ✓
```

```cpp
class Solution {
public:
    int evalRPN(vector<string>& tokens) {
        stack<long long> st;
        for (const string& s : tokens) {
            if (s == "+" || s == "-" || s == "*" || s == "/") {
                long long b = st.top(); st.pop();
                long long a = st.top(); st.pop();
                if (s == "+") st.push(a + b);
                else if (s == "-") st.push(a - b);
                else if (s == "*") st.push(a * b);
                else if (s == "/") st.push(a / b);
            } else {
                st.push(stoll(s));
            }
        }
        return st.top();
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(n)$ |

> **This is the one.** Standard postfix evaluation.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Negative division truncation `"-13", "5", "/"` | Floor vs truncate towards zero | C++ `/` truncates towards zero natively (`-13 / 5 = -2`) |
| Operand order for subtraction `["4", "3", "-"]` | Order reversal ($3 - 4$ vs $4 - 3$) | First popped is `b` (right), second is `a` (left), computes `a - b = 1` |
| Large intermediate multiplication | 32-bit overflow | Using `long long` stack prevents overflow during intermediate operations |

---

## Pattern Takeaway

In **Postfix (RPN) evaluation**, operands precede operators. Popping yields the right operand first, then the left operand.
