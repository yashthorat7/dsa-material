## What are we solving?

Given the `root` of a Binary Search Tree (BST), and an integer `k`, return the $k$-th smallest value (**1-indexed**) among all the values of the nodes in the tree.

```
       (3)
      /   \
    (1)   (4)          k = 1 -> Output: 1
      \
      (2)              k = 2 -> Output: 2
                       k = 3 -> Output: 3
                       k = 4 -> Output: 4
```

### Input & Output Contract
- **Input:**
  - `root`: `TreeNode*` pointing to root of a valid BST ($1 \le k \le n \le 10^4$, $0 \le \text{Node.val} \le 10^4$).
  - `k`: `int` (1-indexed rank).
- **Output:**
  - `int` representing the $k$-th smallest node value.

### The Core Challenge
Because in-order traversal (Left $\rightarrow$ Root $\rightarrow$ Right) of a BST visits nodes in **strictly ascending order**, the $k$-th visited node is mathematically guaranteed to be the $k$-th smallest element. We want to stop the traversal immediately once $k$ reaches 0 without exploring the rest of the tree.

---

**Example 1:**
```
Input:  root = [3,1,4,null,2], k = 1
Output: 1
```

**Example 2:**
```
Input:  root = [5,3,6,2,4,null,null,1], k = 3
Output: 3
```

**Constraints:**
- The number of nodes in the tree is `n`.
- $1 \le k \le n \le 10^4$
- $0 \le \text{Node.val} \le 10^4$

## Approach 1 — Recursive In-Order Traversal with Early Stop

### Intuition
Traverse `node->left` first. When returning from the left subtree, decrement `k--`. When `k == 0`, capture `result = node->val` and return early to avoid exploring further branches.

### C++ Implementation
```cpp
class Solution {
private:
    int count = 0;
    int answer = -1;

public:
    int kthSmallest(TreeNode* root, int k) {
        count = k;
        inOrder(root);
        return answer;
    }

private:
    void inOrder(TreeNode* node) {
        if (node == nullptr || count <= 0) return;
        
        inOrder(node->left);
        
        count--;
        if (count == 0) {
            answer = node->val;
            return;
        }
        
        inOrder(node->right);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(h + k)$ | Reaches leftmost node in $h$ steps and visits $k$ nodes. |
| **Space** | $O(h)$ | Recursion stack depth bounded by tree height $h$. |

## Approach 2 — Iterative In-Order Traversal with Explicit Stack ✅

### Key Insight
Use an explicit stack `stack<TreeNode*>`:
1. Drill down into the leftmost chain, pushing each node onto `st`.
2. Pop the top node: this is the next smallest element in sorted order.
3. Decrement `k--`. If `k == 0`, return `curr->val` immediately!
4. Move to `curr = curr->right` and repeat.

```
Tree: [3, 1, 4, null, 2], k = 1

1. Push left chain: stack = [3, 1]
2. Pop top node (1): k becomes 0 -> MATCH!
3. Immediately returns 1 without visiting nodes 2, 3, or 4! ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int kthSmallest(TreeNode* root, int k) {
        stack<TreeNode*> st;
        TreeNode* curr = root;
        
        while (curr != nullptr || !st.empty()) {
            // Traverse to the leftmost node
            while (curr != nullptr) {
                st.push(curr);
                curr = curr->left;
            }
            
            curr = st.top();
            st.pop();
            
            k--;
            if (k == 0) {
                return curr->val; // Found the k-th smallest element
            }
            
            curr = curr->right;
        }
        
        return -1;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(h + k)$ | Stops immediately after popping the $k$-th element. |
| **Space** | $O(h)$ | Stack size bounded by height $h$ ($O(\log n)$ balanced, $O(n)$ skewed). |

> **This is the one.** Clean iterative stack with instantaneous early termination.

## Approach 3 — Morris In-Order Traversal ($O(1)$ Space)

### Intuition
Thread the BST using Morris Traversal by creating temporary right links from the in-order predecessor back to the current root, allowing in-order traversal with $O(1)$ auxiliary stack space.

### C++ Implementation
```cpp
class Solution {
public:
    int kthSmallest(TreeNode* root, int k) {
        TreeNode* curr = root;
        int count = 0;
        int result = -1;
        
        while (curr != nullptr) {
            if (curr->left == nullptr) {
                count++;
                if (count == k) result = curr->val;
                curr = curr->right;
            } else {
                TreeNode* pred = curr->left;
                while (pred->right != nullptr && pred->right != curr) {
                    pred = pred->right;
                }
                
                if (pred->right == nullptr) {
                    pred->right = curr; // Create thread
                    curr = curr->left;
                } else {
                    pred->right = nullptr; // Restore tree
                    count++;
                    if (count == k) result = curr->val;
                    curr = curr->right;
                }
            }
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Each edge traversed at most 3 times. |
| **Space** | $O(1)$ | No stack, no recursion, pure pointer threading. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **`k = 1`** | `root = [5, 3, 6], k = 1` | Leftmost leaf check | Pops leftmost element `3` on step 1, returns 3. |
| **`k = n` (Largest Element)** | `k = n` | Full traversal required | Stack processes all $n$ nodes and returns root's rightmost leaf. |
| **Single Node Tree** | `root = [10], k = 1` | Single step | Returns 10 immediately. |

---

## Pattern Takeaways

1. **BST In-Order Rank Equivalence:**  
   In any BST, popping elements from an in-order stack yields values in strict ascending sorted rank.
2. **Follow-Up (Frequent Modifications):**  
   If the BST is modified often (insert/delete) and $k$-th queries are frequent, augment each `TreeNode` with a `subtreeSize` field to answer $k$-th queries in $O(h)$ time using binary search on size.
