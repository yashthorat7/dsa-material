## What are we solving?

Given the `root` of a binary search tree, and an integer `k`, return the $k$-th smallest value (**1-indexed**) of all the values of the nodes in the tree.

The question is: **how does In-Order traversal visit nodes in strictly ascending order, enabling early exit at the $k$-th step?**

**Example 1:**
```
Input:  root = [3,1,4,null,2], k = 1
Output: 1
```

**Example 2:**
```
Input:  root = [5,3,6,2,4,null,null,1], k = 3
Output: 3
```

**Constraints:**
- The number of nodes in the tree is `n`.
- $1 \le k \le n \le 10^4$
- $0 \le \text{Node.val} \le 10^4$

## Approach 1 — Iterative In-Order Traversal with Counter ✅

**Key insight:**
In-order traversal (Left $\rightarrow$ Root $\rightarrow$ Right) of a BST visits nodes in **strictly ascending order**.
Iterative in-order using an explicit stack:
1. Push all left children onto stack.
2. Pop node: decrement `k--`. If `k == 0`, return `node->val`.
3. Set `curr = node->right` and continue.

```
Tree: [3, 1, 4, null, 2], k = 1

Push left: stack = [3, 1]
Pop 1: k=1 -> k=0 -> MATCH! Return 1 ✓
```

```cpp
class Solution {
public:
    int kthSmallest(TreeNode* root, int k) {
        stack<TreeNode*> st;
        TreeNode* curr = root;
        
        while (curr || !st.empty()) {
            while (curr) {
                st.push(curr);
                curr = curr->left;
            }
            
            curr = st.top();
            st.pop();
            
            k--;
            if (k == 0) return curr->val;
            
            curr = curr->right;
        }
        
        return -1;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(h + k)$ | $O(h)$ |

> **This is the one.** Stops immediately at the $k$-th element without visiting remaining tree.

---

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| `k = 1` | Leftmost node | Pops leftmost node and returns immediately |
| `k == n` | Full traversal | Visits entire tree, returns maximum element |

---

## Pattern Takeaway

**BST In-Order Traversal** yields a sorted sequence. Halting at `k == 0` achieves $O(h + k)$ optimal runtime.
