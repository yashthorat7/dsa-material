## What are we solving?

Given `head`, the head of a singly linked list, determine if the linked list contains a **cycle**.

There is a cycle in a linked list if there is some node in the list that can be reached again by continuously following the `next` pointer. Return `true` if there is a cycle in the linked list; otherwise return `false`.

```
  [3] -> [2] -> [0] -> [-4]
          ^              |
          +--------------+  (Tail loops back to node with value 2)
          
 Output: true
```

### Input & Output Contract
- **Input:**
  - `head`: `ListNode*` pointing to the first node of the linked list ($0 \le \text{length} \le 10^4$, $-10^5 \le \text{Node.val} \le 10^5$).
- **Output:**
  - `bool`: `true` if a loop exists; `false` if `nullptr` is reached.

### The Core Challenge
In a cyclic list, standard traversal creates an infinite loop. We need an algorithm that can detect whether a list terminates or repeats in $O(n)$ time while utilizing strictly **$O(1)$ constant memory**.

---

**Example 1:**
```
Input:  head = [3,2,0,-4], pos = 1
Output: true
Explanation: There is a cycle in the linked list, where the tail connects to the 1st node (0-indexed).
```

**Example 2:**
```
Input:  head = [1,2], pos = 0
Output: true
Explanation: The tail connects to node 0.
```

**Example 3:**
```
Input:  head = [1], pos = -1
Output: false
Explanation: There is no cycle in the linked list.
```

**Constraints:**
- The number of the nodes in the list is in the range $[0, 10^4]$.
- $-10^5 \le \text{Node.val} \le 10^5$
- `pos` is `-1` or a valid index in the linked-list.

## Approach 1 — Hash Set (Node Address Tracking)

### Intuition
Traverse the list while inserting each node's memory address (`ListNode*`) into a hash set `unordered_set<ListNode*>`.
- If the current node pointer is already present in the set, a cycle exists $\rightarrow$ return `true`.
- If `nullptr` is reached, no cycle exists $\rightarrow$ return `false`.

### C++ Implementation
```cpp
class Solution {
public:
    bool hasCycle(ListNode *head) {
        unordered_set<ListNode*> visited;
        ListNode* curr = head;
        
        while (curr != nullptr) {
            if (visited.count(curr)) {
                return true; // Node previously visited!
            }
            visited.insert(curr);
            curr = curr->next;
        }
        
        return false;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Visits each node once with $O(1)$ hash set lookups and insertions. |
| **Space** | $O(n)$ | Stores up to $n$ memory pointers in the hash set. |

> **Verdict:** Intuitive, but consumes $O(n)$ auxiliary heap space. Can we do this in $O(1)$ memory?

## Approach 2 — Node Value Marking (Destructive In-Place)

### Intuition
If allowed to mutate node values temporarily and values are guaranteed within $[-10^5, 10^5]$, we can mark each visited node with a special sentinel value (e.g. `1000001`). If we encounter this sentinel again, a cycle exists.

### C++ Implementation
```cpp
class Solution {
public:
    bool hasCycle(ListNode *head) {
        const int SENTINEL = 1000001;
        ListNode* curr = head;
        
        while (curr != nullptr) {
            if (curr->val == SENTINEL) {
                return true;
            }
            curr->val = SENTINEL;
            curr = curr->next;
        }
        
        return false;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Traverses each node once. |
| **Space** | $O(1)$ | No extra memory allocated. |

> **Verdict:** Fast and $O(1)$ space, but destructive (modifies input data, which violates read-only principles).

## Approach 3 — Floyd's Cycle-Finding Algorithm (Tortoise and Hare) ✅

### Key Insight
Initialize two pointers:
1. `slow` (Tortoise): moves **1 step** at a time (`slow = slow->next`).
2. `fast` (Hare): moves **2 steps** at a time (`fast = fast->next->next`).

**Why collision is mathematically guaranteed:**
- If there is **no cycle**, `fast` will reach `nullptr` in $n/2$ steps and terminate.
- If there **is a cycle**, both pointers will enter the loop.
- Inside a cycle of length $C$, the distance between `fast` and `slow` decreases by exactly **$2 - 1 = 1$ step** on each iteration.
- Because the distance decreases by $1$ consecutively ($\dots 3 \rightarrow 2 \rightarrow 1 \rightarrow 0$), `fast` can **never skip over `slow`**! They must collide in at most $C$ loop steps.

```
List: 3 -> 2 -> 0 -> -4 -> (loops back to 2)

Step 0: slow = 3, fast = 3
Step 1: slow = 2, fast = 0
Step 2: slow = 0, fast = 2
Step 3: slow = -4, fast = -4  ==> COLLISION (slow == fast)!

Result: true ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    bool hasCycle(ListNode *head) {
        ListNode* slow = head;
        ListNode* fast = head;
        
        // Fast moves 2 steps, slow moves 1 step
        while (fast != nullptr && fast->next != nullptr) {
            slow = slow->next;
            fast = fast->next->next;
            
            if (slow == fast) {
                return true; // Collision detected
            }
        }
        
        return false; // Reached end of list (no cycle)
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | If acyclic: $\le n/2$ steps. If cyclic: $K + C \le 2n$ steps (where $K$ is non-cyclic prefix and $C$ is cycle length). |
| **Space** | $O(1)$ | Purely two pointer variables on the stack without modifying input data. |

> **This is the one.** Non-destructive, $O(1)$ constant memory, universally optimal.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Empty List** | `head = nullptr` | Dereferencing null pointer | Loop condition `fast != nullptr` fails immediately, returns `false`. |
| **Single Node (No Cycle)** | `[1]` | Null pointer dereference on `fast->next->next` | `fast->next != nullptr` check in `while` prevents crash, returns `false`. |
| **Single Node Self-Cycle** | `1 -> 1` | Checking `slow == fast` before advancing | Pointers are advanced *first*, then `slow == fast` is tested $\rightarrow$ returns `true`. |
| **Two Nodes with Cycle** | `1 -> 2 -> 1` | Infinite loop | `slow` and `fast` collide on iteration 2, returns `true`. |

## Pattern Takeaways

1. **The Relative Velocity Differential:**  
   When tracking cyclic sequences (linked lists, repeated functions, pseudo-random generators), a relative speed of 1 ($v_{\text{fast}} - v_{\text{slow}} = 1$) guarantees discrete convergence without overshoot.
2. **Cycle Origin Finding (Floyd's Algorithm II):**
