## What are we solving?

Given an array of positive integers `nums` and a positive integer `target`, return the **minimal length** of a subarray whose sum is greater than or equal to `target`. If there is no such subarray, return `0` instead.

The question is: **how can we dynamically expand and shrink the window to find the smallest valid range in $O(n)$ time?**

**Example 1:**
```
Input:  target = 7, nums = [2,3,1,2,4,3]
Output: 2
Explanation: The subarray [4,3] has the minimal length under the problem constraint.
```

**Example 2:**
```
Input:  target = 4, nums = [1,4,4]
Output: 1
```

**Example 3:**
```
Input:  target = 11, nums = [1,1,1,1,1,1,1,1]
Output: 0
```

**Constraints:**
- $1 \le \text{target} \le 10^9$
- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^4$

## Approach 1 — Dynamic Sliding Window (Shrink While Valid) ✅

**Key insight:** Since all numbers are **positive**:
1. Expanding `right` strictly increases the window sum.
2. Shrinking `left` strictly decreases the window sum.
3. While `currentSum >= target`: record the length `minLen = min(minLen, right - left + 1)`, then subtract `nums[left]` and advance `left` to search for an even shorter valid window.

```
target = 7, nums = [2, 3, 1, 2, 4, 3]
minLen = ∞, sum = 0, left = 0

right=0 (2): sum=2 < 7
right=1 (3): sum=5 < 7
right=2 (1): sum=6 < 7
right=3 (2): sum=8 >= 7 -> minLen = min(∞, 4) = 4; shrink: sum=6, left=1
right=4 (4): sum=10 >= 7 -> minLen = min(4, 4) = 4; shrink: sum=7, left=2 -> minLen = min(4, 3) = 3; shrink: sum=6, left=3
right=5 (3): sum=9 >= 7 -> minLen = min(3, 3) = 3; shrink: sum=7, left=4 -> minLen = min(3, 2) = 2; shrink: sum=3, left=5

Result: minLen = 2 ([4, 3]) ✓
```

```cpp
class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        int left = 0;
        int currentSum = 0;
        int minLen = INT_MAX;
        
        for (int right = 0; right < nums.size(); right++) {
            currentSum += nums[right];
            while (currentSum >= target) {
                minLen = min(minLen, right - left + 1);
                currentSum -= nums[left];
                left++;
            }
        }
        
        return minLen == INT_MAX ? 0 : minLen;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(1)$ |

> **This is the one.** Each element is added once and removed at most once: $2n$ operations total.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| No valid subarray exists `nums = [1,1,1], target = 10` | Returning `INT_MAX` | Ternary check `minLen == INT_MAX ? 0 : minLen` returns 0 |
| Single element equals target `nums = [7], target = 7` | Off-by-one window calculation | Window length `0 - 0 + 1 = 1` recorded immediately |
| Entire array required | Premature shrink | Shrink happens only after full sum accumulates |

---

## Pattern Takeaway

In **dynamic sliding windows with positive numbers**, expand `right` until valid, then greedily contract `left` while valid to find the **minimal** bounding window.
