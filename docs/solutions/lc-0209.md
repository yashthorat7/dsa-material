## What are we solving?

Given an array of positive integers `nums` and a positive integer `target`, return the **minimal length** of a contiguous subarray whose sum is greater than or equal to `target`.

If there is no such subarray, return `0` instead.

```
 nums = [ 2, 3, 1, 2, 4, 3 ],  target = 7
 
 Subarrays with sum >= 7:
 - [2, 3, 1, 2] -> Sum = 8,  Length = 4
 - [3, 1, 2, 4] -> Sum = 10, Length = 4
 - [1, 2, 4]    -> Sum = 7,  Length = 3
 - [4, 3]       -> Sum = 7,  Length = 2  (Minimal Length)
 
 Output: 2
```

### Input & Output Contract
- **Input:**
  - `target`: `int` ($1 \le \text{target} \le 10^9$).
  - `nums`: `vector<int>` ($1 \le n \le 10^5$, $1 \le \text{nums}[i] \le 10^4$).
- **Output:**
  - `int`: Minimal length of valid subarray, or `0` if impossible.

### The Core Invariant
Because all elements are **strictly positive** ($\text{nums}[i] \ge 1$):
- Expanding the right boundary `right++` **monotonically increases** the window sum.
- Contracting the left boundary `left++` **monotonically decreases** the window sum.
This strict monotonicity enables an optimal **$O(n)$ Dynamic Sliding Window**.

---

**Example 1:**
```
Input:  target = 7, nums = [2,3,1,2,4,3]
Output: 2
Explanation: The subarray [4,3] has the minimal length under the problem constraint.
```

**Example 2:**
```
Input:  target = 4, nums = [1,4,4]
Output: 1
```

**Example 3:**
```
Input:  target = 11, nums = [1,1,1,1,1,1,1,1]
Output: 0
```

**Constraints:**
- $1 \le \text{target} \le 10^9$
- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^4$

## Approach 1 — Dynamic Sliding Window (Shrink While Valid) ✅

### Key Insight
1. Maintain `left = 0`, `currentSum = 0`, and `minLen = INT_MAX`.
2. Expand `right` from `0` to $n - 1$, adding `nums[right]` to `currentSum`.
3. **While `currentSum >= target`:**
   - Record current window size: `minLen = min(minLen, right - left + 1)`.
   - Shrink window from the left: `currentSum -= nums[left]`, `left++`.
4. Return `minLen == INT_MAX ? 0 : minLen`.

```
target = 7, nums = [2, 3, 1, 2, 4, 3]

right=0 (2): sum=2 < 7
right=1 (3): sum=5 < 7
right=2 (1): sum=6 < 7
right=3 (2): sum=8 >= 7 -> minLen = 4; shrink left=0 (2) -> sum=6, left=1
right=4 (4): sum=10 >= 7 -> minLen = 4; shrink left=1 (3) -> sum=7 (minLen=3), left=2; shrink left=2 (1) -> sum=6, left=3
right=5 (3): sum=9 >= 7 -> minLen = 3; shrink left=3 (2) -> sum=7 (minLen=2!), left=4; shrink left=4 (4) -> sum=3, left=5

Result: minLen = 2 ([4, 3]) ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        int n = nums.size();
        int left = 0;
        long long currentSum = 0;
        int minLen = INT_MAX;
        
        for (int right = 0; right < n; right++) {
            currentSum += nums[right];
            
            // Greedily shrink the window from the left while sum remains valid
            while (currentSum >= target) {
                minLen = min(minLen, right - left + 1);
                currentSum -= nums[left];
                left++;
            }
        }
        
        return (minLen == INT_MAX) ? 0 : minLen;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Each index is visited by `right` once and by `left` at most once ($2n$ steps total). |
| **Space** | $O(1)$ | Constant auxiliary variables. |

> **This is the one.** Clean, robust, single-pass dynamic sliding window.

## Approach 2 — Prefix Sums + Binary Search ($O(n \log n)$)

### Intuition
Build a strictly increasing prefix sum array `sums[i] = nums[0] + ... + nums[i-1]`. For each index $i$, binary search (`lower_bound`) for the smallest index $j$ such that $\text{sums}[j] \ge \text{sums}[i] + \text{target}$.

### C++ Implementation
```cpp
class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        int n = nums.size();
        vector<long long> sums(n + 1, 0);
        for (int i = 0; i < n; i++) sums[i + 1] = sums[i] + nums[i];
        
        int minLen = INT_MAX;
        for (int i = 0; i < n; i++) {
            long long toFind = sums[i] + target;
            auto it = lower_bound(sums.begin() + i + 1, sums.end(), toFind);
            if (it != sums.end()) {
                int j = distance(sums.begin(), it);
                minLen = min(minLen, j - i);
            }
        }
        
        return (minLen == INT_MAX) ? 0 : minLen;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n \log n)$ | $n$ binary searches over a prefix array of length $n + 1$. |
| **Space** | $O(n)$ | Prefix sum vector. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **No Subarray Satisfies Target** | `nums = [1, 1, 1], target = 10` | Returning `INT_MAX` | `minLen == INT_MAX ? 0 : minLen` returns 0. |
| **Single Element Meets Target** | `nums = [7], target = 7` | Off-by-one window length | `right - left + 1 = 0 - 0 + 1 = 1` recorded instantly. |
| **Sum Equals Exactly Target** | `[2, 3, 2], target = 7` | Boundary inequality `>=` | `currentSum >= target` triggers correctly on equality. |

---

## Pattern Takeaways

1. **Shrinking Sliding Window Template:**  
   When searching for the **minimal** window size, expand `right` with a `for` loop and shrink `left` with an inner `while (isValid)` loop.
2. **Comparison with Max Window:**  
   - Finding *maximum* window: shrink with `while (!isValid) left++;`.
   - Finding *minimum* window: shrink with `while (isValid) { record(); left++; }`.
