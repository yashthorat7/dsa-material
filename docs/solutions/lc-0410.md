# 410. Split Array Largest Sum

https://leetcode.com/problems/split-array-largest-sum

> **Hard** $\rightarrow$ **Binary Search on Answer**


> **Companies:** Google, Amazon, TikTok, Meta, ByteDance, Apple, Flipkart, Amazon India, Cognizant

## What are we solving?

Given an integer array `nums` and an integer `k`, split `nums` into `k` non-empty contiguous subarrays such that the **largest sum of any subarray is minimized**.

Return the **minimized largest sum** of the split.

```
 nums = [ 7, 2, 5, 10, 8 ],  k = 2
 
 Candidate Splits:
 1. [7] and [2, 5, 10, 8]       -> Max Subarray Sum = 25
 2. [7, 2] and [5, 10, 8]       -> Max Subarray Sum = 23
 3. [7, 2, 5] and [10, 8]       -> Max Subarray Sum = max(14, 18) = 18 (OPTIMAL!)
 4. [7, 2, 5, 10] and [8]       -> Max Subarray Sum = 24
 
 Minimized Largest Sum = 18
 Output: 18
```

### Input & Output Contract
- **Input:**
  - `nums`: `vector<int>` where $1 \le n \le 1000$, $0 \le \text{nums}[i] \le 10^6$.
  - `k`: `int` number of subarrays ($1 \le k \le \min(50, n)$).
- **Output:**
  - `int`: Minimized largest subarray sum.

### The Monotonic Search Space
Let candidate maximum subarray capacity be $C$:
- **Lower bound:** `low = max(nums)` (every individual number must fit in some subarray).
- **Upper bound:** `high = sum(nums)` (when $k = 1$, the entire array is in one subarray).
- **Monotonicity:** If capacity $C$ allows partitioning `nums` into $\le k$ subarrays, any larger capacity $C' > C$ is also valid.
We can binary search the capacity range $[ \max(\text{nums}), \sum \text{nums} ]$ in $O(n \log(\sum - \max))$ time!

---

**Example 1:**
```
Input:  nums = [7,2,5,10,8], k = 2
Output: 18
Explanation: There are four ways to split nums into two subarrays. The best way is to split it into [7,2,5] and [10,8], where the largest sum among the two subarrays is only 18.
```

**Example 2:**
```
Input:  nums = [1,2,3,4,5], k = 2
Output: 9
```

**Constraints:**
- $1 \le \text{nums.length} \le 1000$
- $0 \le \text{nums}[i] \le 10^6$
- $1 \le k \le \min(50, \text{nums.length})$

## Approach 1 — 2D Dynamic Programming ($O(k \cdot n^2)$)

### Intuition
Let `dp[i][j]` be the minimum largest sum for partitioning prefix `nums[0..j-1]` into `i` subarrays.
$$\text{dp}[i][j] = \min_{p < j} \max(\text{dp}[i - 1][p], \text{sum}(p \dots j - 1))$$

### C++ Implementation
```cpp
class Solution {
public:
    int splitArray(vector<int>& nums, int k) {
        int n = nums.size();
        vector<long long> prefix(n + 1, 0);
        for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + nums[i];
        
        vector<vector<long long>> dp(k + 1, vector<long long>(n + 1, LLONG_MAX));
        dp[0][0] = 0;
        
        for (int i = 1; i <= k; i++) {
            for (int j = 1; j <= n; j++) {
                for (int p = 0; p < j; p++) {
                    if (dp[i - 1][p] != LLONG_MAX) {
                        long long currentMax = max(dp[i - 1][p], prefix[j] - prefix[p]);
                        dp[i][j] = min(dp[i][j], currentMax);
                    }
                }
            }
        }
        
        return dp[k][n];
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(k \cdot n^2)$ | Three nested loops over subarrays and partition splits. TLE on large $n$. |
| **Space** | $O(k \cdot n)$ | 2D DP table. |

> **Verdict:** Suboptimal. Binary Search on Answer achieves $O(n \log(\sum - \max))$ time.

## Approach 2 — Binary Search on Feasible Capacity ✅

### Key Insight
1. **Define Range:**
   - `low = *max_element(nums.begin(), nums.end())`
   - `high = accumulate(nums.begin(), nums.end(), 0LL)`
2. While `low < high`:
   - `mid = low + (high - low) / 2`
   - **Greedy Subarray Count Test:** Iterate through `nums`. Accumulate numbers in `currentSum`. If `currentSum + x > mid`, we must start a new subarray (`count++`, `currentSum = x`).
   - If `count <= k`: `mid` capacity is sufficient (feasible). Try a tighter capacity: `high = mid`.
   - If `count > k`: capacity `mid` is too tight (requires $> k$ splits) $\implies$ `low = mid + 1`.
3. When `low == high`, `low` is the minimal feasible maximum sum.

```
nums = [7, 2, 5, 10, 8], k = 2
low = 10, high = 32

Iteration 1:
- mid = 21: splits: [7,2,5] (14), [10,8] (18) -> count = 2 <= 2 (valid) -> high = 21

Iteration 2:
- low = 10, high = 21
- mid = 15: splits: [7,2,5] (14), [10] (10), [8] (8) -> count = 3 > 2 (too small) -> low = 16

Iteration 3:
- low = 16, high = 21
- mid = 18: splits: [7,2,5] (14), [10,8] (18) -> count = 2 <= 2 (valid) -> high = 18

Converges to low == high == 18.

Result: 18 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int splitArray(vector<int>& nums, int k) {
        long long low = 0;
        long long high = 0;
        
        for (int x : nums) {
            low = max(low, (long long)x); // A subarray must hold at least the largest element
            high += x;                        // An entire array partition sums to total sum
        }
        
        while (low < high) {
            long long mid = low + (high - low) / 2;
            
            // Greedily count subarrays needed if max subarray sum is capped at mid
            int count = 1;
            long long currentSum = 0;
            
            for (int x : nums) {
                if (currentSum + x > mid) {
                    count++;
                    currentSum = x;
                } else {
                    currentSum += x;
                }
            }
            
            // If we can split within k subarrays, try finding a smaller capacity
            if (count <= k) {
                high = mid;
            } else {
                low = mid + 1;
            }
        }
        
        return static_cast<int>(low);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n \log(\sum - \max))$ | Binary search on answer space $[10^6, 10^9]$ takes $\approx 30$ iterations $\times n = 1000$ items $= 30,000$ operations (<5ms). |
| **Space** | $O(1)$ | Pure stack scalar registers. |

> **This is the one.** Clean, robust, and optimal Minimax Subarray Partition algorithm.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **`k = 1`** | `nums = [1, 2, 3], k = 1` | Subarray bounds | Single partition returns `high = sum = 6`. |
| **`k == nums.length`** | `nums = [1, 2, 3], k = 3` | Single-element splits | Returns `low = max = 3`. |
| **Sum Overflows 32-bit Integer** | $1000$ elements of size $10^6$ | Integer overflow ($10^9$) | Handled using `long long` for `low`, `high`, `mid`, and `currentSum`. |
