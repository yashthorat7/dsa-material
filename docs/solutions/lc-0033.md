## What are we solving?

There is an integer array `nums` sorted in ascending order (with **distinct** values). Prior to being passed to your function, `nums` is possibly rotated at an unknown pivot index. Given the array `nums` after the possible rotation and an integer `target`, return the index of `target` if it is in `nums`, or `-1` if it is not in `nums`.

You must achieve **$O(\log n)$ runtime complexity**.

**Example 1:**
```
Input:  nums = [4,5,6,7,0,1,2], target = 0
Output: 4
```

**Example 2:**
```
Input:  nums = [4,5,6,7,0,1,2], target = 3
Output: -1
```

**Example 3:**
```
Input:  nums = [1], target = 0
Output: -1
```

**Constraints:**
- $1 \le \text{nums.length} \le 5000$
- $-10^4 \le \text{nums}[i] \le 10^4$
- All values of `nums` are unique.
- `nums` is an ascending array that is possibly rotated.
- $-10^4 \le \text{target} \le 10^4$

## Approach 1 — One-Pass Binary Search on Sorted Half ✅

**Key insight:**
In any rotated sorted array, splitting at `mid` always leaves **at least one half strictly sorted**!
1. If `nums[low] <= nums[mid]`, the **left half is sorted**:
   - If `nums[low] <= target && target < nums[mid]`: target is in left half -> `high = mid - 1`.
   - Else: target is in right half -> `low = mid + 1`.
2. Otherwise, the **right half is sorted**:
   - If `nums[mid] < target && target <= nums[high]`: target is in right half -> `low = mid + 1`.
   - Else: target is in left half -> `high = mid - 1`.

```
nums = [4, 5, 6, 7, 0, 1, 2], target = 0
low = 0 (4), high = 6 (2)

1. mid = 3 (val = 7).
   nums[low]=4 <= nums[mid]=7 -> Left half [4, 5, 6, 7] is sorted!
   Is target 0 in [4..7]? No (0 < 4).
   -> Search right half: low = mid + 1 = 4.

2. low = 4 (0), high = 6 (2).
   mid = 5 (val = 1).
   nums[low]=0 <= nums[mid]=1 -> Left half [0, 1] is sorted!
   Is target 0 in [0..1]? YES (0 <= 0 < 1).
   -> Search left half: high = mid - 1 = 4.

3. low = 4 (0), high = 4 (0).
   mid = 4 (val = 0) == target!
   Return 4 ✓
```

```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int low = 0, high = nums.size() - 1;
        
        while (low <= high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] == target) return mid;
            
            if (nums[low] <= nums[mid]) {
                // Left half is sorted
                if (nums[low] <= target && target < nums[mid]) {
                    high = mid - 1;
                } else {
                    low = mid + 1;
                }
            } else {
                // Right half is sorted
                if (nums[mid] < target && target <= nums[high]) {
                    low = mid + 1;
                } else {
                    high = mid - 1;
                }
            }
        }
        
        return -1;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(\log n)$ | $O(1)$ |

> **This is the one.** Direct $O(\log n)$ identification of the sorted half.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| No rotation `[1, 2, 3, 4, 5]` | Condition failure | Behaves as normal binary search |
| Single element `[1], target = 0` | Single iteration | Returns -1 |
| Target at pivot boundary | Boundary inclusion `<= target` | Explicit `<=` comparisons ensure pivot boundaries are tested |

---

## Pattern Takeaway

In rotated arrays, **identify which half is normally sorted** using `nums[low] <= nums[mid]`, then check if the target falls within that sorted range.
