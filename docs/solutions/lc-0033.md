## What are we solving?

There is an integer array `nums` sorted in ascending order with **distinct values**. Prior to being passed to your function, `nums` was rotated at an unknown pivot index $k$ ($1 \le k < n$) such that the resulting array is:
$$[\text{nums}[k], \text{nums}[k+1], \dots, \text{nums}[n-1], \text{nums}[0], \text{nums}[1], \dots, \text{nums}[k-1]]$$

Given `nums` and a `target` integer, return the **index of `target`** if it exists in `nums`, or `-1` if it is not present.

```
 Original Sorted:  [0, 1, 2, 4, 5, 6, 7]
 Rotated (k = 4):  [4, 5, 6, 7, 0, 1, 2]
                                ↑
                   Search for target = 0 -> Index 4
```

### Input & Output Contract
- **Input:**
  - `nums`: `vector<int>` with length $1 \le n \le 5000$, $-10^4 \le \text{nums}[i] \le 10^4$ (all elements unique).
  - `target`: `int` search key ($-10^4 \le \text{target} \le 10^4$).
- **Output:**
  - `int` representing the 0-based index of `target` in `nums`, or `-1` if not found.
- **Constraint:** Must achieve **$O(\log n)$ runtime complexity**.

### The Core Challenge
The array is not globally monotonic, so standard binary search cannot be applied blindly. However, splitting any rotated sorted array at midpoint `mid` guarantees that **at least one of the two halves is strictly sorted**.

---

**Example 1:**
```
Input:  nums = [4,5,6,7,0,1,2], target = 0
Output: 4
```

**Example 2:**
```
Input:  nums = [4,5,6,7,0,1,2], target = 3
Output: -1
```

**Example 3:**
```
Input:  nums = [1], target = 0
Output: -1
```

**Constraints:**
- $1 \le \text{nums.length} \le 5000$
- $-10^4 \le \text{nums}[i] \le 10^4$
- All values of `nums` are unique.
- `nums` is an ascending array that is possibly rotated.
- $-10^4 \le \text{target} \le 10^4$

## Approach 1 — Linear Search (Brute Force)

### Intuition
Iterate through the array sequentially from index $0$ to $n-1$. Compare each element against `target`.

### C++ Implementation
```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        for (int i = 0; i < nums.size(); i++) {
            if (nums[i] == target) return i;
        }
        return -1;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Scans all $n$ elements in the worst case. |
| **Space** | $O(1)$ | No extra memory allocated. |

> **Verdict:** Violates the required $O(\log n)$ time constraint.

## Approach 2 — Two-Pass Binary Search (Find Pivot, then Search Half)

### Intuition
1. **Pass 1:** Use binary search to locate the pivot index (the minimum element where the rotation occurs).
2. **Pass 2:** Determine whether `target` lies in the left sorted segment `[0, pivot - 1]` or right sorted segment `[pivot, n - 1]`, and run standard binary search on that specific half.

```
nums = [4, 5, 6, 7, 0, 1, 2], target = 0

Pass 1 (Find min element index):
- Binary search locates minimum element 0 at pivot = 4.

Pass 2 (Target routing):
- target = 0 >= nums[pivot]=0 and target <= nums[n-1]=2 -> search in [4..6].
- Standard binary search in [4..6] finds target 0 at index 4 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int n = nums.size();
        int low = 0, high = n - 1;
        
        // Pass 1: Find index of minimum element (pivot)
        while (low < high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] > nums[high]) {
                low = mid + 1;
            } else {
                high = mid;
            }
        }
        int pivot = low;
        
        // Pass 2: Choose search interval
        low = 0;
        high = n - 1;
        if (target >= nums[pivot] && target <= nums[high]) {
            low = pivot;
        } else {
            high = pivot - 1;
        }
        
        // Standard Binary Search
        while (low <= high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] == target) return mid;
            if (nums[mid] < target) low = mid + 1;
            else high = mid - 1;
        }
        
        return -1;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\log n)$ | Two binary searches: $\log n + \log n = 2 \log n = O(\log n)$. |
| **Space** | $O(1)$ | Constant variables. |

> **Verdict:** Solid $O(\log n)$ approach, but requires writing two separate binary search routines.

## Approach 3 — Single-Pass Binary Search on Sorted Half ✅

### Key Insight
In any rotated array, the midpoint `mid` divides the array such that **at least one half is always strictly sorted**:
- If `nums[low] <= nums[mid]`, the **left half is sorted**:
  - If `nums[low] <= target && target < nums[mid]`, `target` lies in the left half $\rightarrow$ `high = mid - 1`.
  - Else, `target` must be in the right half $\rightarrow$ `low = mid + 1`.
- Otherwise (`nums[low] > nums[mid]`), the **right half is sorted**:
  - If `nums[mid] < target && target <= nums[high]`, `target` lies in the right half $\rightarrow$ `low = mid + 1`.
  - Else, `target` must be in the left half $\rightarrow$ `high = mid - 1`.

```
nums = [4, 5, 6, 7, 0, 1, 2], target = 0
low = 0 (4), high = 6 (2)

Iteration 1:
- mid = 3 (val = 7).
- nums[low]=4 <= nums[mid]=7 -> Left half [4, 5, 6, 7] is SORTED!
- Is target 0 in range [4, 7)? No (0 < 4).
- Eliminate left half -> low = mid + 1 = 4.

Iteration 2:
- low = 4 (0), high = 6 (2).
- mid = 5 (val = 1).
- nums[low]=0 <= nums[mid]=1 -> Left half [0, 1] is SORTED!
- Is target 0 in range [0, 1)? YES (0 <= 0 < 1).
- Target is in left half -> high = mid - 1 = 4.

Iteration 3:
- low = 4 (0), high = 4 (0).
- mid = 4 (val = 0) == target!
- Return index 4 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int low = 0;
        int high = nums.size() - 1;
        
        while (low <= high) {
            int mid = low + (high - low) / 2;
            
            if (nums[mid] == target) {
                return mid;
            }
            
            // Determine which half is sorted
            if (nums[low] <= nums[mid]) {
                // Left half [low..mid] is strictly sorted
                if (nums[low] <= target && target < nums[mid]) {
                    high = mid - 1; // Target is within left sorted range
                } else {
                    low = mid + 1;  // Target is in the other half
                }
            } else {
                // Right half [mid..high] is strictly sorted
                if (nums[mid] < target && target <= nums[high]) {
                    low = mid + 1;  // Target is within right sorted range
                } else {
                    high = mid - 1; // Target is in the other half
                }
            }
        }
        
        return -1;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\log n)$ | Search interval is halved in every step, guaranteeing $\log_2 n$ comparisons. |
| **Space** | $O(1)$ | Uses only three index pointer integers. |

> **This is the one.** Single pass, elegant condition partitioning, optimal time and space.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Not Rotated** | `[1, 2, 3, 4, 5]` | Left half condition triggers throughout | `nums[low] <= nums[mid]` always true; behaves like standard binary search. |
| **Single Element Found** | `[1], target = 1` | Loop bounds | Evaluates `mid = 0 == target`, returns 0 immediately. |
| **Single Element Missing** | `[1], target = 0` | Infinite loop | `low > high` after step 1, returns -1. |
| **Target at Extreme Ends** | `[4,5,6,0,1,2], target = 4` | Boundary inclusion `<= target` | Range checks `nums[low] <= target` and `target <= nums[high]` include bounds. |

## Pattern Takeaways

1. **The Invariant of Rotated Sub-Arrays:**  
   No matter where an array is rotated, picking `mid` guarantees that **at least one side (`[low..mid]` or `[mid..high]`) is completely monotonic**.
2. **Binary Decision Tree:**  
   Always check membership inside the *sorted* half first (since range bounds are definitive: $A \le \text{target} \le B$). If it's not inside, eliminate it and explore the other half.
3. **Generalization to Duplicates:**  
   When elements can be duplicated ([LC 81: Search in Rotated Sorted Array II](file:///e:/Projects/dsa-notes/docs/solutions/lc-0081.md)), if `nums[low] == nums[mid] == nums[high]`, we shrink bounds with `low++, high--` giving worst-case $O(n)$.
