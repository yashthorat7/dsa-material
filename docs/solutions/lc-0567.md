## What are we solving?

Given two strings `s1` and `s2`, return `true` if `s2` contains a **permutation** of `s1`, or `false` otherwise.

In other words, return `true` if one of `s1`'s permutations is a contiguous **substring** of `s2`.

```
 s1 = " a b " (length = 2)
 s2 = " e i d b a o o o "
 
 Substrings of length 2 in s2:
 - "ei" != permutation("ab")
 - "id" != permutation("ab")
 - "db" != permutation("ab")
 - "ba" == permutation("ab") -> MATCH FOUND!
 
 Output: true
```

### Input & Output Contract
- **Input:**
  - `s1`: `string` ($1 \le |s1| \le 10^4$).
  - `s2`: `string` ($1 \le |s2| \le 10^4$).
- **Output:**
  - `bool`: `true` if any substring of `s2` is an anagram of `s1`.

### The Core Fixed-Window Invariant
Any valid permutation of $s1$ must have:
1. Length **exactly equal** to $|s1|$.
2. The **exact same character counts** as $s1$.
We slide a fixed-size window of length $|s1|$ across $s2$, adjusting counts on the right (entering) and left (leaving) boundaries.

---

**Example 1:**
```
Input:  s1 = "ab", s2 = "eidbaooo"
Output: true
Explanation: s2 contains one permutation of s1 ("ba").
```

**Example 2:**
```
Input:  s1 = "ab", s2 = "eidboaoo"
Output: false
```

**Constraints:**
- $1 \le s1.\text{length}, s2.\text{length} \le 10^4$
- `s1` and `s2` consist of lowercase English letters.

## Approach 1 — Fixed-Size Sliding Window with Array Comparison

### Intuition
Maintain frequency tables `s1Count[26]` and `s2Count[26]`. Slide window of size $|s_1|$ across $s_2$. If `s1Count == s2Count`, a permutation exists $\implies$ return `true`.

### C++ Implementation
```cpp
class Solution {
public:
    bool checkInclusion(string s1, string s2) {
        int n1 = s1.length(), n2 = s2.length();
        if (n1 > n2) return false;
        
        vector<int> s1Count(26, 0), s2Count(26, 0);
        for (int i = 0; i < n1; i++) {
            s1Count[s1[i] - 'a']++;
            s2Count[s2[i] - 'a']++;
        }
        
        if (s1Count == s2Count) return true;
        
        for (int i = n1; i < n2; i++) {
            s2Count[s2[i] - 'a']++;
            s2Count[s2[i - n1] - 'a']--;
            if (s1Count == s2Count) return true;
        }
        
        return false;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(26 \cdot (n_2 - n_1)) = O(n_2)$ | Compares 26-element array at each step. |
| **Space** | $O(1)$ | Fixed 26-element arrays. |

## Approach 2 — Sliding Window with Match Count Tracking ✅

### Key Insight
Instead of scanning all 26 entries on every step, maintain a running counter `matches` (number of characters with identical counts in `s1` and the active window of `s2`):
- `matches == 26` indicates a complete anagram match.
- On shifting the window:
  - Add incoming character $s_2[i]$: update count and adjust `matches` ($\pm 1$).
  - Remove outgoing character $s_2[i - |s_1|]$: update count and adjust `matches` ($\pm 1$).
  - If `matches == 26`, return `true` immediately.
- This ensures strictly **$O(1)$ operations per character slide**!

```
s1 = "ab" (len 2), s2 = "eidbaooo"
count1: {a:1, b:1, others:0}

Initial window [0..1] ("ei"): count2={e:1, i:1}. matches = 24 (!= 26)
Slide 1: Add 'd', Remove 'e' -> "id" -> matches = 24
Slide 2: Add 'b', Remove 'i' -> "db" -> matches = 24
Slide 3: Add 'a', Remove 'd' -> "ba" -> matches = 26! MATCH!

Return true ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    bool checkInclusion(string s1, string s2) {
        int n1 = s1.length();
        int n2 = s2.length();
        if (n1 > n2) return false;
        
        int count1[26] = {0};
        int count2[26] = {0};
        
        for (int i = 0; i < n1; i++) {
            count1[s1[i] - 'a']++;
            count2[s2[i] - 'a']++;
        }
        
        int matches = 0;
        for (int i = 0; i < 26; i++) {
            if (count1[i] == count2[i]) matches++;
        }
        
        if (matches == 26) return true;
        
        for (int i = n1; i < n2; i++) {
            int inChar = s2[i] - 'a';
            int outChar = s2[i - n1] - 'a';
            
            // Add incoming character into window
            count2[inChar]++;
            if (count2[inChar] == count1[inChar]) {
                matches++;
            } else if (count2[inChar] == count1[inChar] + 1) {
                matches--;
            }
            
            // Remove outgoing character from window
            count2[outChar]--;
            if (count2[outChar] == count1[outChar]) {
                matches++;
            } else if (count2[outChar] == count1[outChar] - 1) {
                matches--;
            }
            
            if (matches == 26) return true;
        }
        
        return false;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n_1 + n_2)$ | Initial window calculation is $O(n_1 + 26)$; sliding window processes each character in $O(1)$ operations. |
| **Space** | $O(1)$ | Stack fixed frequency tables of size 26. |

> **This is the one.** Clean, robust, optimal single-pass substring permutation search.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **`s1` Longer Than `s2`** | `s1 = "abc", s2 = "ab"` | Substring index underflow | Early check `if (n1 > n2) return false;`. |
| **Immediate Match at Index 0** | `s1 = "ab", s2 = "abxyz"` | Missing pre-loop check | `if (matches == 26) return true;` before the loop catches immediate match. |
| **Permutation at the Very End** | `s1 = "ab", s2 = "xyab"` | Loop boundary omission | Loop index $i$ goes up to $n_2 - 1$, covering final window. |
