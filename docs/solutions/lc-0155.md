# 155. Min Stack

https://leetcode.com/problems/min-stack

> **Medium** $\rightarrow$ **Stack & Queue**


> **Companies:** Amazon, Microsoft, Bloomberg, Meta, Google, Salesforce, Flipkart, Adobe India, Infosys

---

## What are we solving?

Design a stack data structure that supports standard LIFO operations (`push`, `pop`, `top`) and retrieving the **minimum element in constant time** (`getMin`).

Implement the `MinStack` class:
- `MinStack()`: Initializes the stack object.
- `void push(int val)`: Pushes the element `val` onto the stack.
- `void pop()`: Removes the element on the top of the stack.
- `int top()`: Gets the top element of the stack.
- `int getMin()`: Retrieves the minimum element in the stack.

You must implement a solution with **$O(1)$ time complexity** for every function call.

```
 push(-2):  Top -> [-2 | min=-2]
 push(0):   Top -> [ 0 | min=-2] -> [-2 | min=-2]
 push(-3):  Top -> [-3 | min=-3] -> [ 0 | min=-2] -> [-2 | min=-2]
 
 getMin() -> -3
 pop()    -> pops -3
 top()    -> 0
 getMin() -> -2  (Historical minimum restored in O(1)!)
```

### Input & Output Contract
- **Operations:**
  - `push(int val)`: $-2^{31} \le \text{val} \le 2^{31} - 1$.
  - `pop()`, `top()`, `getMin()`: Guaranteed to be called only when the stack is non-empty.
- **Output:**
  - `top()` returns `int` top value.
  - `getMin()` returns `int` minimum element in stack.
- **Constraints:** Max $3 \times 10^4$ total method calls. All operations must run in strictly $O(1)$ time.

### The Core Challenge
When a new minimum is pushed and later popped, the stack must seamlessly restore the **previous historical minimum** in $O(1)$ time without scanning remaining elements.

---

**Example 1:**
```
Input:  ["MinStack","push","push","push","getMin","pop","top","getMin"]
[[],[-2],[0],[-3],[],[],[],[]]
Output: [null,null,null,null,-3,null,0,-2]

Explanation:
MinStack minStack = new MinStack();
minStack.push(-2);
minStack.push(0);
minStack.push(-3);
minStack.getMin(); // return -3
minStack.pop();
minStack.top();    // return 0
minStack.getMin(); // return -2
```

**Constraints:**
- $-2^{31} \le \text{val} \le 2^{31} - 1$
- Methods `pop`, `top` and `getMin` operations will always be called on non-empty stacks.
- At most $3 \times 10^4$ calls will be made to `push`, `pop`, `top`, and `getMin`.

## Approach 1 — Two Synchronized Stacks (Data Stack + Min Stack)

### Intuition
Maintain two separate stacks:
1. `dataStack`: stores all pushed values.
2. `minStack`: stores the running minimum. When pushing `val`, push `min(val, minStack.top())` onto `minStack`.
When popping from `dataStack`, simultaneously pop from `minStack`.

### C++ Implementation
```cpp
class MinStack {
private:
    stack<int> dataStack;
    stack<int> minStack;
public:
    MinStack() {}
    
    void push(int val) {
        dataStack.push(val);
        int currentMin = minStack.empty() ? val : min(val, minStack.top());
        minStack.push(currentMin);
    }
    
    void pop() {
        dataStack.pop();
        minStack.pop();
    }
    
    int top() {
        return dataStack.top();
    }
    
    int getMin() {
        return minStack.top();
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(1)$ | All operations (`push`, `pop`, `top`, `getMin`) perform constant number of stack operations. |
| **Space** | $O(n)$ | Stores $2n$ integers across two stacks. |

## Approach 2 — Stack of Pairs (Value + Prefix Minimum Snapshot) ✅

### Key Insight
Instead of synchronizing two independent stacks, bundle each item as a `pair<int, int>` `{value, prefixMin}` in a single stack:
- When pushing `val`:
  $$\text{newMin} = \text{st.empty()} \ ? \ \text{val} : \min(\text{val}, \text{st.top().second})$$
- `getMin()` simply inspects `st.top().second` in $O(1)$ time!

```
push(-2):  stack: [ {-2, -2} ]
push(0):   stack: [ {-2, -2}, {0, -2} ]
push(-3):  stack: [ {-2, -2}, {0, -2}, {-3, -3} ]

getMin():  st.top().second -> returns -3
pop():     pops {-3, -3}   -> stack: [ {-2, -2}, {0, -2} ]
top():     st.top().first  -> returns 0
getMin():  st.top().second -> returns -2 ✓
```

### C++ Implementation
```cpp
class MinStack {
private:
    stack<pair<int, int>> st; // pair<value, currentMinimum>
public:
    MinStack() {}
    
    void push(int val) {
        int currentMin = st.empty() ? val : min(val, st.top().second);
        st.push({val, currentMin});
    }
    
    void pop() {
        st.pop();
    }
    
    int top() {
        return st.top().first;
    }
    
    int getMin() {
        return st.top().second;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(1)$ | Every operation is strictly $O(1)$ with zero loop iteration or pointer hunting. |
| **Space** | $O(n)$ | Single stack storing $n$ pairs. |

> **This is the one.** Clean, impossible to de-synchronize, completely thread-safe and optimal.

## Approach 3 — Single Stack with Encoded Difference ($O(1)$ Value Storage)

### Intuition
If memory overhead is paramount, we can store a single integer per node by encoding differences:
- Maintain a single scalar `minVal`.
- When pushing `val`:
  - If `val < minVal`: push encoded value $2 \cdot \text{val} - \text{minVal}$ and update $\text{minVal} = \text{val}$.
  - Else: push raw `val`.
- On `pop()`:
  - If popped encoded value $< \text{minVal}$, the previous minimum was $2 \cdot \text{minVal} - \text{encoded}$.

### C++ Implementation
```cpp
class MinStack {
private:
    stack<long long> st;
    long long minVal;
public:
    MinStack() {}
    
    void push(int val) {
        if (st.empty()) {
            st.push(0LL);
            minVal = val;
        } else {
            st.push(static_cast<long long>(val) - minVal);
            if (val < minVal) {
                minVal = val;
            }
        }
    }
    
    void pop() {
        long long diff = st.top();
        st.pop();
        if (diff < 0) {
            minVal = minVal - diff; // Restore previous minimum
        }
    }
    
    int top() {
        long long diff = st.top();
        if (diff < 0) {
            return static_cast<int>(minVal);
        }
        return static_cast<int>(minVal + diff);
    }
    
    int getMin() {
        return static_cast<int>(minVal);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(1)$ | Arithmetic encoding and decoding in $O(1)$. |
| **Space** | $O(n)$ | Stores exactly one `long long` per pushed element. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Duplicate Minimums** | `push(2), push(2), pop()` | Forgetting previous minimum when duplicate is popped | Stack of pairs stores independent snapshot for each frame, keeping minimum intact. |
| **Extreme Range Values** | `val = INT_MIN, INT_MAX` | Integer overflow during difference encoding | Approach 2 uses direct `min` without subtraction overflow risks. |
| **Monotonically Decreasing** | `[5, 4, 3, 2, 1]` | Consecutive minimum updates | Each step updates current minimum smoothly. |

---

## Pattern Takeaways

1. **State Snapshotting Pattern:**  
   When an aggregate property (like min, max, or running sum) needs to be queried in $O(1)$ after arbitrary push and pop operations, store the aggregate value directly inside each stack node snapshot.
2. **Generalization to MaxStack / MedianStack:**  
   This exact pattern implements `MaxStack` (`pair<val, maxVal>`) and forms the foundation for Monotonic Stacks and Double-Ended Priority Queues.
