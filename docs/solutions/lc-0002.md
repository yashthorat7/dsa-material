## What are we solving?

You are given two **non-empty** linked lists representing two non-negative integers. The digits are stored in **reverse order**, and each of their nodes contains a single digit. Add the two numbers and return the sum as a linked list.

```
  l1:  (2) -> (4) -> (3)      [Represents 342]
  l2:  (5) -> (6) -> (4)      [Represents 465]
  ------------------------
  Sum: (7) -> (0) -> (8)      [Represents 807: 342 + 465]
```

### Input & Output Contract
- **Input:**
  - `l1`: `ListNode*` pointing to the head of the first reversed-digit list ($1 \le \text{length} \le 100$).
  - `l2`: `ListNode*` pointing to the head of the second reversed-digit list ($1 \le \text{length} \le 100$).
- **Output:**
  - `ListNode*` pointing to the head of the result list containing the digit-by-digit sum in reversed order.

### The Core Challenge
Since the digits are given in **reverse order**, the heads of both lists are the **least significant digits** (ones column). This is actually convenient because addition naturally flows from least significant to most significant digit with carry propagation ($0 \le \text{carry} \le 1$). The challenge is cleanly handling lists of unequal lengths and managing an extra overflow carry at the very end (e.g., $99 + 1 = 100$).

---

**Example 1:**
```
Input:  l1 = [2,4,3], l2 = [5,6,4]
Output: [7,0,8]
Explanation: 342 + 465 = 807.
```

**Example 2:**
```
Input:  l1 = [0], l2 = [0]
Output: [0]
```

**Example 3:**
```
Input:  l1 = [9,9,9,9,9,9,9], l2 = [9,9,9,9]
Output: [8,9,9,9,0,0,0,1]
```

**Constraints:**
- The number of nodes in each linked list is in the range $[1, 100]$.
- $0 \le \text{Node.val} \le 9$
- It is guaranteed that the list represents a number that does not have leading zeros.

## Approach 1 — Iterative Simulation with Dummy Head & Carry Propagation ✅

### Intuition
Simulate elementary school column-by-column addition:
1. Start with `carry = 0` and a `dummy` pre-head node.
2. Advance through both lists simultaneously. At each position, sum = $\text{val}_1 + \text{val}_2 + \text{carry}$.
3. Create a new node with `sum % 10` and set `carry = sum / 10`.
4. If one list runs out before the other, treat missing digits as `0`.
5. Keep running as long as `l1 != nullptr`, `l2 != nullptr`, OR `carry > 0`!

### Step-by-Step Algorithm
1. Initialize `ListNode dummy(0)`, `curr = &dummy`, and `carry = 0`.
2. While `l1 != nullptr || l2 != nullptr || carry != 0`:
   - `sum = carry`
   - If `l1 != nullptr`, add `l1->val` and advance `l1 = l1->next`.
   - If `l2 != nullptr`, add `l2->val` and advance `l2 = l2->next`.
   - Update `carry = sum / 10`.
   - Attach new node `curr->next = new ListNode(sum % 10)`.
   - Advance `curr = curr->next`.
3. Return `dummy.next`.

```
l1 = [2, 4, 3] (342)
l2 = [5, 6, 4] (465)
carry = 0, dummy -> nullptr

Step 1: sum = 0 + 2 + 5 = 7  -> carry = 0, node(7), curr = 7
Step 2: sum = 0 + 4 + 6 = 10 -> carry = 1, node(0), curr = 0
Step 3: sum = 1 + 3 + 4 = 8  -> carry = 0, node(8), curr = 8
Loop ends (l1=null, l2=null, carry=0).

Result: dummy.next -> 7 -> 0 -> 8 (807) ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    ListNode* addTwoNumbers(ListNode* l1, ListNode* l2) {
        ListNode dummy(0);
        ListNode* curr = &dummy;
        int carry = 0;
        
        // Loop runs until BOTH lists are exhausted AND no carry remains
        while (l1 != nullptr || l2 != nullptr || carry != 0) {
            int sum = carry;
            
            if (l1 != nullptr) {
                sum += l1->val;
                l1 = l1->next;
            }
            if (l2 != nullptr) {
                sum += l2->val;
                l2 = l2->next;
            }
            
            carry = sum / 10;
            curr->next = new ListNode(sum % 10);
            curr = curr->next;
        }
        
        return dummy.next;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\max(m, n))$ | Loops at most $\max(m, n) + 1$ times, visiting each node in `l1` and `l2` once. |
| **Space** | $O(\max(m, n))$ | The returned linked list contains at most $\max(m, n) + 1$ nodes. Auxiliary memory is $O(1)$. |

> **This is the one.** Optimal, clean, single loop with unified carry handling.

## Approach 2 — Recursive Simulation

### Intuition
Each recursive step adds the head digits of `l1` and `l2` plus a passed `carry`, attaches the resulting node, and recursively calculates the remainder of the sum.

### Step-by-Step Algorithm
1. Base case: If `l1 == nullptr && l2 == nullptr && carry == 0`, return `nullptr`.
2. Compute `sum = carry + (l1 ? l1->val : 0) + (l2 ? l2->val : 0)`.
3. Create node `ListNode* result = new ListNode(sum % 10)`.
4. Link `result->next = addRecursive(l1 ? l1->next : nullptr, l2 ? l2->next : nullptr, sum / 10)`.
5. Return `result`.

### C++ Implementation
```cpp
class Solution {
public:
    ListNode* addTwoNumbers(ListNode* l1, ListNode* l2) {
        return addHelper(l1, l2, 0);
    }

private:
    ListNode* addHelper(ListNode* l1, ListNode* l2, int carry) {
        if (!l1 && !l2 && carry == 0) {
            return nullptr;
        }
        
        int sum = carry;
        if (l1) {
            sum += l1->val;
            l1 = l1->next;
        }
        if (l2) {
            sum += l2->val;
            l2 = l2->next;
        }
        
        ListNode* node = new ListNode(sum % 10);
        node->next = addHelper(l1, l2, sum / 10);
        return node;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\max(m, n))$ | Exactly $\max(m, n) + 1$ recursive calls. |
| **Space** | $O(\max(m, n))$ | Recursion stack depth is $\max(m, n) + 1$. |

> **Verdict:** Elegant functional style, but utilizes extra stack space compared to the iterative approach.

## Approach 3 — In-Place Node Mutation (Memory Constrained)

### Intuition
If memory allocations are strictly prohibited or expensive in a low-latency environment, we can reuse the existing `ListNode` objects in `l1` (or whichever list is longer), modifying `val` directly and only allocating a single node if an overflow carry remains at the end.

### C++ Implementation
```cpp
class Solution {
public:
    ListNode* addTwoNumbers(ListNode* l1, ListNode* l2) {
        ListNode* head = l1;
        ListNode* prev = nullptr;
        int carry = 0;
        
        while (l1 != nullptr || l2 != nullptr) {
            int sum = carry + (l1 ? l1->val : 0) + (l2 ? l2->val : 0);
            carry = sum / 10;
            
            if (l1 != nullptr) {
                l1->val = sum % 10;
                prev = l1;
                l1 = l1->next;
            } else {
                // l1 ran out, append l2 node into l1 chain
                prev->next = l2;
                l2->val = sum % 10;
                prev = l2;
                l1 = nullptr; // keep l1 null
            }
            
            if (l2 != nullptr) l2 = l2->next;
        }
        
        // Final carry node if needed
        if (carry > 0) {
            prev->next = new ListNode(carry);
        }
        
        return head;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\max(m, n))$ | Traverses each node once. |
| **Space** | $O(1)$ auxiliary | Reuses existing nodes, creating at most 1 new node for the final carry. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Unequal List Lengths** | `[9, 9] + [1]` | Loop exiting early when shorter list ends. | `while (l1 \|\| l2 \|\| carry)` with ternary `l1 ? l1->val : 0` treats missing positions as 0. |
| **Final Carry Overflow** | `[5] + [5]` $\rightarrow$ `[0, 1]` | Forgetting the carry after both lists reach `nullptr`. | `carry != 0` in loop condition ensures extra `1` node is created. |
| **Cascade of Nines** | `[9,9,9] + [1]` $\rightarrow$ `[0,0,0,1]` | Carry propagating across multiple iterations. | `carry` carries over to each subsequent column correctly. |
| **Zero Values** | `[0] + [0]` $\rightarrow$ `[0]` | Incorrect termination on 0. | `sum = 0 + 0 = 0`, outputs `[0]` and loop terminates cleanly. |

## Pattern Takeaways

1. **Unified Loop Condition:**  
   Including `carry != 0` directly in `while (l1 || l2 || carry)` eliminates any duplicate "clean-up" logic after the loop.
2. **Column Addition Paradigm:**
