## What are we solving?

A **path** in a binary tree is a sequence of nodes where each pair of adjacent nodes in the sequence has an edge connecting them. A node can only appear in the sequence **at most once**. Note that the path does not need to pass through the root.

The **path sum** of a path is the sum of the node's values in the path.

Given the `root` of a binary tree, return the **maximum path sum** of any non-empty path.

```
       (-10)
       /   \
     (9)   (20)  <-- Optimal Apex Node
           /  \
        (15)  (7)
        
 Optimal Path: 15 -> 20 -> 7
 Path Sum = 15 + 20 + 7 = 42
```

### Input & Output Contract
- **Input:**
  - `root`: `TreeNode*` pointing to root of binary tree ($1 \le n \le 3 \times 10^4$, $-1000 \le \text{Node.val} \le 1000$).
- **Output:**
  - `int` representing the maximum sum among all possible paths in the tree.

### The Core Challenge
At any node `u`, there is a critical distinction between:
1. **The Maximum Path with `u` as Apex (Turning Point):** Combines `u->val + leftGain + rightGain`. This path cannot be extended upwards to `u`'s parent.
2. **The Maximum Single-Branch Gain Returned Upward:** Can only choose **at most one** child path: `u->val + max(leftGain, rightGain)`.
Additionally, if a child's branch sum is **negative**, choosing it would only decrease our sum, so we must clamp negative gains to `0`!

---

**Example 1:**
```
Input:  root = [1,2,3]
Output: 6
Explanation: The optimal path is 2 -> 1 -> 3 with a path sum of 2 + 1 + 3 = 6.
```

**Example 2:**
```
Input:  root = [-10,9,20,null,null,15,7]
Output: 42
Explanation: The optimal path is 15 -> 20 -> 7 with a path sum of 15 + 20 + 7 = 42.
```

**Constraints:**
- The number of nodes in the tree is in the range $[1, 3 \times 10^4]$.
- $-1000 \le \text{Node.val} \le 1000$

## Approach 1 — Top-Down Brute Force (Evaluate All Pairs)

### Intuition
For every node $u$ in the tree, treat $u$ as the highest ancestor (inflection point) of a path. Calculate the maximum downward branch sum from $u \rightarrow \text{left}$ and $u \rightarrow \text{right}$, and sum them with $u\text{->val}$.

### C++ Implementation
```cpp
class Solution {
public:
    int maxPathSum(TreeNode* root) {
        if (!root) return INT_MIN;
        
        int leftMax = max(0, maxGain(root->left));
        int rightMax = max(0, maxGain(root->right));
        int currentMax = root->val + leftMax + rightMax;
        
        int leftSubtree = maxPathSum(root->left);
        int rightSubtree = maxPathSum(root->right);
        
        return max({currentMax, leftSubtree, rightSubtree});
    }

private:
    int maxGain(TreeNode* node) {
        if (!node) return 0;
        int left = max(0, maxGain(node->left));
        int right = max(0, maxGain(node->right));
        return node->val + max(left, right);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n^2)$ | For each node, `maxGain` traverses descendant subtrees. |
| **Space** | $O(h)$ | Recursion stack depth bounded by tree height $h$. |

> **Verdict:** Suboptimal. Bottom-up post-order DFS aggregates inflection sums and branch gains in a single $O(n)$ pass.
