## What are we solving?

Implement the `BSTIterator` class that represents an iterator over the **in-order traversal** of a binary search tree (BST):
- `BSTIterator(TreeNode* root)` Initializes an object of the `BSTIterator` class. The `root` of the BST is given as part of the constructor. The pointer should be initialized to a non-existent number smaller than any element in the BST.
- `boolean hasNext()` Returns `true` if there exists a number in the traversal to the right of the pointer, otherwise returns `false`.
- `int next()` Moves the pointer to the right, then returns the number at the pointer.

You must implement `next()` and `hasNext()` in **$O(1)$ amortized time** and use **$O(h)$ memory**.

**Example 1:**
```
Input:  ["BSTIterator", "next", "next", "hasNext", "next", "hasNext", "next", "hasNext", "next", "hasNext"]
[[[7, 3, 15, null, null, 9, 20]], [], [], [], [], [], [], [], [], []]
Output: [null, 3, 7, true, 9, true, 15, true, 20, false]
Explanation: BSTIterator bSTIterator = new BSTIterator(root);
bSTIterator.next();    // return 3
bSTIterator.next();    // return 7
bSTIterator.hasNext(); // return True
bSTIterator.next();    // return 9
bSTIterator.hasNext(); // return True
bSTIterator.next();    // return 15
bSTIterator.hasNext(); // return True
bSTIterator.next();    // return 20
bSTIterator.hasNext(); // return False
```

**Constraints:**
- The number of nodes in the tree is in the range $[1, 10^5]$.
- $0 \le \text{Node.val} \le 10^6$
- At most $10^5$ calls will be made to `hasNext`, and `next`.

## Approach 1 — Controlled In-Order Traversal with Stack ✅

**Key insight:**
Maintain a stack of nodes representing the current path down the leftmost branch:
1. Helper `pushAllLeft(node)`: pushes `node` and all its left descendants onto stack.
2. In constructor: `pushAllLeft(root)`.
3. `hasNext()`: `return !st.empty();` ($O(1)$).
4. `next()`:
   - Pop `node = st.top()`, `st.pop()`.
   - Call `pushAllLeft(node->right)`.
   - Return `node->val`.
Each node is pushed and popped exactly once, giving **$O(1)$ amortized time per `next()`** and $O(h)$ space.

```
Tree: [7, 3, 15, null, null, 9, 20]

Init: pushAllLeft(7) -> stack: [7, 3]
next(): pop 3, pushAllLeft(null) -> returns 3, stack: [7]
next(): pop 7, pushAllLeft(15) -> stack: [15, 9], returns 7
next(): pop 9, returns 9, stack: [15]
next(): pop 15, pushAllLeft(20) -> stack: [20], returns 15
next(): pop 20, returns 20, stack: []
hasNext(): false ✓
```

```cpp
class BSTIterator {
private:
    stack<TreeNode*> st;
    
    void pushAllLeft(TreeNode* node) {
        while (node) {
            st.push(node);
            node = node->left;
        }
    }
public:
    BSTIterator(TreeNode* root) {
        pushAllLeft(root);
    }
    
    int next() {
        TreeNode* node = st.top();
        st.pop();
        pushAllLeft(node->right);
        return node->val;
    }
    
    bool hasNext() {
        return !st.empty();
    }
};
```

| Time | Space |
|:-----|:------|
| $O(1)$ amortized for `next()`, $O(1)$ for `hasNext()` | $O(h)$ for stack memory |

> **This is the one.** Standard design for lazy BST in-order streaming.

---

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Skewed BST | Stack depth | Stack size bounded by maximum tree height $h$ |
| No right children | Empty pushAllLeft | `node->right` is null, returns popped values smoothly |

---

## Pattern Takeaway

**Controlled In-Order traversal (`pushAllLeft`)** freezes and resumes recursive in-order state on demand in $O(h)$ space.
