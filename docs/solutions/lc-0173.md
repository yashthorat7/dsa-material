## What are we solving?

Implement the `BSTIterator` class that represents an iterator over the **in-order traversal** of a Binary Search Tree (BST):
- `BSTIterator(TreeNode* root)`: Initializes an object of the class. The pointer is positioned before the smallest element in the BST.
- `bool hasNext()`: Returns `true` if there exists a number in the in-order traversal to the right of the pointer; otherwise `false`.
- `int next()`: Advances the pointer to the next smallest element and returns its value.

```
       7
      / \
     3   15
        /  \
       9    20
       
 In-Order Sequence: [ 3, 7, 9, 15, 20 ]
 
 Operations:
 1. next()    -> 3
 2. next()    -> 7
 3. hasNext() -> true
 4. next()    -> 9
 5. hasNext() -> true
 6. next()    -> 15
 7. hasNext() -> true
 8. next()    -> 20
 9. hasNext() -> false
```

### Input & Output Contract
- **Input:**
  - `root`: `TreeNode*` root of a BST ($1 \le N \le 10^5$, $0 \le \text{Node.val} \le 10^6$).
- **Requirements:**
  - `next()` and `hasNext()` must run in **$O(1)$ amortized time**.
  - Must use at most **$O(h)$ memory**, where $h$ is the height of the tree.

### The Core Challenge
Pre-flattening the entire BST into an array in the constructor requires $O(N)$ space, violating the strict $O(h)$ memory constraint (for balanced trees, $h = \log N \ll N$).  
We must construct a **Lazy Generator Stack** that pauses the in-order traversal after each node and only consumes memory equal to the active branch height.

---

**Example 1:**
```
Input:
["BSTIterator", "next", "next", "hasNext", "next", "hasNext", "next", "hasNext", "next", "hasNext"]
[[[7, 3, 15, null, null, 9, 20]], [], [], [], [], [], [], [], [], []]

Output:
[null, 3, 7, true, 9, true, 15, true, 20, false]
```

**Constraints:**
- The number of nodes in the tree is in the range $[1, 10^5]$.
- $0 \le \text{Node.val} \le 10^6$
- At most $10^5$ calls will be made to `hasNext`, and `next`.

## Approach 1 — Eager Array In-Order Flattening ($O(N)$ Space)

### Intuition
Flatten the entire BST in-order into a dynamic vector `nodes` during constructor initialization. Use an integer index `idx` to answer `next()` and `hasNext()` queries.

### C++ Implementation
```cpp
class BSTIterator {
private:
    vector<int> nodes;
    int idx;
    
    void inorder(TreeNode* root) {
        if (!root) return;
        inorder(root->left);
        nodes.push_back(root->val);
        inorder(root->right);
    }

public:
    BSTIterator(TreeNode* root) {
        idx = 0;
        inorder(root);
    }
    
    int next() {
        return nodes[idx++];
    }
    
    bool hasNext() {
        return idx < nodes.size();
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | Constructor $O(N)$, `next()`/`hasNext()` $O(1)$ | Eagerly traverses entire tree upfront. |
| **Space** | $O(N)$ | Stores all $N$ node values in an array. |

> **Verdict:** Suboptimal. Lazy iterative stack traversal reduces memory to $O(h)$ (height of tree).
