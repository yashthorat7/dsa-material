## What are we solving?

Koko loves to eat bananas. There are `n` piles of bananas, the $i$-th pile has `piles[i]` bananas. The guards have gone and will come back in `h` hours. Koko can decide her bananas-per-hour eating speed of `k`. Each hour, she chooses some pile of bananas and eats `k` bananas from that pile. If the pile has less than `k` bananas, she eats all of them instead and will not eat any more bananas during this hour.

Return the **minimum integer `k`** such that she can eat all the bananas within `h` hours.

The core question is: **how do we binary search over the monotonic answer space `k \in [1, \max(\text{piles})]`?**

**Example 1:**
```
Input:  piles = [3,6,7,11], h = 8
Output: 4
```

**Example 2:**
```
Input:  piles = [30,11,23,4,20], h = 5
Output: 30
```

**Example 3:**
```
Input:  piles = [30,11,23,4,20], h = 6
Output: 23
```

**Constraints:**
- $1 \le \text{piles.length} \le 10^4$
- $\text{piles.length} \le h \le 10^9$
- $1 \le \text{piles}[i] \le 10^9$

## Approach 1 — Binary Search on Answer Space ✅

**Key insight:**
- Minimum possible speed: `low = 1`.
- Maximum needed speed: `high = max(piles)` (eating any pile in 1 hour).
- Monotonic property: If speed `k` is fast enough to finish within `h` hours, any speed `> k` is also valid.
For a speed `k`, hours needed = $\sum \lceil \text{pile} / k \rceil = \sum (\text{pile} + k - 1) / k$.
- If `hours <= h`: speed is valid, try smaller speed -> `high = mid`.
- If `hours > h`: speed is too slow -> `low = mid + 1`.

```
piles = [3, 6, 7, 11], h = 8
low = 1, high = 11

mid = 6: hours = 1 + 1 + 2 + 2 = 6 <= 8 (valid) -> high = 6
mid = 3: hours = 1 + 2 + 3 + 4 = 10 > 8 (too slow) -> low = 4
mid = 5: hours = 1 + 2 + 2 + 3 = 8 <= 8 (valid) -> high = 5
mid = 4: hours = 1 + 2 + 2 + 3 = 8 <= 8 (valid) -> high = 4
low == high == 4.

Result: 4 ✓
```

```cpp
class Solution {
public:
    int minEatingSpeed(vector<int>& piles, int h) {
        int low = 1, high = 0;
        for (int p : piles) high = max(high, p);
        
        while (low < high) {
            int mid = low + (high - low) / 2;
            long long hours = 0;
            for (int p : piles) {
                hours += (p + mid - 1LL) / mid; // ceiling division
            }
            
            if (hours <= h) {
                high = mid; // can finish, try slower speed
            } else {
                low = mid + 1; // too slow, need faster speed
            }
        }
        
        return low;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n \log(\max(\text{piles})))$ | $O(1)$ |

> **This is the one.** Standard Binary Search on Answer pattern.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| `h == piles.length` | Minimum speed equals max pile | Binary search converges to `max(piles)` |
| Large piles summing to huge hours `pile = 10^9` | Integer overflow on hours sum | Accumulate `hours` using `long long` |
| Ceiling division roundoff | Floating point inaccuracies | Integer formula `(p + mid - 1LL) / mid` prevents precision issues |

---

## Pattern Takeaway

Whenever a decision function exhibits monotonicity (**'can we do it with capacity X?' is True for all $X \ge X^*$**), apply **Binary Search on the Answer Space**.
