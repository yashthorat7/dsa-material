## What are we solving?

Given the heads of two sorted linked lists `list1` and `list2`, merge the two lists into one **sorted** list. The list should be made by splicing together the existing nodes of both lists. Return the head of the merged list.

```
 list1: [1] ---------> [2] ---------> [4] -> nullptr
           \             \               \
            v             v               v
 Result: [1] -> [1] -> [2] -> [3] -> [4] -> [4] -> nullptr
                ^             ^               ^
               /             /               /
 list2:      [1] ---------> [3] ---------> [4] -> nullptr
```

### Input & Output Contract
- **Input:**
  - `list1`: `ListNode*` pointing to the first sorted list ($0 \le \text{length} \le 50$).
  - `list2`: `ListNode*` pointing to the second sorted list ($0 \le \text{length} \le 50$).
- **Output:**
  - `ListNode*` pointing to the head of the merged sorted list.

### The Core Challenge
We want to merge the lists in-place without creating new nodes (`$O(1)$` auxiliary memory), preserving sorted order in a single $O(m + n)$ scan.

---

**Example 1:**
```
Input:  list1 = [1,2,4], list2 = [1,3,4]
Output: [1,1,2,3,4,4]
```

**Example 2:**
```
Input:  list1 = [], list2 = []
Output: []
```

**Example 3:**
```
Input:  list1 = [], list2 = [0]
Output: [0]
```

**Constraints:**
- The number of nodes in both lists is in the range $[0, 50]$.
- $-100 \le \text{Node.val} \le 100$
- Both `list1` and `list2` are sorted in non-decreasing order.

## Approach 1 — Iterative Pointer Splicing with Dummy Head ✅

### Intuition
Maintain a `dummy` node and a running `tail` pointer. At each step, compare the values at `list1` and `list2`. Append the node with the smaller value to `tail->next` and advance that list's pointer. When one list runs out, attach the entire remainder of the other list in a single $O(1)$ link.

### Step-by-Step Algorithm
1. Initialize `ListNode dummy(0)` and `ListNode* tail = &dummy`.
2. While both `list1 != nullptr` and `list2 != nullptr`:
   - If `list1->val <= list2->val`: attach `list1` (`tail->next = list1`) and advance `list1 = list1->next`.
   - Else: attach `list2` (`tail->next = list2`) and advance `list2 = list2->next`.
   - Advance `tail = tail->next`.
3. Once the loop ends, at most one list is non-empty. Attach it: `tail->next = list1 ? list1 : list2`.
4. Return `dummy.next`.

```
list1 = [1, 2, 4], list2 = [1, 3, 4]
dummy -> nullptr, tail = dummy

Step 1: list1->val (1) <= list2->val (1) -> tail->next = list1 (1), list1 = [2, 4], tail = 1
Step 2: list2->val (1) < list1->val (2)  -> tail->next = list2 (1), list2 = [3, 4], tail = 1
Step 3: list1->val (2) < list2->val (3)  -> tail->next = list1 (2), list1 = [4],    tail = 2
Step 4: list2->val (3) < list1->val (4)  -> tail->next = list2 (3), list2 = [4],    tail = 3
Step 5: list1->val (4) <= list2->val (4) -> tail->next = list1 (4), list1 = null,   tail = 4
Loop terminates: list1 is null -> tail->next = list2 (4)

Merged result: 1 -> 1 -> 2 -> 3 -> 4 -> 4 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {
        ListNode dummy(0);
        ListNode* tail = &dummy;
        
        while (list1 != nullptr && list2 != nullptr) {
            if (list1->val <= list2->val) {
                tail->next = list1;
                list1 = list1->next;
            } else {
                tail->next = list2;
                list2 = list2->next;
            }
            tail = tail->next;
        }
        
        // Splice the entire remaining non-null chain in O(1)
        tail->next = (list1 != nullptr) ? list1 : list2;
        
        return dummy.next;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(m + n)$ | Each iteration consumes one node from either `list1` or `list2`. |
| **Space** | $O(1)$ | Only references/pointers are manipulated in place. |

> **This is the one.** Constant auxiliary space, single pass, clean edge handling.

## Approach 2 — Recursive Divide & Conquer

### Intuition
The merge operation has a clean recursive substructure:
- If `list1->val <= list2->val`, then `list1` is the head of the merged list, and its `next` pointer should point to the result of `mergeTwoLists(list1->next, list2)`.
- Otherwise, `list2` is the head, and its `next` should point to `mergeTwoLists(list1, list2->next)`.

### Step-by-Step Algorithm
1. **Base Cases:**
   - If `list1 == nullptr`, return `list2`.
   - If `list2 == nullptr`, return `list1`.
2. **Recursive Step:**
   - If `list1->val <= list2->val`:
     `list1->next = mergeTwoLists(list1->next, list2);`
     return `list1`;
   - Else:
     `list2->next = mergeTwoLists(list1, list2->next);`
     return `list2`;

```
merge([1, 2, 4], [1, 3, 4])
 └─ 1 (list1) -> next = merge([2, 4], [1, 3, 4])
     └─ 1 (list2) -> next = merge([2, 4], [3, 4])
         └─ 2 (list1) -> next = merge([4], [3, 4])
             └─ 3 (list2) -> next = merge([4], [4])
                 └─ 4 (list1) -> next = merge([], [4])
                     └─ returns [4] (list2)
```

### C++ Implementation
```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {
        if (!list1) return list2;
        if (!list2) return list1;
        
        if (list1->val <= list2->val) {
            list1->next = mergeTwoLists(list1->next, list2);
            return list1;
        } else {
            list2->next = mergeTwoLists(list1, list2->next);
            return list2;
        }
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(m + n)$ | Visits every node in both lists. |
| **Space** | $O(m + n)$ | Call stack depth proportional to total nodes ($m + n$). |

> **Verdict:** Extremely concise and mathematically elegant, but consumes $O(m + n)$ stack frames.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Both lists empty** | `list1 = [], list2 = []` | Dereferencing null pointer | Loop condition fails immediately, `tail->next = nullptr`, returns `nullptr`. |
| **One empty list** | `list1 = [], list2 = [0]` | Premature termination | Loop skipped; `tail->next = list2` attaches `[0]` directly. |
| **Unequal lengths** | `list1 = [1, 5, 9, 12], list2 = [2]` | Dropping remaining elements | `tail->next = list1 ? list1 : list2` splices remainder in $O(1)$. |
| **Duplicate values** | `list1 = [1, 1], list2 = [1, 1]` | Preserving all duplicates | Uses `<=` so duplicate values from both lists are retained in sequence. |

## Pattern Takeaways

1. **The Single-Link Remainder Attachment:**  
   Unlike arrays where merging remaining elements requires a `while` loop copying items, linked lists allow attaching the entire rest of a chain via a single assignment (`tail->next = list1 ? list1 : list2`).
2. **Foundational for Merge Sort on Linked Lists:**  
   This exact routine serves as the merge step in $O(n \log n)$ Merge Sort for linked lists ([LC 148: Sort List](file:///e:/Projects/dsa-notes/docs/solutions/lc-0148.md)) and in merging $k$ sorted lists ([LC 23: Merge k Sorted Lists](file:///e:/Projects/dsa-notes/docs/solutions/lc-0023.md)).
