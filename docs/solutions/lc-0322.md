## What are we solving?

You are given an integer array `coins` representing coins of different denominations and an integer `amount` representing a total amount of money.

Return the **fewest number of coins** that you need to make up that amount. If that amount of money cannot be made up by any combination of the coins, return `-1`.

You may assume that you have an **infinite supply** of each kind of coin.

```
 coins = [ 1, 2, 5 ],  amount = 11
 
 Ways to make 11:
 - 11 * 1¢ = 11 coins
 - 5 * 2¢ + 1 * 1¢ = 6 coins
 - 2 * 5¢ + 1 * 1¢ = 3 coins (5 + 5 + 1 = 11) <-- MINIMUM!
 
 Fewest Coins = 3
```

### Input & Output Contract
- **Input:**
  - `coins`: `vector<int>` where $1 \le \text{coins.length} \le 12$, $1 \le \text{coins}[i] \le 2^{31} - 1$.
  - `amount`: `int` ($0 \le \text{amount} \le 10^4$).
- **Output:**
  - `int`: Minimum coins required, or `-1` if impossible.

### The Core Challenge
A greedy choice (always picking the largest denomination) fails! For example: `coins = [1, 3, 4], amount = 6`:
- Greedy: $4 + 1 + 1 = 6$ (3 coins).
- Optimal: $3 + 3 = 6$ (2 coins).
Because denominations are arbitrary, this is an **Unbounded Knapsack / Shortest Path** problem requiring Dynamic Programming.

---

Input:  coins = [1,2,5], amount = 11

Explanation: 11 = 5 + 5 + 1
```

**Example 2:**

```

## Approach 1 — Top-Down Recursion with Memoization

### Intuition
Let `solve(rem)` be the minimum coins to make remaining amount `rem`:
$$\text{solve}(\text{rem}) = 1 + \min_{c \in \text{coins}} \text{solve}(\text{rem} - c)$$
Cache computed subproblems in `memo[rem]`.

### C++ Implementation
```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        vector<int> memo(amount + 1, -2);
        return solve(amount, coins, memo);
    }

private:
    int solve(int rem, const vector<int>& coins, vector<int>& memo) {
        if (rem == 0) return 0;
        if (rem < 0) return -1;
        if (memo[rem] != -2) return memo[rem];
        
        int minCoins = INT_MAX;
        for (int c : coins) {
            int res = solve(rem - c, coins, memo);
            if (res >= 0 && res < minCoins) {
                minCoins = res + 1;
            }
        }
        
        memo[rem] = (minCoins == INT_MAX) ? -1 : minCoins;
        return memo[rem];
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(A \cdot C)$ | Computes each amount state $A$ once with $C$ transitions. |
| **Space** | $O(A)$ | Memoization array and recursion call stack depth $A$. |

## Approach 2 — Bottom-Up 1D Unbounded Knapsack DP ✅

### Key Insight
Let `dp[i]` be the minimum coins needed to make amount `i`:
- Base case: `dp[0] = 0`.
- Initialize `dp[1...amount]` with sentinel `amount + 1` (acting as infinity, since the maximum coins to make `amount` is at most `amount` 1¢ coins).
- For each target value $i \in [1 \dots \text{amount}]$:
  - For each `coin` in `coins`:
    $$\text{if } i \ge \text{coin}: \quad \text{dp}[i] = \min(\text{dp}[i], 1 + \text{dp}[i - \text{coin}])$$
- If `dp[amount] > amount`, target is unreachable $\rightarrow$ return `-1`. Otherwise return `dp[amount]`.

```
coins = [1, 2, 5], amount = 11
dp = [0, 12, 12, 12, 12, 12, 12, 12, 12, 12, 12, 12]

i=1: min(12, 1 + dp[0]) = 1
i=2: min(12, 1 + dp[1]=2, 1 + dp[0]=1) = 1
i=5: min(12, 1 + dp[0]=1) = 1
...
i=11: 1 + dp[6] (with coin 5) = 1 + 2 = 3

Result: dp[11] = 3 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        // Initialize with amount + 1 (safe infinity representation)
        vector<int> dp(amount + 1, amount + 1);
        dp[0] = 0;
        
        for (int i = 1; i <= amount; i++) {
            for (int coin : coins) {
                if (i >= coin) {
                    dp[i] = min(dp[i], 1 + dp[i - coin]);
                }
            }
        }
        
        return dp[amount] > amount ? -1 : dp[amount];
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\text{amount} \cdot \text{coins.size()})$ | Outer loop runs `amount` times, inner loop checks each denomination. |
| **Space** | $O(\text{amount})$ | 1D DP table of size $\text{amount} + 1$. |

> **This is the one.** Clean, robust Unbounded Knapsack tabulation.

## Approach 3 — Breadth-First Search (Shortest Path in State Space)

### Intuition
Model making change as finding the shortest path from node `0` to node `amount` in an unweighted graph where each coin is a directed edge of weight 1. The first time BFS reaches `amount`, that level is the minimal coin count!

### C++ Implementation
```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        if (amount == 0) return 0;
        
        queue<int> q;
        vector<bool> visited(amount + 1, false);
        
        q.push(0);
        visited[0] = true;
        int level = 0;
        
        while (!q.empty()) {
            int sz = q.size();
            level++;
            
            for (int i = 0; i < sz; i++) {
                int curr = q.front();
                q.pop();
                
                for (int coin : coins) {
                    long long nextVal = static_cast<long long>(curr) + coin;
                    if (nextVal == amount) return level;
                    if (nextVal < amount && !visited[nextVal]) {
                        visited[nextVal] = true;
                        q.push(static_cast<int>(nextVal));
                    }
                }
            }
        }
        
        return -1;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(A \cdot C)$ | Explores each amount at most once. |
| **Space** | $O(A)$ | Visited array and queue. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **`amount = 0`** | `amount = 0` | Loop bounds | Returns 0 immediately (`dp[0] = 0`). |
| **Target Unreachable** | `coins = [2], amount = 3` | Returning infinity | `dp[3] == 4 > 3` evaluates true $\rightarrow$ returns `-1`. |
| **Denomination Larger than Amount** | `coins = [10], amount = 5` | Underflow | Guard `i >= coin` prevents accessing negative array indices. |

---

## Pattern Takeaways

1. **Unbounded Knapsack Iteration Order:**  
   Iterating forward from $1$ to $\text{amount}$ naturally allows multiple selections of the same coin denomination.
2. **Sentinel Infinity:**  
   Using `amount + 1` instead of `INT_MAX` avoids integer overflow when computing `1 + dp[i - coin]`.
