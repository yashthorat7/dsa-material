# 1584. Min Cost to Connect All Points

https://leetcode.com/problems/min-cost-to-connect-all-points

> **Medium** $\rightarrow$ **Graph Traversal**


> **Companies:** Amazon, Google, Uber, Meta

## What are we solving?

You are given an array `points` representing integer coordinates of some points on a 2D-plane, where `points[i] = [xi, yi]`.

The cost of connecting two points `[xi, yi]` and `[xj, yj]` is the **manhattan distance** between them: `|xi - xj| + |yi - yj|`.

Return the **minimum cost** to make all points connected. All points are connected if there is exactly one simple path between any two points (Minimum Spanning Tree).

**Example 1:**
```
Input:  points = [[0,0],[2,2],[3,10],[5,2],[7,0]]
Output: 20
Explanation: Connect (0,0)-(2,2) cost 4, (2,2)-(5,2) cost 3, (5,2)-(7,0) cost 4, (2,2)-(3,10) cost 9. Total cost = 4 + 3 + 4 + 9 = 20.
```

**Example 2:**
```
Input:  points = [[3,12],[-2,5],[-4,1]]
Output: 18
```

**Constraints:**
- $1 \le \text{points.length} \le 1000$
- $-10^6 \le x_i, y_i \le 10^6$
- All pairs $(x_i, y_i)$ are distinct.

## Approach 1 — Prim's Algorithm (Dense MST) ✅

**Key insight:**
This is finding the Minimum Spanning Tree (MST) on a complete graph with $n$ vertices.
Use **Prim's Algorithm**:
1. Maintain `minDist[n]` initialized to $\infty$, with `minDist[0] = 0`, and `inMST[n]` initialized to `false`.
2. For $n$ iterations:
   - Pick the unvisited node `u` with the smallest `minDist[u]`.
   - Mark `inMST[u] = true`, add `minDist[u]` to `totalCost`.
   - Update `minDist[v] = min(minDist[v], manhattanDistance(u, v))` for all unvisited `v`.
Total complexity $O(n^2)$ is optimal for dense complete graphs without building $O(n^2)$ explicit edge lists!

```
points = [[0,0],[2,2],[3,10],[5,2],[7,0]] (n=5)
Start at 0:
- Add 0: cost=0, update dists: [-, 4, 13, 7, 7]
- Pick 1 (cost 4): update dists: [-, -, 9, 3, 7]
- Pick 3 (cost 3): update dists: [-, -, 10, -, 4]
- Pick 4 (cost 4): update dists: [-, -, 14, -, -]
- Pick 2 (cost 9): done.

Total MST cost = 4 + 3 + 4 + 9 = 20 ✓
```

```cpp
class Solution {
public:
    int minCostConnectPoints(vector<vector<int>>& points) {
        int n = points.size();
        vector<int> minDist(n, INT_MAX);
        vector<bool> inMST(n, false);
        minDist[0] = 0;
        int totalCost = 0;
        
        for (int step = 0; step < n; step++) {
            int u = -1;
            for (int i = 0; i < n; i++) {
                if (!inMST[i] && (u == -1 || minDist[i] < minDist[u])) {
                    u = i;
                }
            }
            
            inMST[u] = true;
            totalCost += minDist[u];
            
            for (int v = 0; v < n; v++) {
                if (!inMST[v]) {
                    int dist = abs(points[u][0] - points[v][0]) + abs(points[u][1] - points[v][1]);
                    minDist[v] = min(minDist[v], dist);
                }
            }
        }
        
        return totalCost;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n^2)$ | $O(n)$ |

> **This is the one.** $O(n^2)$ Prim's algorithm avoids $O(n^2 \log n)$ priority queue overhead on complete graphs.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Single point `[[0, 0]]` | 0 cost edges | Loop runs 1 step, cost 0 |
| Collinear points `[[0,0],[1,0],[2,0]]` | Distances sum | Selects adjacent segments, cost 2 |

---

## Pattern Takeaway

For **dense complete graphs ($E \approx V^2$)**, **$O(V^2)$ Prim's algorithm with an array** beats $O(E \log V)$ Kruskal's algorithm by eliminating heap overhead.
