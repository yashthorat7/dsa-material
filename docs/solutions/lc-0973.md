> **Companies:** Meta, Amazon, Microsoft, Asana, Google, LinkedIn, Flipkart, Ola, Accenture

## What are we solving?

Given an array of `points` where `points[i] = [x, y]` represents a point on the **X-Y** plane and an integer `k`, return the `k` **closest points to the origin `(0, 0)`**.

The distance between two points $(x_1, y_1)$ and $(x_2, y_2)$ is the Euclidean distance $\sqrt{(x_1 - x_2)^2 + (y_1 - y_2)^2}$.
- You may return the answer in **any order**.
- The answer is guaranteed to be **unique** (except for the order that it is in).

```
 Points: [ [1, 3], [-2, 2] ],  k = 1
 
 Distances to (0, 0):
 - Point [1, 3]:   1^2 + 3^2 = 1 + 9 = 10 (sqrt(10) ~ 3.16)
 - Point [-2, 2]:  (-2)^2 + 2^2 = 4 + 4 = 8 (sqrt(8) ~ 2.83)
 
 Closest Point: [-2, 2]
 Output: [ [-2, 2] ]
```

### Input & Output Contract
- **Input:**
  - `points`: `vector<vector<int>>` ($1 \le k \le n \le 10^4$, $-10^4 \le x_i, y_i \le 10^4$).
  - `k`: `int` number of closest points to extract.
- **Output:**
  - `vector<vector<int>>`: $k$ closest points in any order.

### Distance Optimization Trick
Because the square root function $f(d) = \sqrt{d}$ is strictly monotonically increasing for $d \ge 0$:
$$\sqrt{x_1^2 + y_1^2} < \sqrt{x_2^2 + y_2^2} \iff \mathbf{x_1^2 + y_1^2 < x_2^2 + y_2^2}$$
We can compare **squared Euclidean distances** directly using pure integer arithmetic, completely avoiding slow floating-point square root operations and precision issues!

---

**Example 1:**
```
Input:  points = [[1,3],[-2,2]], k = 1
Output: [[-2,2]]
Explanation: The distance between (1, 3) and the origin is sqrt(10).
The distance between (-2, 2) and the origin is sqrt(8).
Since sqrt(8) < sqrt(10), (-2, 2) is closer to the origin.
```

**Example 2:**
```
Input:  points = [[3,3],[5,-1],[-2,4]], k = 2
Output: [[3,3],[-2,4]]
```

**Constraints:**
- $1 \le k \le \text{points.length} \le 10^4$
- $-10^4 \le x_i, y_i \le 10^4$

## Approach 1 — Sorting by Squared Distance ($O(n \log n)$)

### Intuition
Sort the entire array of points in ascending order of their squared Euclidean distance $x^2 + y^2$. Return the first $k$ points.

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
        sort(points.begin(), points.end(), [](const vector<int>& a, const vector<int>& b) {
            return (a[0] * a[0] + a[1] * a[1]) < (b[0] * b[0] + b[1] * b[1]);
        });
        
        return vector<vector<int>>(points.begin(), points.begin() + k);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n \log n)$ | Full sorting pass over $n$ elements. |
| **Space** | $O(1)$ auxiliary | In-place sorting. |

## Approach 2 — Max-Heap of Fixed Capacity $K$ ($O(n \log k)$) ✅

### Key Insight
To find the **$k$ smallest elements in a stream**, maintain a **Max-Heap of size $k$**:
1. For each point $i$:
   - Calculate $d^2 = x^2 + y^2$.
   - Push `{d^2, i}` into the `priority_queue`.
   - If `maxHeap.size() > k`: **pop the top element** (which has the largest distance among the $k + 1$ candidates).
2. After processing all $n$ points, the heap holds exactly the $k$ closest points!

```
points = [[1, 3], [-2, 2]], k = 1
maxHeap = []

Point 0 [1, 3]:  d^2 = 1+9 = 10 -> push {10, 0} -> heap: [ {10, 0} ]
Point 1 [-2, 2]: d^2 = 4+4 = 8  -> push {8, 1}  -> heap: [ {10, 0}, {8, 1} ]
Heap size > 1 -> pop max ({10, 0}) -> heap: [ {8, 1} ]

Result: [ [-2, 2] ] ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
        // Max-heap storing pairs: {squared_distance, point_index}
        priority_queue<pair<int, int>> maxHeap;
        
        for (int i = 0; i < points.size(); i++) {
            int distSq = points[i][0] * points[i][0] + points[i][1] * points[i][1];
            maxHeap.push({distSq, i});
            
            if (maxHeap.size() > k) {
                maxHeap.pop(); // Discard the point farthest from origin
            }
        }
        
        vector<vector<int>> result;
        result.reserve(k);
        while (!maxHeap.empty()) {
            result.push_back(points[maxHeap.top().second]);
            maxHeap.pop();
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n \log k)$ | Each of the $n$ points takes $O(\log k)$ heap insertion/eviction. Ideal when $k \ll n$. |
| **Space** | $O(k)$ | Max-heap stores at most $k + 1$ entries. |

> **This is the one.** Optimal bounded heap for streaming datasets.

## Approach 3 — Quickselect (`nth_element`) ($O(n)$ Average Time)

### Intuition
C++'s `nth_element` implements Quickselect in $O(n)$ expected linear time, partitioning the $k$ closest elements into the first $k$ positions without fully sorting them.

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
        auto cmp = [](const vector<int>& a, const vector<int>& b) {
            return (a[0] * a[0] + a[1] * a[1]) < (b[0] * b[0] + b[1] * b[1]);
        };
        
        // Partitions the array so that the first k elements are the smallest k elements
        nth_element(points.begin(), points.begin() + k - 1, points.end(), cmp);
        
        return vector<vector<int>>(points.begin(), points.begin() + k);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ average | Quickselect linear time partition. |
| **Space** | $O(1)$ auxiliary | In-place partition. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **`k == points.length`** | `points = [[1, 2]], k = 1` | Unnecessary heap evictions | Heap retains all $k$ items, returns whole array. |
| **Equidistant Points** | `[1, 1], [-1, -1]` with $k = 1$ | Distance ties | Any equidistant point is valid per problem description. |
