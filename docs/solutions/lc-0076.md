# 76. Minimum Window Substring

https://leetcode.com/problems/minimum-window-substring

> **Hard** $\rightarrow$ **Sliding Window**


> **Companies:** Meta, Amazon, LinkedIn, Lyft, Microsoft, Airbnb, Flipkart, Swiggy, Wipro

## What are we solving?

Given two strings `s` and `t` of lengths `m` and `n` respectively, return the **minimum window substring** of `s` such that every character in `t` (including duplicates) is included in the window. If there is no such substring, return the empty string `""`.

The testcases will be generated such that the answer is **unique**.

The fundamental challenge is: **how can we track required character frequency fulfillment in $O(1)$ per step while minimizing the substring length?**

**Example 1:**
```
Input:  s = "ADOBECODEBANC", t = "ABC"
Output: "BANC"
Explanation: The minimum window substring "BANC" includes 'A', 'B', and 'C' from string t.
```

**Example 2:**
```
Input:  s = "a", t = "a"
Output: "a"
```

**Example 3:**
```
Input:  s = "a", t = "aa"
Output: ""
Explanation: Both 'a's from t must be included in the window. Since the largest window of s only has one 'a', return empty string.
```

**Constraints:**
- $m == s.\text{length}$
- $n == t.\text{length}$
- $1 \le m, n \le 10^5$
- `s` and `t` consist of uppercase and lowercase English letters.

## Approach 1 — Sliding Window with Character Deficit Counter ✅

**Key insight:**
1. Populate frequency map `targetFreq[128]` for `t`, and set `requiredChars = t.length()`.
2. Expand `right`:
   - If `targetFreq[s[right]] > 0`, it satisfies a needed character $\rightarrow$ `requiredChars--`.
   - Decrement `targetFreq[s[right]]` (values can go negative for excess characters).
3. When `requiredChars == 0` (window contains all characters of `t`):
   - Record window if smaller than current `minLen`.
   - Shrink `left`: increment `targetFreq[s[left]]`. If `targetFreq[s[left]] > 0`, we just lost a required character $\rightarrow$ `requiredChars++`.
   - Advance `left++`.

```
s = "ADOBECODEBANC", t = "ABC"
targetFreq = {A:1, B:1, C:1}, required = 3

right expands until right=5 ('C'): window="ADOBEC", required=0
  -> valid window "ADOBEC" (len=6). Shrink left: 'A' removed -> required=1, left=1
right continues until right=10 ('A'): window="CODEBA", required=0
  -> shrink left: 'C' removed at left=6 -> "ODEBA"
right reaches end right=12 ('C'): window="BANC", required=0 (len=4)
  -> min window recorded: "BANC"

Result: "BANC" ✓
```

```cpp
class Solution {
public:
    string minWindow(string s, string t) {
        if (s.empty() || t.empty() || s.size() < t.size()) return "";
        
        vector<int> targetFreq(128, 0);
        for (char c : t) targetFreq[c]++;
        
        int left = 0, minLeft = 0, minLen = INT_MAX;
        int required = t.size();
        
        for (int right = 0; right < s.size(); right++) {
            if (targetFreq[s[right]] > 0) {
                required--;
            }
            targetFreq[s[right]]--;
            
            while (required == 0) {
                if (right - left + 1 < minLen) {
                    minLen = right - left + 1;
                    minLeft = left;
                }
                
                targetFreq[s[left]]++;
                if (targetFreq[s[left]] > 0) {
                    required++;
                }
                left++;
            }
        }
        
        return minLen == INT_MAX ? "" : s.substr(minLeft, minLen);
    }
};
```

| Time | Space |
|:-----|:------|
| $O(m + n)$ | $O(1)$ (fixed 128-element array) |

> **This is the one.** Hard problem solved in optimal linear time and constant auxiliary memory.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| `s.length() < t.length()` | Impossible to contain `t` | Returns `""` immediately |
| No matching substring | `minLen` stays `INT_MAX` | Returns `""` |
| Duplicate characters in `t` (`t = "aa"`) | Counting duplicate satisfaction once | `targetFreq` counts exact multiplicity and `required` counts total characters |

---

## Pattern Takeaway

The **Sliding Window Deficit Counter** pattern manages complex multi-character constraints in $O(1)$ step updates without scanning dictionary keys.
