## What are we solving?

You are given an array of non-overlapping intervals `intervals` where `intervals[i] = [starti, endi]` represent the start and the end of the $i$-th interval and `intervals` is sorted in ascending order by `starti`. You are also given an interval `newInterval = [start, end]` that represents the start and end of another interval.

Insert `newInterval` into `intervals` such that `intervals` is still sorted in ascending order by `starti` and `intervals` still does not have any overlapping intervals (merge overlapping intervals if necessary). Return `intervals` after the insertion.

**Example 1:**
```
Input:  intervals = [[1,3],[6,9]], newInterval = [2,5]
Output: [[1,5],[6,9]]
```

**Example 2:**
```
Input:  intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]], newInterval = [4,8]
Output: [[1,2],[3,10],[12,16]]
Explanation: Because the new interval [4,8] overlaps with [3,5],[6,7],[8,10].
```

**Constraints:**
- $0 \le \text{intervals.length} \le 10^4$
- $\text{intervals}[i].\text{length} == 2$
- $0 \le \text{start}_i \le \text{end}_i \le 10^5$
- `intervals` is sorted by $\text{start}_i$ in ascending order.
- $\text{newInterval}.\text{length} == 2$
- $0 \le \text{start} \le \text{end} \le 10^5$

## Approach 1 — 3-Phase Linear Merge ✅

**Key insight:**
Process intervals in 3 sequential phases:
1. **Left (Before):** Add all intervals that end before `newInterval` starts (`intervals[i][1] < newInterval[0]`).
2. **Overlap (Merge):** While intervals start before `newInterval` ends (`intervals[i][0] <= newInterval[1]`):
   - Merge: `newInterval[0] = min(newInterval[0], intervals[i][0])`
   - Merge: `newInterval[1] = max(newInterval[1], intervals[i][1])`
   - Advance `i`.
   - Push merged `newInterval`.
3. **Right (After):** Add all remaining intervals after `newInterval`.

```
intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]], newInterval = [4,8]

Phase 1 (before 4):
[1,2] ends at 2 < 4 -> add [1,2]

Phase 2 (overlaps with [4,8]):
[3,5]: 3 <= 8 -> merge -> newInterval = [min(4,3), max(8,5)] = [3,8]
[6,7]: 6 <= 8 -> merge -> newInterval = [min(3,6), max(8,7)] = [3,8]
[8,10]: 8 <= 8 -> merge -> newInterval = [min(3,8), max(8,10)] = [3,10]
Add merged [3,10]

Phase 3 (after):
[12,16] -> add [12,16]

Result: [[1,2], [3,10], [12,16]] ✓
```

```cpp
class Solution {
public:
    vector<vector<int>> insert(vector<vector<int>>& intervals, vector<int>& newInterval) {
        vector<vector<int>> result;
        int i = 0, n = intervals.size();
        
        // 1. Add intervals ending before newInterval starts
        while (i < n && intervals[i][1] < newInterval[0]) {
            result.push_back(intervals[i]);
            i++;
        }
        
        // 2. Merge overlapping intervals
        while (i < n && intervals[i][0] <= newInterval[1]) {
            newInterval[0] = min(newInterval[0], intervals[i][0]);
            newInterval[1] = max(newInterval[1], intervals[i][1]);
            i++;
        }
        result.push_back(newInterval);
        
        // 3. Add remaining intervals
        while (i < n) {
            result.push_back(intervals[i]);
            i++;
        }
        
        return result;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(1)$ (output vector excluded) |

> **This is the one.** Single linear pass with clean 3-phase partition.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Empty list `intervals = [], newInterval = [5, 7]` | Loop termination | Phase 2 pushes `newInterval`, returns `[[5, 7]]` |
| New interval inserted at very beginning | Phase 1 empty | Phase 2 merges or inserts at front immediately |
| New interval encompasses all existing intervals | Multiple merges | Phase 2 absorbs all intervals into one range |

---

## Pattern Takeaway

Sorted interval insertion decomposes into **3 linear phases: Before ($O(n)$) $\rightarrow$ Overlapping Merge ($O(n)$) $\rightarrow$ After ($O(n)$)**.
