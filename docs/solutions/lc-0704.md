## What are we solving?

Given an array of integers `nums` which is sorted in **ascending order**, and an integer `target`, write a function to search for `target` in `nums`.

If `target` exists, return its **index**. Otherwise, return `-1`.

You must write an algorithm with **$O(\log n)$ runtime complexity**.

```
 nums = [ -1,  0,  3,  5,  9, 12 ],  target = 9
           0   1   2   3   4   5
          low     mid         high   (mid = 2, val = 3 < 9 -> low = mid + 1)
                      low mid high   (mid = 4, val = 9 == 9 -> FOUND at index 4!)
```

### Input & Output Contract
- **Input:**
  - `nums`: `vector<int>` with length $1 \le n \le 10^4$, $-10^4 < \text{nums}[i], \text{target} < 10^4$.
  - `nums` contains strictly unique elements sorted in ascending order.
  - `target`: `int` key to find.
- **Output:**
  - `int` representing the 0-based index of `target`, or `-1` if absent.

### The Core Challenge
A naive sequential scan takes $O(n)$ time. Because the array is strictly monotonic (sorted), comparing the middle element allows us to eliminate half of the remaining search space in $O(1)$ time, yielding $O(\log n)$ total steps.

---

**Example 1:**
```
Input:  nums = [-1,0,3,5,9,12], target = 9
Output: 4
Explanation: 9 exists in nums and its index is 4.
```

**Example 2:**
```
Input:  nums = [-1,0,3,5,9,12], target = 2
Output: -1
Explanation: 2 does not exist in nums so return -1.
```

**Constraints:**
- $1 \le \text{nums.length} \le 10^4$
- $-10^4 < \text{nums}[i], \text{target} < 10^4$
- All the integers in `nums` are unique.
- `nums` is sorted in ascending order.

## Approach 1 — Linear Search (Brute Force)

### Intuition
Scan each element sequentially from left to right until the target is found or the end of the array is reached.

### C++ Implementation
```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        for (int i = 0; i < nums.size(); i++) {
            if (nums[i] == target) return i;
        }
        return -1;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | In the worst case, checks every element once. |
| **Space** | $O(1)$ | No additional memory used. |

> **Verdict:** Correct, but does not meet the mandatory $O(\log n)$ runtime constraint.

## Approach 2 — Iterative Binary Search (Overflow-Safe Midpoint) ✅

### Key Insight
1. Maintain two search boundaries: `low = 0` and `high = n - 1`.
2. While `low <= high`:
   - Compute midpoint: `mid = low + (high - low) / 2` (avoids integer overflow from `(low + high) / 2`).
   - If `nums[mid] == target`: return `mid`.
   - If `nums[mid] < target`: target must reside in the right half $\rightarrow$ `low = mid + 1`.
   - If `nums[mid] > target`: target must reside in the left half $\rightarrow$ `high = mid - 1`.
3. If loop ends with `low > high`, target is not present $\rightarrow$ return `-1`.

```
nums = [-1, 0, 3, 5, 9, 12], target = 9
low = 0, high = 5

Iteration 1:
- mid = 0 + (5 - 0) / 2 = 2 (nums[2] = 3)
- 3 < 9 -> discard left half -> low = mid + 1 = 3

Iteration 2:
- low = 3, high = 5
- mid = 3 + (5 - 3) / 2 = 4 (nums[4] = 9)
- 9 == 9 -> MATCH!

Return index 4 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int low = 0;
        int high = nums.size() - 1;
        
        while (low <= high) {
            // Prevents potential integer overflow
            int mid = low + (high - low) / 2;
            
            if (nums[mid] == target) {
                return mid;
            } else if (nums[mid] < target) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        
        return -1;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\log n)$ | Halves the active search space in each iteration ($k = \log_2 n$ steps). |
| **Space** | $O(1)$ | Pure stack index variables. |

> **This is the one.** Clean, optimal, integer-safe, and zero extra allocations.

## Approach 3 — Recursive Binary Search (Divide & Conquer)

### Intuition
Formulate the search as a recursive function `searchHelper(nums, target, low, high)`.

### C++ Implementation
```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        return helper(nums, target, 0, nums.size() - 1);
    }

private:
    int helper(const vector<int>& nums, int target, int low, int high) {
        if (low > high) return -1;
        
        int mid = low + (high - low) / 2;
        if (nums[mid] == target) return mid;
        
        if (nums[mid] < target) {
            return helper(nums, target, mid + 1, high);
        } else {
            return helper(nums, target, low, mid - 1);
        }
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\log n)$ | $\log_2 n$ recursive calls. |
| **Space** | $O(\log n)$ | Call stack depth is bounded by $\log_2 n$. |

## Approach 4 — C++ STL `lower_bound`

### Intuition
In production C++, `lower_bound` performs binary search on sorted iterators in $O(\log n)$ time.

### C++ Implementation
```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        auto it = lower_bound(nums.begin(), nums.end(), target);
        if (it != nums.end() && *it == target) {
            return distance(nums.begin(), it);
        }
        return -1;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\log n)$ | Standard library binary search implementation. |
| **Space** | $O(1)$ | No memory allocated. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Single Element Match** | `nums = [5], target = 5` | Loop bounds | `low = 0, high = 0 (low <= high is true)`, `mid = 0`, returns 0. |
| **Single Element Miss** | `nums = [5], target = 2` | Infinite loop | `mid = 0 (5 > 2) -> high = -1`, loop exits, returns -1. |
| **Target Smaller than Minimum** | `nums = [1, 2, 3], target = 0` | Negative index | `high` becomes `-1`, terminates cleanly. |
| **Target Larger than Maximum** | `nums = [1, 2, 3], target = 10` | Out of bounds access | `low` becomes `n`, terminates cleanly. |

## Pattern Takeaways

1. **The Midpoint Overflow Safeguard:**  
   Always write `mid = low + (high - low) / 2` instead of `(low + high) / 2` to prevent 32-bit signed integer overflow when `low + high > 2^{31} - 1`.
2. **The 3 Canonical Binary Search Templates:**  
   - Exact match: `while (low <= high)` with `low = mid + 1` / `high = mid - 1`.
   - First true / lower bound: `while (low < high)` with `high = mid`.
   - Floating / monotonic predicate: binary search on answer space (e.g. [LC 875: Koko Eating Bananas](file:///e:/Projects/dsa-notes/docs/solutions/lc-0875.md)).
