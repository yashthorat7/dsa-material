## What are we solving?

Implement a last-in-first-out (LIFO) stack using only two queues. The implemented stack should support all the functions of a normal stack (`push`, `top`, `pop`, and `empty`).

The question is: **how can a single FIFO queue rotate its existing elements to achieve $O(1)$ LIFO top access on push?**

**Example 1:**
```
Input:  ["MyStack", "push", "push", "top", "pop", "empty"]
[[], [1], [2], [], [], []]
Output: [null, null, null, 2, 2, false]
Explanation: MyStack myStack = new MyStack();
myStack.push(1);
myStack.push(2);
myStack.top(); // return 2
myStack.pop(); // return 2
myStack.empty(); // return False
```

**Constraints:**
- $1 \le \text{x} \le 9$
- At most $100$ calls will be made to `push`, `pop`, `top`, and `empty`.
- All the calls to `pop` and `top` are valid.

## Approach 1 — Single Queue with Push Rotation ✅

**Key insight:**
We can use just **one queue `q`**.
When pushing `x`:
1. Get current size `sz = q.size()`.
2. Push `x` to back of queue.
3. Pop from front and push to back `sz` times!
This rotates the new element `x` to the front of the queue, making `q.front()` act as `top()` in $O(1)$!

```
push(1): q = [1]
push(2): push 2 -> [1, 2], rotate 1 time -> [2, 1]
push(3): push 3 -> [2, 1, 3], rotate 2 times:
         rotate 2 -> [1, 3, 2]
         rotate 1 -> [3, 2, 1]
top():   q.front() = 3
pop():   q.pop() = 3 -> q = [2, 1] ✓
```

```cpp
class MyStack {
private:
    queue<int> q;
public:
    MyStack() {}
    
    void push(int x) {
        int sz = q.size();
        q.push(x);
        for (int i = 0; i < sz; i++) {
            q.push(q.front());
            q.pop();
        }
    }
    
    int pop() {
        int val = q.front();
        q.pop();
        return val;
    }
    
    int top() {
        return q.front();
    }
    
    bool empty() {
        return q.empty();
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ for `push`, $O(1)$ for `pop`, `top`, `empty` | $O(n)$ in a single queue |

> **This is the one.** Elegant single-queue implementation.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Single element push & pop | Rotation on empty queue | `sz = 0` loop does not execute, element stays at front |
| Multiple sequential pops | Queue state corruption | Elements are always positioned in reverse order |

---

## Pattern Takeaway

**Queue Rotation (`push(front); pop();`)** can maintain reverse order inside a single queue so that `top()` is always at the front.
