# 721. Accounts Merge

https://leetcode.com/problems/accounts-merge

> **Medium** $\rightarrow$ **Graph Traversal**


> **Companies:** Meta, Apple, Google, Twitter, Amazon, LinkedIn, Ola, Swiggy, Accenture

---

## What are we solving?

Given a list of `accounts` where each element `accounts[i]` is a list of strings:
- `accounts[i][0]` is a **name**.
- `accounts[i][1 ... k]` are **email addresses** associated with that account.

Two accounts definitely belong to the same person if there is **some common email** to both accounts. Note that two people can have the same name, but they are different people if they share no emails.

After merging the accounts, return the merged accounts where:
- The first element is the account name.
- The rest of the elements are the distinct emails in **lexicographically sorted order**.

```
 Accounts:
 [ ["John", "johnsmith@mail.com", "john_newyork@mail.com"],
   ["John", "johnsmith@mail.com", "john00@mail.com"],
   ["Mary", "mary@mail.com"],
   ["John", "johnnybravo@mail.com"] ]
   
 Merged:
 [ ["John", "john00@mail.com", "john_newyork@mail.com", "johnsmith@mail.com"],
   ["Mary", "mary@mail.com"],
   ["John", "johnnybravo@mail.com"] ]
```

### Input & Output Contract
- **Input:**
  - `accounts`: `vector<vector<string>>` ($1 \le n \le 1000$, $2 \le \text{len} \le 10$).
- **Output:**
  - `vector<vector<string>>`: Merged accounts with sorted unique emails.

---

**Example 1:**
```
Input:  accounts = [["John","johnsmith@mail.com","john_newyork@mail.com"],["John","johnsmith@mail.com","john00@mail.com"],["Mary","mary@mail.com"],["John","johnnybravo@mail.com"]]
Output: [["John","john00@mail.com","john_newyork@mail.com","johnsmith@mail.com"],["Mary","mary@mail.com"],["John","johnnybravo@mail.com"]]
```

**Constraints:**
- $1 \le \text{accounts.length} \le 1000$
- $2 \le \text{accounts}[i].\text{length} \le 10$
- $1 \le \text{accounts}[i][j].\text{length} \le 30$
- `accounts[i][0]` consists of English letters.
- `accounts[i][j]` (for $j > 0$) are valid emails.

## Approach 1 — Graph Construction + DFS Component Traversal

### Intuition
Treat each email as a node in an undirected graph. Build adjacency list between the first email of an account and all other emails in that account. Run DFS on unvisited emails to gather connected components.

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<string>> accountsMerge(vector<vector<string>>& accounts) {
        unordered_map<string, vector<string>> adj;
        unordered_map<string, string> emailToName;
        
        for (const auto& acc : accounts) {
            const string& name = acc[0];
            const string& firstEmail = acc[1];
            for (int i = 1; i < acc.size(); i++) {
                adj[firstEmail].push_back(acc[i]);
                adj[acc[i]].push_back(firstEmail);
                emailToName[acc[i]] = name;
            }
        }
        
        unordered_set<string> visited;
        vector<vector<string>> result;
        
        auto dfs = [&](auto& self, const string& email, vector<string>& component) -> void {
            visited.insert(email);
            component.push_back(email);
            for (const string& next : adj[email]) {
                if (!visited.count(next)) {
                    self(self, next, component);
                }
            }
        };
        
        for (const auto& [email, name] : emailToName) {
            if (!visited.count(email)) {
                vector<string> component;
                dfs(dfs, email, component);
                sort(component.begin(), component.end());
                component.insert(component.begin(), name);
                result.push_back(component);
            }
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(N \log N)$ | Graph traversal and sorting of components ($N = \text{total emails}$). |
| **Space** | $O(N)$ | Adjacency list and visited hash set. |

## Approach 2 — Disjoint Set Union (DSU on Account Indices) ✅

### Key Insight
1. Maintain a DSU parent array for account indices $0 \dots n - 1$.
2. Maintain a hash map `emailToAccId` mapping each unique email string to the first account ID that introduced it.
3. For each account $i$:
   - For each email $e$ in `accounts[i]`:
     - If $e$ was previously seen in account `emailToAccId[e]`:
       - Merge account $i$ with `emailToAccId[e]` via `dsu.unite(i, emailToAccId[e])`.
     - Else: record `emailToAccId[e] = i`.
4. Group all unique emails by their representative account root:
   - `mergedEmails[dsu.find(accId)].push_back(email)`.
5. For each component: sort emails and format output `[Name, email1, email2, ...]`.

```
Account 0: [John, e1, e2] -> emailToAcc: {e1:0, e2:0}
Account 1: [John, e1, e3] -> e1 seen at 0 -> dsu.unite(1, 0), emailToAcc: {e3:1}
Account 2: [Mary, e4]     -> emailToAcc: {e4:2}
Account 3: [John, e5]     -> emailToAcc: {e5:3}

DSU Roots:
Root 0: [e1, e2, e3] -> [John, e1, e2, e3]
Root 2: [e4]         -> [Mary, e4]
Root 3: [e5]         -> [John, e5] ✓
```

### C++ Implementation
```cpp
class Solution {
    struct DSU {
        vector<int> parent;
        DSU(int n) : parent(n) {
            iota(parent.begin(), parent.end(), 0);
        }
        int find(int i) {
            if (parent[i] == i) return i;
            return parent[i] = find(parent[i]);
        }
        void unite(int i, int j) {
            int rootI = find(i);
            int rootJ = find(j);
            if (rootI != rootJ) {
                parent[rootI] = rootJ;
            }
        }
    };

public:
    vector<vector<string>> accountsMerge(vector<vector<string>>& accounts) {
        int n = accounts.size();
        DSU dsu(n);
        unordered_map<string, int> emailToAcc;
        
        // 1. Unify accounts that share emails
        for (int i = 0; i < n; i++) {
            for (int j = 1; j < accounts[i].size(); j++) {
                const string& email = accounts[i][j];
                auto it = emailToAcc.find(email);
                if (it != emailToAcc.end()) {
                    dsu.unite(i, it->second);
                } else {
                    emailToAcc[email] = i;
                }
            }
        }
        
        // 2. Group emails by DSU root component
        unordered_map<int, vector<string>> merged;
        for (const auto& [email, accIdx] : emailToAcc) {
            int root = dsu.find(accIdx);
            merged[root].push_back(email);
        }
        
        // 3. Format result with owner name and sorted emails
        vector<vector<string>> result;
        for (auto& [root, emails] : merged) {
            sort(emails.begin(), emails.end());
            vector<string> acc = {accounts[root][0]};
            acc.insert(acc.end(), emails.begin(), emails.end());
            result.push_back(move(acc));
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(N \cdot \alpha(K) + N \log N)$ | Where $N$ is total emails across all accounts; sorting dominating step. |
| **Space** | $O(N)$ | Hash maps storing emails and DSU parent vector. |

> **This is the one.** Clean, robust DSU indexed directly on accounts.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Same Name, Disjoint People** | Two different "John"s with no shared emails | Accidental merging by name | Only unions accounts if an identical email string matches. |
| **Chained Transitive Merges** | Account A shares with B, B shares with C | Partial components | Path compression links A, B, and C into a single root. |
