## What are we solving?

You are given an integer array `height` of length `n`. There are `n` vertical lines drawn such that the two endpoints of the $i$-th line are `(i, 0)` and `(i, height[i])`. Find two lines that together with the x-axis form a container, such that the container contains the most water. Return the **maximum amount of water** a container can store.

The question is: **how can we greedily shrink the window from the ends while proving no optimal solution is missed?**

**Example 1:**
```
Input:  height = [1,8,6,2,5,4,8,3,7]
Output: 49
Explanation: The vertical lines are represented by array [1,8,6,2,5,4,8,3,7]. In this case, the max area of water the container can contain is 49 (between index 1 and index 8).
```

**Example 2:**
```
Input:  height = [1,1]
Output: 1
```

**Constraints:**
- $n == \text{height.length}$
- $2 \le n \le 10^5$
- $0 \le \text{height}[i] \le 10^4$

## Approach 1 — Two Pointers Shrinking Inward ✅

**Key insight:**
Area is determined by: `Area = min(height[left], height[right]) * (right - left)`.
- Start with maximum width (`left = 0`, `right = n - 1`).
- The height is bottlenecked by the **shorter line**.
- Moving the taller line inward only decreases the width while the bottleneck height cannot increase!
- Therefore, we MUST move the pointer at the **shorter line** inward to have any hope of finding a larger area.

```
height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
left = 0 (1), right = 8 (7) -> width = 8, area = min(1, 7) * 8 = 8, maxArea = 8
height[0] < height[8] -> left++

left = 1 (8), right = 8 (7) -> width = 7, area = min(8, 7) * 7 = 49, maxArea = 49
height[8] < height[1] -> right--

left = 1 (8), right = 7 (3) -> width = 6, area = min(8, 3) * 6 = 18
height[7] < height[1] -> right--

left = 1 (8), right = 6 (8) -> width = 5, area = min(8, 8) * 5 = 40
...
Result: 49 ✓
```

```cpp
class Solution {
public:
    int maxArea(vector<int>& height) {
        int left = 0, right = height.size() - 1;
        int maxWater = 0;
        while (left < right) {
            int h = min(height[left], height[right]);
            maxWater = max(maxWater, h * (right - left));
            if (height[left] < height[right]) {
                left++;
            } else {
                right--;
            }
        }
        return maxWater;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(1)$ |

> **This is the one.** Single pass, provably optimal $O(n)$ runtime.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Two lines `[1, 1]` | Minimum width | Computes `1 * (1 - 0) = 1` correctly |
| Uniform heights `[5, 5, 5, 5]` | Either pointer move | Wide outer boundary gives max area `5 * 3 = 15` |
| Tall spikes at center `[1, 1, 100, 100, 1, 1]` | Premature termination | Pointers march past outer low lines to reach center spikes |

---

## Pattern Takeaway

When calculating `min(A, B) * distance`, always **advance the smaller of A and B**. This guarantees you eliminate suboptimal search spaces without evaluating every pair.
