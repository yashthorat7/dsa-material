# 15. 3Sum

> **Medium** $\rightarrow$ **Two-Pointer**


> **Companies:** Amazon, Meta, Microsoft, Apple, Adobe, Google, Infosys

## What are we solving?

Given an integer array `nums`, return all **unique triplets** `[nums[i], nums[j], nums[k]]` such that $i \neq j$, $i \neq k$, and $j \neq k$, and:
$$\text{nums}[i] + \text{nums}[j] + \text{nums}[k] = 0$$

Notice that the output must **not contain duplicate triplets** (even if identical numbers appear multiple times at different indices in `nums`).

```
 Input: nums = [-1, 0, 1, 2, -1, -4]
 
 Step 1: Sort -> [-4, -1, -1, 0, 1, 2]
 
 Fix i = 1 (-1):
   left = 2 (-1), right = 5 (2)  -> (-1) + (-1) + (2) = 0  ==> Triplet: [-1, -1, 2]
   left = 3 (0),  right = 4 (1)  -> (-1) + (0)  + (1) = 0  ==> Triplet: [-1,  0, 1]
   
 Distinct Triplets Found: [[-1, -1, 2], [-1, 0, 1]]
```

### Input & Output Contract
- **Input:**
  - `nums`: `vector<int>` with length $3 \le n \le 3000$, $-10^5 \le \text{nums}[i] \le 10^5$.
- **Output:**
  - `vector<vector<int>>` containing all unique triplets that sum to 0.

### The Core Challenge
A naive 3-loop search is $O(n^3)$, which easily TLEs on $n = 3000$ ($3000^3 = 2.7 \times 10^{10}$). Furthermore, input arrays contain duplicates (e.g. `[-1, -1, 2, 2]`), which could yield identical triplets `[-1, -1, 2]` multiple times unless handled gracefully.

---

**Example 1:**
```
Input:  nums = [-1,0,1,2,-1,-4]
Output: [[-1,-1,2],[-1,0,1]]
Explanation: 
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0.
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0.
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0.
The distinct triplets are [-1,0,1] and [-1,-1,2].
```

**Example 2:**
```
Input:  nums = [0,1,1]
Output: []
Explanation: The only possible triplet (0, 1, 1) sums to 2 != 0.
```

**Example 3:**
```
Input:  nums = [0,0,0]
Output: [[0,0,0]]
```

**Constraints:**
- $3 \le \text{nums.length} \le 3000$
- $-10^5 \le \text{nums}[i] \le 10^5$

## Approach 1 — Brute Force with Set Deduplication

### Intuition
Generate all triplets $(i, j, k)$ with three nested loops. If the sum is zero, sort the three values and insert them into a `set<vector<int>>` to eliminate duplicates.

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        int n = nums.size();
        set<vector<int>> uniqueTriplets;
        
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                for (int k = j + 1; k < n; k++) {
                    if (nums[i] + nums[j] + nums[k] == 0) {
                        vector<int> triplet = {nums[i], nums[j], nums[k]};
                        sort(triplet.begin(), triplet.end());
                        uniqueTriplets.insert(triplet);
                    }
                }
            }
        }
        
        return vector<vector<int>>(uniqueTriplets.begin(), uniqueTriplets.end());
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n^3 \log K)$ | Three nested loops $O(n^3)$ plus logarithmic set insertions. TLEs for $n > 300$. |
| **Space** | $O(K)$ | Set stores $K$ unique triplets. |

> **Verdict:** Too slow. We need to reduce the 3-variable problem into a sorted 2-pointer problem.

## Approach 2 — Sort + Fixed Pointer + Two Pointers ✅

### Key Insight
1. **Sort the array first** in $O(n \log n)$.
2. Iterate `i` from $0$ to $n-3$. Fix `nums[i]` as the first element.
   - If `nums[i] > 0`, break immediately: since the array is sorted, any subsequent numbers will also be positive, and three positive numbers cannot sum to 0.
   - If `i > 0 && nums[i] == nums[i-1]`, skip `i` to avoid generating duplicate triplets.
3. For the fixed `nums[i]`, find pairs `(left, right)` in the remaining sub-array `[i+1, n-1]` such that:
   $$\text{nums}[\text{left}] + \text{nums}[\text{right}] = -\text{nums}[i]$$
4. When a valid triplet is found:
   - Append to results.
   - Increment `left` and decrement `right`.
   - Skip duplicate values for `left` (`while (nums[left] == nums[left-1]) left++`) and `right`.

```
nums = [-1, 0, 1, 2, -1, -4]
Sorted: [-4, -1, -1, 0, 1, 2]

i=0 (val = -4): left=1 (-1), right=5 (2) -> sum = -4 + 1 = -3 < 0 -> left++
                left=4 (1),  right=5 (2) -> sum = -4 + 3 = -1 < 0 -> no triplet
i=1 (val = -1): left=2 (-1), right=5 (2) -> sum = -1 + 1 = 0  -> MATCH: [-1, -1, 2]
                left=3 (0),  right=4 (1) -> sum = -1 + 1 = 0  -> MATCH: [-1, 0, 1]
i=2 (val = -1): nums[2] == nums[1] -> SKIP duplicate!
i=3 (val = 0):  left=4 (1), right=5 (2)  -> sum = 0 + 3 = 3 > 0 -> right--
Terminates.

Result: [[-1, -1, 2], [-1, 0, 1]] ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        vector<vector<int>> result;
        int n = nums.size();
        
        for (int i = 0; i < n - 2; i++) {
            // Early exit: smallest element is positive, sum cannot be 0
            if (nums[i] > 0) break;
            
            // Skip duplicates for the first element
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            
            int left = i + 1;
            int right = n - 1;
            
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                
                if (sum == 0) {
                    result.push_back({nums[i], nums[left], nums[right]});
                    left++;
                    right--;
                    
                    // Skip duplicates for second and third elements
                    while (left < right && nums[left] == nums[left - 1]) left++;
                    while (left < right && nums[right] == nums[right + 1]) right--;
                } else if (sum < 0) {
                    left++;
                } else {
                    right--;
                }
            }
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n^2)$ | Sorting takes $O(n \log n)$. The outer loop runs $n$ times with an inner $O(n)$ two-pointer scan: $O(n \log n) + O(n^2) = O(n^2)$. |
| **Space** | $O(1)$ extra | Sorting uses $O(\log n)$ stack space (in C++ `sort`). No extra auxiliary data structures allocated. |

> **This is the one.** Clean $O(n^2)$ time, $O(1)$ extra space, with exact in-place duplicate skipping.

## Approach 3 — Sort + Hash Set Lookup

### Intuition
Fix the first element `nums[i]`. For the remainder of the array, run a Two Sum hash set complement lookup: target complement $= -(nums[i] + nums[j])$.

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        vector<vector<int>> result;
        int n = nums.size();
        
        for (int i = 0; i < n - 2; i++) {
            if (nums[i] > 0) break;
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            
            unordered_set<int> seen;
            for (int j = i + 1; j < n; j++) {
                int complement = -(nums[i] + nums[j]);
                if (seen.count(complement)) {
                    result.push_back({nums[i], complement, nums[j]});
                    // Advance j past duplicates
                    while (j + 1 < n && nums[j] == nums[j + 1]) j++;
                }
                seen.insert(nums[j]);
            }
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n^2)$ | Outer loop $n$ times $\times$ inner hash set lookup $O(n)$. |
| **Space** | $O(n)$ | Recreates an unordered set of up to $n$ elements per outer iteration. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **All Zeroes** | `[0, 0, 0, 0]` | Generating duplicate `[0, 0, 0]` triplets. | `nums[i] == nums[i-1]` skips `i=1,2,3`, producing exactly one `[0, 0, 0]`. |
| **No Valid Triplet** | `[1, 2, -1, -2, 5]` | Extra unnecessary work. | Two-pointer checks all combinations and returns empty list `[]`. |
| **Small Array** | `[0, 1]` | Out of bounds loop access. | `i < n - 2` condition ensures loop is skipped when $n < 3$. |
| **Large Duplicate Clusters** | `[-2, 0, 0, 2, 2]` | Redundant intermediate pairs. | Inner `while` duplicate skipping advances pointers cleanly. |

---

## Pattern Takeaways

1. **The $K$-Sum Reduction Invariant:**  
   Sort the input array and recursively reduce $K$-Sum to $(K-1)$-Sum until reaching 2Sum, which is solved in $O(n)$ with Two Pointers.
2. **Duplicate Invariant Rule:**  
   Never check `nums[i] == nums[i+1]` before running the inner loop (which would skip the first valid occurrence of duplicate values like `[-1, -1, 2]`). Always check **`nums[i] == nums[i-1]`** after processing the first instance.
