## What are we solving?

You are climbing a staircase that takes `n` steps to reach the top. Each time you take a step, you can climb either **1 step** or **2 steps**.

In how many **distinct ways** can you climb to the top?

```
 Step n=4:
                   [Top: Step 4]
                  /             \
            Take 1 step      Take 2 steps
                /                 \
        [From Step 3]        [From Step 2]
        
 Ways(4) = Ways(3) + Ways(2) = 3 + 2 = 5
```

### Input & Output Contract
- **Input:**
  - `n`: `int` representing total steps to the top ($1 \le n \le 45$).
- **Output:**
  - `int` representing the total number of distinct combinations of 1-step and 2-step moves to reach step $n$.

### The Core Challenge
To reach step $i$, your very last move must have been either:
1. A **1-step jump** from step $i - 1$, OR
2. A **2-step jump** from step $i - 2$.

Since these two possibilities are mutually exclusive and exhaustive, the recurrence is identical to the Fibonacci sequence:
$$\text{Ways}(i) = \text{Ways}(i - 1) + \text{Ways}(i - 2)$$
Solving this recursively without memoization takes exponential $O(2^n)$ time. We need to optimize it to $O(n)$ time and $O(1)$ space.

---

**Example 1:**
```
Input:  n = 2
Output: 2
Explanation: There are 2 ways to climb to the top:
1. 1 step + 1 step
2. 2 steps
```

**Example 2:**
```
Input:  n = 3
Output: 3
Explanation: There are 3 ways to climb to the top:
1. 1 step + 1 step + 1 step
2. 1 step + 2 steps
3. 2 steps + 1 step
```

**Constraints:**
- $1 \le n \le 45$

## Approach 1 — Naive Recursion (Brute Force Tree)

### Intuition
Directly implement the recurrence `climb(i) = climb(i - 1) + climb(i - 2)` with base cases `climb(1) = 1` and `climb(2) = 2`.

```
                    climb(5)
                   /        \
              climb(4)       climb(3)
              /      \        /      \
          climb(3) climb(2) climb(2) climb(1)
          /      \
      climb(2) climb(1)
```
Notice `climb(3)` and `climb(2)` are recomputed repeatedly!

### C++ Implementation
```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) return n;
        return climbStairs(n - 1) + climbStairs(n - 2);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(2^n)$ | Binary recursion tree of depth $n$ without caching generates $2^n$ redundant calls (TLE for $n > 40$). |
| **Space** | $O(n)$ | Call stack depth reaches $n$. |

> **Verdict:** Exponential explosion due to overlapping subproblems.

## Approach 2 — Top-Down DP (Recursion + Memoization)

### Intuition
Cache the result of `climb(i)` in a memoization table `memo[n + 1]`. If `memo[i] != 0`, return the cached answer immediately.

### C++ Implementation
```cpp
class Solution {
public:
    int climbStairs(int n) {
        vector<int> memo(n + 1, 0);
        return helper(n, memo);
    }

private:
    int helper(int n, vector<int>& memo) {
        if (n <= 2) return n;
        if (memo[n] != 0) return memo[n];
        
        memo[n] = helper(n - 1, memo) + helper(n - 2, memo);
        return memo[n];
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Each subproblem from $1$ to $n$ is computed exactly once. |
| **Space** | $O(n)$ | Memoization array of size $n + 1$ plus $O(n)$ recursion stack. |

## Approach 3 — Bottom-Up DP (1D Table)

### Intuition
Iteratively build a DP array from base cases up to $n$:
- `dp[1] = 1`
- `dp[2] = 2`
- `dp[i] = dp[i-1] + dp[i-2]` for $i \in [3, n]$.

### C++ Implementation
```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) return n;
        
        vector<int> dp(n + 1);
        dp[1] = 1;
        dp[2] = 2;
        
        for (int i = 3; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];
        }
        
        return dp[n];
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | A single linear loop from $3$ to $n$. |
| **Space** | $O(n)$ | 1D vector of size $n + 1$. |

## Approach 4 — Space-Optimized Rolling Variables ✅

### Key Insight
To compute `dp[i]`, we only need the values of the **two immediately preceding states** (`dp[i-1]` and `dp[i-2]`). We can discard the rest of the array and maintain two scalar variables (`prev1` and `prev2`).

```
n = 5:
Initial: prev2 = 1 (step 1), prev1 = 2 (step 2)

i = 3: curr = 1 + 2 = 3  -> prev2 = 2, prev1 = 3
i = 4: curr = 2 + 3 = 5  -> prev2 = 3, prev1 = 5
i = 5: curr = 3 + 5 = 8  -> prev2 = 5, prev1 = 8

Return prev1 = 8 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) return n;
        
        int prev2 = 1; // ways to reach step 1
        int prev1 = 2; // ways to reach step 2
        
        for (int i = 3; i <= n; i++) {
            int curr = prev1 + prev2;
            prev2 = prev1;
            prev1 = curr;
        }
        
        return prev1;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Single pass with $n - 2$ additions. |
| **Space** | $O(1)$ | Only two integer variables maintained on the stack. |

> **This is the one.** Clean, zero memory allocation, $O(n)$ time, $O(1)$ space.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Base Step 1** | `n = 1` | Loop indexing out of bounds | `if (n <= 2) return n;` returns 1 immediately. |
| **Base Step 2** | `n = 2` | Loop bounds | Returns 2 immediately. |
| **Upper Bound** | `n = 45` | 32-bit integer overflow | The 45th Fibonacci number is $1,836,311,903$, which safely fits within a signed 32-bit integer ($< 2^{31}-1 = 2,147,483,647$). |

## Pattern Takeaways

1. **State Compression in 1D DP:**  
   Whenever `dp[i]` depends strictly on a fixed window of previous states (e.g. $k=2$ states), compress the DP table into $k$ variables to reduce space complexity from $O(n)$ to $O(1)$.
2. **Generalization to $K$-Steps:**  
   If allowed to take up to $k$ steps at a time (e.g. $[1, 2, \dots, k]$), the recurrence becomes $\text{Ways}(n) = \sum_{j=1}^k \text{Ways}(n - j)$, solvable in $O(n \cdot k)$ with a sliding window sum in $O(n)$.
