# 19. Remove Nth Node From End of List

https://leetcode.com/problems/remove-nth-node-from-end-of-list

> **Medium** $\rightarrow$ **Linked List**


> **Companies:** Meta, Amazon, Microsoft, Google, Bloomberg, Walmart Global Tech, Accenture

## What are we solving?

Given the `head` of a singly linked list and an integer `n`, remove the $n$-th node from the **end** of the list and return its head.

```
       n = 2 (2nd node from end is 4)
       
       [1] -> [2] -> [3] -> [4] -> [5] -> nullptr
                             ↑
                           Remove
                           
 Result: [1] -> [2] -> [3] ------> [5] -> nullptr
```

### Input & Output Contract
- **Input:**
  - `head`: `ListNode*` pointing to the first node of the linked list ($1 \le \text{length} \le 30$).
  - `n`: `int` specifying which node from the end to remove ($1 \le n \le \text{length}$).
- **Output:**
  - `ListNode*` pointing to the head of the modified linked list.

### The Core Challenge
In a singly linked list, links only go forward (`next`). To delete a node, we need access to its **predecessor** (`node_before->next = node_before->next->next`). But since $n$ is measured from the **end**, we either need to know the total length first, maintain a fixed offset between two pointers, or use auxiliary storage.

---

**Example 1:**
```
Input:  head = [1,2,3,4,5], n = 2
Output: [1,2,3,5]
Explanation: The 2nd node from the end is 4. Removing it leaves [1,2,3,5].
```

**Example 2:**
```
Input:  head = [1], n = 1
Output: []
Explanation: Only 1 node exists, and removing the 1st from end leaves an empty list.
```

**Example 3:**
```
Input:  head = [1,2], n = 1
Output: [1]
Explanation: The 1st node from the end is 2. Removing it leaves [1].
```

**Constraints:**
- The number of nodes in the list is `sz`.
- $1 \le sz \le 30$
- $0 \le \text{Node.val} \le 100$
- $1 \le n \le sz$

## Approach 1 — Two Pass (Calculate List Length)

### Intuition
The $n$-th node from the end is the $(L - n + 1)$-th node from the beginning (where $L$ is the total length of the list).  
Therefore, the node **immediately before** the target is at index $(L - n)$ from a dummy pre-head node.

### Step-by-Step Algorithm
1. Create a `dummy` node pointing to `head` (`dummy.next = head`).
2. **Pass 1:** Traverse the entire list to count total length $L$.
3. **Pass 2:** Start a pointer `curr` at `dummy` and advance it $L - n$ steps.
4. `curr` is now right before the node to remove. Relink: `curr->next = curr->next->next`.
5. Return `dummy.next`.

```
List: [1, 2, 3, 4, 5], n = 2

Pass 1 (Count length):
dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> nullptr  ==> Length L = 5

Pass 2 (Advance L - n = 5 - 2 = 3 steps from dummy):
Step 0: curr = dummy
Step 1: curr = 1
Step 2: curr = 2
Step 3: curr = 3 (Predecessor found!)

Relink: curr->next (3) = 3->next->next (5)
Result: 1 -> 2 -> 3 -> 5 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    ListNode* removeNthFromEnd(ListNode* head, int n) {
        ListNode dummy(0, head);
        
        // Pass 1: find total list length L
        int length = 0;
        ListNode* curr = head;
        while (curr != nullptr) {
            length++;
            curr = curr->next;
        }
        
        // Pass 2: traverse to node immediately preceding target (L - n steps from dummy)
        curr = &dummy;
        for (int i = 0; i < length - n; i++) {
            curr = curr->next;
        }
        
        // Remove target node
        ListNode* toDelete = curr->next;
        curr->next = curr->next->next;
        // delete toDelete; // Recommended in production C++
        
        return dummy.next;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(L)$ | Two passes: $L$ steps to count + $(L - n)$ steps to position = $2L - n$ operations. |
| **Space** | $O(1)$ | Only pointers and primitive counters allocated. |

> **Verdict:** Straightforward and easy to reason about, but requires two traversals over the list.

## Approach 2 — One Pass (Fast & Slow Pointers with Dummy Node) ✅

### Key Insight
Instead of counting length first, we maintain a **constant gap of $n + 1$ nodes** between a `fast` and a `slow` pointer:
- When `fast` reaches `nullptr` (past the tail), `slow` will automatically be positioned at the node **immediately preceding** the $n$-th node from the end!

```
Initial Setup (dummy attached):
dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> nullptr, n = 2
  ↑
fast, slow

1. Advance `fast` by n + 1 = 3 steps:
dummy -> 1 -> 2 -> [3] -> 4 -> 5 -> nullptr
  ↑                 ↑
slow              fast (gap = 3 nodes)

2. Move both `fast` and `slow` together until fast == nullptr:
- fast = 4, slow = 1
- fast = 5, slow = 2
- fast = nullptr, slow = 3

3. `slow` points to node 3!
   slow->next = slow->next->next (bypasses 4)
   
Result: dummy->next = 1 -> 2 -> 3 -> 5 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    ListNode* removeNthFromEnd(ListNode* head, int n) {
        ListNode dummy(0, head);
        ListNode* fast = &dummy;
        ListNode* slow = &dummy;
        
        // Advance fast pointer n + 1 steps ahead
        for (int i = 0; i <= n; i++) {
            fast = fast->next;
        }
        
        // Move both pointers until fast reaches beyond the end
        while (fast != nullptr) {
            fast = fast->next;
            slow = slow->next;
        }
        
        // Delete target node
        ListNode* toDelete = slow->next;
        slow->next = slow->next->next;
        // delete toDelete; // in production
        
        return dummy.next;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(L)$ | Single pass: `fast` visits each node exactly once ($L + 1$ total steps). |
| **Space** | $O(1)$ | Only two pointer references on the stack. |

> **This is the one.** Single pass, elegant dummy node handling, optimal time and space.

## Approach 3 — Stack / Backtracking (LIFO Traversal)

### Intuition
A stack is a Last-In, First-Out (LIFO) structure. If we push every node in the list onto a stack, the top of the stack will be the last node. Popping $n$ nodes brings the predecessor node directly to the top!

### Step-by-Step Algorithm
1. Push `dummy` and all list nodes onto `stack<ListNode*>`.
2. Pop $n$ nodes from the stack.
3. The current top of the stack is now the node **preceding** the target.
4. Update `top->next = top->next->next`.
5. Return `dummy.next`.

```
Stack after pushing [dummy, 1, 2, 3, 4, 5]:
Top -> [5]
       [4]  <- (n=2 target)
       [3]  <- (predecessor)
       [2]
       [1]
       [dummy]

Pop 2 times (pops 5, 4):
Top -> [3]

Relink: top(3)->next = 3->next->next (5)
Result: 1 -> 2 -> 3 -> 5 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    ListNode* removeNthFromEnd(ListNode* head, int n) {
        ListNode dummy(0, head);
        stack<ListNode*> st;
        
        ListNode* curr = &dummy;
        while (curr != nullptr) {
            st.push(curr);
            curr = curr->next;
        }
        
        // Pop n elements
        for (int i = 0; i < n; i++) {
            st.pop();
        }
        
        // Node preceding target is now at the top
        ListNode* prev = st.top();
        prev->next = prev->next->next;
        
        return dummy.next;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(L)$ | Push $L + 1$ nodes and pop $n$ nodes. |
| **Space** | $O(L)$ | Stack stores pointers to all $L + 1$ nodes. |

> **Verdict:** Useful conceptual alternative when two-pointer arithmetic is not preferred or when converting recursion to iteration.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Remove Head Node** | `[1, 2], n = 2` | Head pointer changes; dereferencing without dummy causes segmentation fault. | `dummy` node ensures `slow` points to `dummy`, safely updating `dummy.next` to `2`. |
| **Single Node List** | `[1], n = 1` | Result should be empty `[]`. | `slow` is `dummy`, `dummy.next = dummy.next->next = nullptr`. Correctly returns `nullptr`. |
| **Remove Last Node** | `[1, 2, 3], n = 1` | Target `next` is `nullptr`. | `slow` points to `2`; `2->next = nullptr`. Safely truncates tail. |
| **Two Elements** | `[1, 2], n = 1` | Short list boundaries. | Fast moves 2 steps, slow stays at 1; `1->next = nullptr`. |

## Pattern Takeaways

1. **The Dummy Pre-Head Invariant:**  
   Always introduce a `dummy` node (`ListNode dummy(0, head);`) when a linked list problem involves:
   - Deleting the `head` node.
   - Returning a potentially empty list.
   - Building a new list incrementally.
2. **The $k$-Step Offset Invariant:**  
   To locate the $n$-th element from the end of a stream or singly linked list in a single pass, initialize two pointers with a distance of $n$ (or $n + 1$ for the predecessor). Advance both in lockstep until the leader reaches termination.
