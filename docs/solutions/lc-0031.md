## What are we solving?

A **permutation** of an array of integers is an arrangement of its members into a sequence or linear order.

The **next permutation** of an array of integers is the next lexicographically greater permutation of its numbers.
- If no such arrangement is possible (the array is sorted in strictly descending order, e.g. `[3, 2, 1]`), the array must be rearranged as the lowest possible order (i.e., sorted in ascending order `[1, 2, 3]`).
- The replacement must be done **in-place** and use only **$O(1)$ extra memory**.

```
 Current: [ 1, 2, 7, 4, 3, 1 ]
 
 Step 1: Identify pivot index i=1 (value 2), where nums[i] < nums[i+1] (2 < 7)
 Step 2: Find smallest number in suffix greater than 2: nums[4] = 3
         Swap 2 and 3 -> [ 1, 3, 7, 4, 2, 1 ]
 Step 3: Reverse strictly decreasing suffix [ 7, 4, 2, 1 ] -> [ 1, 2, 4, 7 ]
 
 Next Permutation: [ 1, 3, 1, 2, 4, 7 ]
```

### Input & Output Contract
- **Input:**
  - `nums`: `vector<int>` ($1 \le n \le 100$, $0 \le \text{nums}[i] \le 100$).
- **Output:**
  - `void` (mutates `nums` in place).
- **Constraint:** Must use strictly $O(1)$ auxiliary space.

## Approach 1 — Brute Force (Generate All Permutations)

### Intuition
Generate all $n!$ permutations in lexicographical order via recursion. Locate `nums` in the generated list, and pick the next adjacent permutation (or wrap to the first permutation if `nums` is the largest).

### C++ Implementation
```cpp
class Solution {
public:
    void nextPermutation(vector<int>& nums) {
        vector<int> sorted = nums;
        sort(sorted.begin(), sorted.end());
        vector<vector<int>> allPerms;
        vector<int> curr;
        vector<bool> used(nums.size(), false);
        
        auto backtrack = [&](auto& self) -> void {
            if (curr.size() == nums.size()) {
                allPerms.push_back(curr);
                return;
            }
            for (int i = 0; i < sorted.size(); i++) {
                if (used[i]) continue;
                if (i > 0 && sorted[i] == sorted[i-1] && !used[i-1]) continue;
                used[i] = true;
                curr.push_back(sorted[i]);
                self(self);
                curr.pop_back();
                used[i] = false;
            }
        };
        
        backtrack(backtrack);
        
        for (int i = 0; i < allPerms.size(); i++) {
            if (allPerms[i] == nums) {
                nums = (i + 1 < allPerms.size()) ? allPerms[i + 1] : allPerms[0];
                return;
            }
        }
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n! \cdot n)$ | Generating and searching all $n!$ permutations. Explodes for $n > 10$. |
| **Space** | $O(n! \cdot n)$ | Memory required to store all permutations. |

> **Verdict:** Impractical. Single-pass pivot identification achieves $O(n)$ time and $O(1)$ space.
