## What are we solving?

There is a robot on an `m x n` grid. The robot is initially located at the **top-left corner** (`grid[0][0]`) and wishes to reach the **bottom-right corner** (`grid[m - 1][n - 1]`).

The robot can only move either **down** or **right** at any point in time.

Given the two integers `m` and `n`, return the number of **possible unique paths** that the robot can take to reach the destination.

```
 Robot (0,0) ---> ---> --->
      |     \
      v      \  (Only Right and Down moves allowed)
      |       v
      v ---> Destination (m-1, n-1)
```

### Input & Output Contract
- **Input:**
  - `m`: `int` number of rows ($1 \le m \le 100$).
  - `n`: `int` number of columns ($1 \le n \le 100$).
- **Output:**
  - `int` representing total distinct valid path trajectories. (Guaranteed $\le 2 \times 10^9$, fitting in 32-bit signed integer).

### The Core Challenge
To arrive at cell `(r, c)`, the robot must come from either:
1. The cell directly above: `(r - 1, c)` (by moving Down).
2. The cell directly to the left: `(r, c - 1)` (by moving Right).

Thus, the recurrence relation is:
$$\text{Paths}(r, c) = \text{Paths}(r - 1, c) + \text{Paths}(r, c - 1)$$
With base cases $\text{Paths}(0, c) = 1$ and $\text{Paths}(r, 0) = 1$.

---

**Example 1:**
```
Input:  m = 3, n = 7
Output: 28
```

**Example 2:**
```
Input:  m = 3, n = 2
Output: 3
Explanation: From the top-left corner, there are a total of 3 ways:
1. Right -> Down -> Down
2. Down -> Down -> Right
3. Down -> Right -> Down
```

**Constraints:**
- $1 \le m, n \le 100$

## Approach 1 — 2D Dynamic Programming Matrix

### Intuition
Create an $m \times n$ table `dp[r][c]`:
- Initialize top row `dp[0][c] = 1` and left column `dp[r][0] = 1`.
- For all other cells: `dp[r][c] = dp[r - 1][c] + dp[r][c - 1]`.

```
m = 3, n = 3:
[ 1,  1,  1 ]
[ 1,  2,  3 ]
[ 1,  3,  6 ]  -> Returns dp[2][2] = 6
```

### C++ Implementation
```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        vector<vector<int>> dp(m, vector<int>(n, 1));
        
        for (int r = 1; r < m; r++) {
            for (int c = 1; c < n; c++) {
                dp[r][c] = dp[r - 1][c] + dp[r][c - 1];
            }
        }
        
        return dp[m - 1][n - 1];
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(m \cdot n)$ | Fills each cell in the $m \times n$ grid once. |
| **Space** | $O(m \cdot n)$ | 2D vector allocation of size $m \times n$. |

## Approach 2 — 1D Space-Optimized Rolling Row ✅

### Key Insight
Notice that updating `dp[r][c]` only requires:
- `dp[r - 1][c]` (the value from the current column in the *previous row*).
- `dp[r][c - 1]` (the newly calculated value from the *current row* immediately to the left).

We can compress the entire 2D table into a single 1D array `dp[c]` of size $n$:
$$\text{dp}[c] = \text{dp}[c] + \text{dp}[c - 1]$$

```
m = 3, n = 3:
Initial (Row 0): [1, 1, 1]

Row 1:
c=1: dp[1] = dp[1] + dp[0] = 1 + 1 = 2
c=2: dp[2] = dp[2] + dp[1] = 1 + 2 = 3
State after Row 1: [1, 2, 3]

Row 2:
c=1: dp[1] = dp[1] + dp[0] = 2 + 1 = 3
c=2: dp[2] = dp[2] + dp[1] = 3 + 3 = 6
State after Row 2: [1, 3, 6]

Result: 6 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        // Initialize single row of size n with 1s
        vector<int> dp(n, 1);
        
        for (int r = 1; r < m; r++) {
            for (int c = 1; c < n; c++) {
                dp[c] += dp[c - 1];
            }
        }
        
        return dp[n - 1];
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(m \cdot n)$ | Nested loop performing $m \times n$ additions. |
| **Space** | $O(n)$ | A single 1D vector of length $n$. |

> **This is the one.** Minimal memory footprint, high CPU cache locality, clean and concise.

## Approach 3 — Combinatorics Formula (Binomial Coefficient)

### Intuition
To reach $(m-1, n-1)$ from $(0, 0)$, the robot must make exactly:
- $(m - 1)$ Down moves ($D$).
- $(n - 1)$ Right moves ($R$).
Total moves $= (m - 1) + (n - 1) = m + n - 2$.

The problem reduces to choosing $(m - 1)$ positions for the Down moves out of $(m + n - 2)$ total steps:
$$\text{Unique Paths} = \binom{m + n - 2}{m - 1} = \frac{(m + n - 2)!}{(m - 1)! \cdot (n - 1)!}$$

### C++ Implementation
```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        int N = m + n - 2;
        int k = min(m - 1, n - 1);
        long long ans = 1;
        
        // Compute C(N, k) iteratively while avoiding overflow
        for (int i = 1; i <= k; i++) {
            ans = ans * (N - k + i) / i;
        }
        
        return static_cast<int>(ans);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\min(m, n))$ | A single loop running $\min(m-1, n-1)$ iterations. |
| **Space** | $O(1)$ | Pure integer arithmetic. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Single Row or Column** | `m = 1, n = 5` or `m = 5, n = 1` | Loop bounds | Only 1 straight-line path exists; returns 1 immediately. |
| **$1 \times 1$ Grid** | `m = 1, n = 1` | Move calculations | Start is already destination; returns 1. |
| **32-Bit Arithmetic Overflow** | $m = 100, n = 100$ | Combinatorics factorial overflow | Approach 2 using DP avoids intermediate factorial multiplication overflows. |

## Pattern Takeaways

1. **Pascal's Triangle on Grids:**  
   Grid traversal without obstacles is isomorphic to Pascal's identity $\binom{n}{k} = \binom{n-1}{k-1} + \binom{n-1}{k}$.
2. **Grid Space Compression:**  
   Any 2D grid DP where cell $(r, c)$ depends only on $(r-1, c)$ and $(r, c-1)$ can be compressed from $O(M \times N)$ space down to $O(\min(M, N))$ space using a rolling row vector.
3. **Generalization with Obstacles:**  
   When obstacles exist ([LC 63: Unique Paths II](file:///e:/Projects/dsa-notes/docs/solutions/lc-0063.md)), set `dp[c] = 0` whenever `grid[r][c] == 1`.
