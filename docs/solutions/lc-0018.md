> **Medium** $\rightarrow$ **Two-Pointer**

## What are we solving?

Given an array `nums` of `n` integers, return an array of all the **unique quadruplets** `[nums[a], nums[b], nums[c], nums[d]]` such that `0 <= a, b, c, d < n`, `a, b, c, and d` are distinct, and `nums[a] + nums[b] + nums[c] + nums[d] == target`. You may return the answer in any order.

The core challenge is: **how do we scale 3Sum to 4Sum while preventing duplicate quadruplets and avoiding integer overflow in $O(n^3)$ time?**

**Example 1:**
```
Input:  nums = [1,0,-1,0,-2,2], target = 0
Output: [[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]]
```

**Example 2:**
```
Input:  nums = [2,2,2,2,2], target = 8
Output: [[2,2,2,2]]
```

**Constraints:**
- $1 \le \text{nums.length} \le 200$
- $-10^9 \le \text{nums}[i] \le 10^9$
- $-10^9 \le \text{target} \le 10^9$

## Approach 1 — Nested Loops + Two Pointers ✅

**Key insight:**
1. Sort `nums`.
2. Outer loop `i` from `0` to `n-4` (skip duplicates with `if (i > 0 && nums[i] == nums[i-1]) continue;`).
3. Inner loop `j` from `i+1` to `n-3` (skip duplicates with `if (j > i + 1 && nums[j] == nums[j-1]) continue;`).
4. Two pointers `left = j + 1`, `right = n - 1`.
5. Use `long long` for sum calculation to avoid overflow when adding large values.
6. When a quadruplet is found, skip duplicate values for `left` and `right`.

```
nums = [-2, -1, 0, 0, 1, 2], target = 0
Fix i = 0 (-2), Fix j = 1 (-1):
  left = 2 (0), right = 5 (2) -> sum = -2 + -1 + 0 + 2 = -1 < 0 -> left = 3 (0)
  left = 3 (0), right = 5 (2) -> sum = -2 + -1 + 0 + 2 = -1 < 0 -> left = 4 (1)
  left = 4 (1), right = 5 (2) -> sum = -2 + -1 + 1 + 2 = 0 -> MATCH: [-2, -1, 1, 2]
...
Result: [[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]] ✓
```

```cpp
class Solution {
public:
    vector<vector<int>> fourSum(vector<int>& nums, int target) {
        sort(nums.begin(), nums.end());
        vector<vector<int>> result;
        int n = nums.size();
        
        for (int i = 0; i < n - 3; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            
            for (int j = i + 1; j < n - 2; j++) {
                if (j > i + 1 && nums[j] == nums[j - 1]) continue;
                
                int left = j + 1, right = n - 1;
                while (left < right) {
                    long long sum = (long long)nums[i] + nums[j] + nums[left] + nums[right];
                    if (sum == target) {
                        result.push_back({nums[i], nums[j], nums[left], nums[right]});
                        while (left < right && nums[left] == nums[left + 1]) left++;
                        while (left < right && nums[right] == nums[right - 1]) right--;
                        left++;
                        right--;
                    } else if (sum < target) {
                        left++;
                    } else {
                        right--;
                    }
                }
            }
        }
        return result;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n^3)$ | $O(1)$ |

> **This is the one.** Standard optimal $O(n^3)$ solution with 64-bit integer safety.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Integer overflow with large values `[1000000000, 1000000000, ...]` | 32-bit signed overflow | Casting sum terms to `long long` prevents arithmetic overflow |
| Array with fewer than 4 elements | Negative index bounds `n - 3 < 0` | `n < 4` check implicitly handled by loop bounds |
| Identical elements `[2, 2, 2, 2, 2], target = 8` | Multiple duplicates | All duplicate bypass checks ensure only 1 quadruplet `[[2,2,2,2]]` is returned |

---

## Pattern Takeaway

The **K-Sum Generalized Template** fixes $K-2$ variables with nested loops and solves the base 2-variable case with Two Pointers. Always watch for arithmetic overflow when summing $K$ numbers.
