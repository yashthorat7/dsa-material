## What are we solving?

Given an integer array `nums`, return the length of the longest **strictly increasing subsequence**.

Can you solve it in **$O(n \log n)$ time complexity** using binary search with patience sorting?

**Example 1:**
```
Input:  nums = [10,9,2,5,3,7,101,18]
Output: 4
Explanation: The longest increasing subsequence is [2,3,7,101], therefore the length is 4.
```

**Example 2:**
```
Input:  nums = [0,1,0,3,2,3]
Output: 4
```

**Example 3:**
```
Input:  nums = [7,7,7,7,7,7,7]
Output: 1
```

**Constraints:**
- $1 \le \text{nums.length} \le 2500$
- $-10^4 \le \text{nums}[i] \le 10^4$

## Approach 1 — Patience Sorting with Binary Search (std::lower_bound) ✅

**Key insight:**
Maintain an array `tails` where `tails[i]` stores the **smallest tail element** among all increasing subsequences of length `i + 1`.
- `tails` is always strictly increasing.
- For each `x` in `nums`:
  - Binary search for first element in `tails >= x` (`lower_bound`).
  - If `x` is greater than all elements: append `tails.push_back(x)`.
  - Else: overwrite `*it = x` (a smaller tail allows more future elements to extend this subsequence!).
Length of LIS is `tails.size()`.

```
nums = [10, 9, 2, 5, 3, 7, 101, 18]
tails = []

x=10: tails = [10]
x=9:  replace 10 -> tails = [9]
x=2:  replace 9  -> tails = [2]
x=5:  append 5   -> tails = [2, 5]
x=3:  replace 5  -> tails = [2, 3]
x=7:  append 7   -> tails = [2, 3, 7]
x=101: append 101 -> tails = [2, 3, 7, 101]
x=18: replace 101 -> tails = [2, 3, 7, 18]

LIS length = tails.size() = 4 ✓
```

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        vector<int> tails;
        for (int x : nums) {
            auto it = lower_bound(tails.begin(), tails.end(), x);
            if (it == tails.end()) {
                tails.push_back(x);
            } else {
                *it = x;
            }
        }
        return tails.size();
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n \log n)$ | $O(n)$ |

> **This is the one.** Patience sorting with $O(n \log n)$ binary search.

---

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| All identical elements `[7, 7, 7, 7]` | Overwriting index 0 repeatedly | `tails` length stays 1 |
| Strictly decreasing `[5, 4, 3, 2, 1]` | Overwriting index 0 | Returns 1 |

---

## Pattern Takeaway

**Patience Sorting (`tails` array + `lower_bound`)** maintains the optimal minimal endpoints for each subsequence length in $O(n \log n)$.
