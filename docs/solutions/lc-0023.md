# 23. Merge k Sorted Lists

> **Companies:** Meta, Amazon, Microsoft, Apple, Google, ByteDance, Walmart Global Tech, Sprinklr, Infosys

## What are we solving?

You are given an array of $k$ linked lists `lists`, where each individual linked list is sorted in ascending order. Merge all $k$ linked lists into one **single sorted linked list** and return its head.

```
 lists = [
   [1] -> [4] -> [5] -> nullptr,
   [1] -> [3] -> [4] -> nullptr,
   [2] -> [6] -> nullptr
 ]
 
 Merged Output:
   [1] -> [1] -> [2] -> [3] -> [4] -> [4] -> [5] -> [6] -> nullptr
```

### Input & Output Contract
- **Input:**
  - `lists`: `vector<ListNode*>` of length $k$ ($0 \le k \le 10^4$), where each `lists[i]` is the head of a sorted list ($0 \le \text{length} \le 500$, total nodes $N \le 10^4$).
- **Output:**
  - `ListNode*` pointing to the head of the single merged sorted list (or `nullptr` if $k = 0$ or all lists are empty).

### The Core Challenge
If we sequentially merge lists one by one ($L_1$ with $L_2$, then with $L_3$, etc.), the first list gets traversed $k$ times, resulting in $O(k \cdot N)$ runtime. The challenge is to perform the $k$-way merge in $O(N \log k)$ time either through a Priority Queue or a Divide & Conquer merge tree.

---

**Example 1:**
```
Input:  lists = [[1,4,5],[1,3,4],[2,6]]
Output: [1,1,2,3,4,4,5,6]
Explanation: The linked-lists are:
[
  1->4->5,
  1->3->4,
  2->6
]
merging them into one sorted list:
1->1->2->3->4->4->5->6
```

**Example 2:**
```
Input:  lists = []
Output: []
```

**Example 3:**
```
Input:  lists = [[]]
Output: []
```

**Constraints:**
- $k == \text{lists.length}$
- $0 \le k \le 10^4$
- $0 \le \text{lists}[i].\text{length} \le 500$
- $-10^4 \le \text{lists}[i][j] \le 10^4$
- `lists[i]` is sorted in ascending order.
- The total sum of all `lists[i].length` will not exceed $10^4$.

## Approach 1 — Collect All Values, Sort, and Rebuild

### Intuition
The simplest brute force: traverse all $k$ linked lists, collect every node value into a flat array, sort the array using `sort`, and rebuild a brand new linked list.

### C++ Implementation
```cpp
class Solution {
public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        vector<int> values;
        for (ListNode* head : lists) {
            while (head != nullptr) {
                values.push_back(head->val);
                head = head->next;
            }
        }
        
        if (values.empty()) return nullptr;
        sort(values.begin(), values.end());
        
        ListNode dummy(0);
        ListNode* curr = &dummy;
        for (int v : values) {
            curr->next = new ListNode(v);
            curr = curr->next;
        }
        
        return dummy.next;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(N \log N)$ | Collecting values takes $O(N)$, sorting takes $O(N \log N)$, rebuilding takes $O(N)$. |
| **Space** | $O(N)$ | Extra vector storing all $N$ integers and creating new nodes. |

> **Verdict:** Functional, but ignores the fact that each individual list is already sorted and allocates $O(N)$ extra nodes.

## Approach 2 — Min-Heap (Priority Queue Multi-Way Merge)

### Intuition
Since each of the $k$ lists is already sorted, the global minimum at any moment is guaranteed to be among the **current head nodes** of the $k$ lists.
1. Insert the head node of each non-empty list into a **Min-Heap** of size at most $k$.
2. Pop the smallest node `minNode` from the heap, attach it to our merged list `tail->next = minNode`.
3. If `minNode->next != nullptr`, push `minNode->next` into the heap.
4. Repeat until the heap is empty.

```
lists = [L1: 1->4->5, L2: 1->3->4, L3: 2->6]
Min-Heap: [1(L1), 1(L2), 2(L3)]

1. Pop 1(L1) -> tail = 1 -> push 4(L1) -> Heap: [1(L2), 2(L3), 4(L1)]
2. Pop 1(L2) -> tail = 1 -> push 3(L2) -> Heap: [2(L3), 3(L2), 4(L1)]
3. Pop 2(L3) -> tail = 2 -> push 6(L3) -> Heap: [3(L2), 4(L1), 6(L3)]
4. Pop 3(L2) -> tail = 3 -> push 4(L2) -> Heap: [4(L1), 4(L2), 6(L3)]
...
Result: 1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6 ✓
```

### C++ Implementation
```cpp
class Solution {
    struct CompareNode {
        bool operator()(ListNode* a, ListNode* b) const {
            return a->val > b->val; // Min-heap comparator
        }
    };
public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        priority_queue<ListNode*, vector<ListNode*>, CompareNode> minHeap;
        
        // Push initial heads of all non-empty lists
        for (ListNode* head : lists) {
            if (head != nullptr) {
                minHeap.push(head);
            }
        }
        
        ListNode dummy(0);
        ListNode* tail = &dummy;
        
        while (!minHeap.empty()) {
            ListNode* minNode = minHeap.top();
            minHeap.pop();
            
            tail->next = minNode;
            tail = tail->next;
            
            if (minNode->next != nullptr) {
                minHeap.push(minNode->next);
            }
        }
        
        return dummy.next;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(N \log k)$ | The heap size is at most $k$. Each of the $N$ nodes is pushed and popped from the heap exactly once ($N \times \log k$). |
| **Space** | $O(k)$ | The priority queue holds at most $k$ pointer references at any time. |

> **Verdict:** Very practical, intuitive, and optimal $O(N \log k)$ time.

## Approach 3 — Divide & Conquer (Pairwise Merge Sort) ✅

### Key Insight
Instead of merging one by one or using a heap, pair up the $k$ lists and merge each pair using our $O(1)$-space **Merge Two Sorted Lists** subroutine ([LC 21](file:///e:/Projects/dsa-notes/docs/solutions/lc-0021.md)).
- Round 1: Merge $k$ lists into $k/2$ lists.
- Round 2: Merge $k/2$ lists into $k/4$ lists.
- ...
- Total rounds: $\log_2 k$. Each round processes all $N$ nodes in $O(N)$ time.
- **Total Time:** $O(N \log k)$, with **$O(1)$ extra heap memory!**

```
Round 0:  [L0]   [L1]   [L2]   [L3]   [L4]   [L5]   [L6]   [L7]  (8 lists)
            \     /       \     /       \     /       \     /
Round 1:   [L0 + L1]     [L2 + L3]     [L4 + L5]     [L6 + L7]    (4 lists)
                 \         /                 \         /
Round 2:      [L0 + L1 + L2 + L3]         [L4 + L5 + L6 + L7]     (2 lists)
                          \                     /
Round 3:              [Fully Merged 8-List Chain]                 (1 list)
```

### C++ Implementation
```cpp
class Solution {
public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        if (lists.empty()) return nullptr;
        
        int interval = 1;
        int k = lists.size();
        
        // Iterative bottom-up pairwise merge
        while (interval < k) {
            for (int i = 0; i + interval < k; i += interval * 2) {
                lists[i] = mergeTwoLists(lists[i], lists[i + interval]);
            }
            interval *= 2;
        }
        
        return lists[0];
    }

private:
    ListNode* mergeTwoLists(ListNode* l1, ListNode* l2) {
        ListNode dummy(0);
        ListNode* tail = &dummy;
        
        while (l1 && l2) {
            if (l1->val <= l2->val) {
                tail->next = l1;
                l1 = l1->next;
            } else {
                tail->next = l2;
                l2 = l2->next;
            }
            tail = tail->next;
        }
        
        tail->next = l1 ? l1 : l2;
        return dummy.next;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(N \log k)$ | $\log_2 k$ reduction levels, each level merges pairs totalling $N$ nodes in $O(N)$ operations. |
| **Space** | $O(1)$ | Splicing pointers in-place requires no extra data structures or priority queues. |

> **This is the one.** Optimal $O(N \log k)$ time, zero heap memory allocations, in-place pointer splicing.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Empty Outer Vector** | `lists = []` | Accessing `lists[0]` index out of bounds. | `if (lists.empty()) return nullptr;` returns immediately. |
| **Vector with Empty Sublists** | `lists = [nullptr, nullptr]` | Null pointer dereference in comparator. | Pairwise merge cleanly joins null lists returning `nullptr`. |
| **Single List** | `lists = [1->2->3]` | Loop interval not executing. | `interval < k` (1 < 1 is false) immediately returns `lists[0]`. |
| **Varying Lengths** | `[1], [2->3->4->5->6], []` | Skewed list sizes. | Single link remainder attachment (`tail->next = l1 ? l1 : l2`) splices trailing chains in $O(1)$. |

---

## Pattern Takeaways

1. **$K$-Way Merge Hierarchy:**  
   - Sequential merge: $O(k \cdot N)$ (Suboptimal)
   - Min-Heap: $O(N \log k)$ time, $O(k)$ space (Best for streaming data)
   - Divide & Conquer: $O(N \log k)$ time, $O(1)$ space (Best for in-memory linked lists)
2. **Streaming Scalability:**  
   When merging $k$ sorted files from disk where all data cannot fit in RAM, the **Min-Heap** (Approach 2) is the industry standard (External Merge Sort).
