## What are we solving?

Given a **1-indexed** array of integers `numbers` that is already **sorted in non-decreasing order**, find two numbers such that they add up to a specific `target` number.

Return the indices of the two numbers, `index1` and `index2`, added by one as an integer array `[index1, index2]` of length 2.

The tests are generated such that there is **exactly one solution**. You may not use the same element twice. Your solution must use only **$O(1)$ extra space**.

```
 numbers = [ 2,  7, 11, 15 ],  target = 9
             ^   ^
           idx1 idx2
           
 2 + 7 = 9 -> 1-based indices: [1, 2]
```

### Input & Output Contract
- **Input:**
  - `numbers`: `vector<int>` sorted in non-decreasing order ($2 \le n \le 3 \times 10^4$, $-1000 \le \text{numbers}[i] \le 1000$).
  - `target`: `int` target sum ($-1000 \le \text{target} \le 1000$).
- **Output:**
  - `vector<int>` of size 2 containing `[index1 + 1, index2 + 1]`.
- **Constraint:** Must use strictly $O(1)$ extra space.

### The Core Challenge
Unlike [LC 1: Two Sum](file:///e:/Projects/dsa-notes/docs/solutions/lc-0001.md) where a hash map provides $O(n)$ time using $O(n)$ memory, the sorted precondition here allows us to achieve $O(n)$ time in **$O(1)$ constant memory** using Two Pointers.

Input:  numbers = [2,7,11,15], target = 9

Explanation: The sum of 2 and 7 is 9. Therefore, index1 = 1, index2 = 2. We return [1, 2].

- Exactly one valid solution is guaranteed.

## Approach 1 — Binary Search for Complement

### Intuition
For each index $i$ from $0$ to $n-1$, compute the needed complement $\text{comp} = \text{target} - \text{numbers}[i]$. Then binary search for $\text{comp}$ in the sub-array `[i + 1, n - 1]`.

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& numbers, int target) {
        int n = numbers.size();
        
        for (int i = 0; i < n; i++) {
            int complement = target - numbers[i];
            int low = i + 1, high = n - 1;
            
            while (low <= high) {
                int mid = low + (high - low) / 2;
                if (numbers[mid] == complement) {
                    return {i + 1, mid + 1}; // 1-indexed
                } else if (numbers[mid] < complement) {
                    low = mid + 1;
                } else {
                    high = mid - 1;
                }
            }
        }
        
        return {};
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n \log n)$ | For each of the $n$ elements, performs binary search of length up to $n$. |
| **Space** | $O(1)$ | No extra memory allocated. |

## Approach 2 — Two Pointers Inward Squeeze ✅

### Key Insight
Start with two pointers at the extreme ends: `left = 0` and `right = n - 1`:
- If `numbers[left] + numbers[right] == target`: solution found $\rightarrow$ return `[left + 1, right + 1]`.
- If `numbers[left] + numbers[right] < target`: the sum is too small. Because `numbers` is sorted, no element to the left of `right` can produce a larger sum with `numbers[left]`. We **must advance `left++`** to increase the sum.
- If `numbers[left] + numbers[right] > target`: the sum is too large. We **must decrement `right--`** to decrease the sum.

```
numbers = [2, 7, 11, 15], target = 9
left = 0 (val 2), right = 3 (val 15)

Step 1: sum = 2 + 15 = 17 > 9 -> right-- (right = 2)
Step 2: sum = 2 + 11 = 13 > 9 -> right-- (right = 1)
Step 3: sum = 2 + 7  = 9  == target -> MATCH!

1-indexed Result: [1, 2] ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& numbers, int target) {
        int left = 0;
        int right = numbers.size() - 1;
        
        while (left < right) {
            int sum = numbers[left] + numbers[right];
            
            if (sum == target) {
                return {left + 1, right + 1}; // 1-indexed output
            } else if (sum < target) {
                left++;  // Need a larger sum
            } else {
                right--; // Need a smaller sum
            }
        }
        
        return {};
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Each iteration moves either `left` forward or `right` backward. At most $n - 1$ steps. |
| **Space** | $O(1)$ | Pure stack index variables. |

> **This is the one.** Strictly optimal $O(n)$ time and $O(1)$ constant memory.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Negative Values & Negative Target** | `[-5, -3, -1, 0], target = -6` | Sign confusion | Standard algebraic additions handle negative sums seamlessly. |
| **Duplicate Target Halves** | `[2, 3, 3, 4], target = 6` | Using same element twice | Pointers `left = 1` and `right = 2` are distinct indices, returning `[2, 3]`. |
| **Minimum Array Size** | `[1, 2], target = 3` | Initial pointers adjacent | Evaluates on first step, returning `[1, 2]`. |
