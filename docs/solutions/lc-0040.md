## What are we solving?

Given a collection of candidate numbers (`candidates`) and a target number (`target`), find all **unique combinations** in `candidates` where the candidate numbers sum to `target`.

Each number in `candidates` may only be used **once** in the combination. The solution set must **not contain duplicate combinations**.

```
 candidates = [10, 1, 2, 7, 6, 1, 5], target = 8
 Sorted:      [1, 1, 2, 5, 6, 7, 10]
 
 Unique Combinations:
 1. [1, 1, 6]  (1 + 1 + 6 = 8)
 2. [1, 2, 5]  (1 + 2 + 5 = 8)
 3. [1, 7]     (1 + 7 = 8)
 4. [2, 6]     (2 + 6 = 8)
 
 Output: [[1,1,6],[1,2,5],[1,7],[2,6]]
```

### Input & Output Contract
- **Input:**
  - `candidates`: `vector<int>` where $1 \le n \le 100$, $1 \le \text{candidates}[i] \le 50$. May contain duplicate values!
  - `target`: `int` ($1 \le \text{target} \le 30$).
- **Output:**
  - `vector<vector<int>>` containing all unique combinations without duplicate lists.

### The Core Challenge
Unlike Combination Sum I where elements are distinct and reusable, here:
1. Each element may be used **at most once** per combination (`start` advances to `i + 1`).
2. Input contains **duplicate numbers** (e.g. two `1`s). We must allow identical values across vertical tree depth (like `[1, 1, 6]`) while skipping identical values at the same horizontal tree level to prevent duplicate sets.

## Approach 1 — Backtracking with Set Deduplication (Brute Force)

### Intuition
Sort the array and run standard subset backtracking without skipping duplicate consecutive elements. To avoid returning duplicate combinations, collect results in a `set<vector<int>>`.

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<int>> combinationSum2(vector<int>& candidates, int target) {
        sort(candidates.begin(), candidates.end());
        set<vector<int>> uniqueCombos;
        vector<int> current;
        
        auto backtrack = [&](auto& self, int idx, int remain) -> void {
            if (remain == 0) {
                uniqueCombos.insert(current);
                return;
            }
            if (idx == candidates.size() || remain < 0) return;
            
            // Choice 1: Include current element
            current.push_back(candidates[idx]);
            self(self, idx + 1, remain - candidates[idx]);
            current.pop_back();
            
            // Choice 2: Exclude current element
            self(self, idx + 1, remain);
        };
        
        backtrack(backtrack, 0, target);
        return vector<vector<int>>(uniqueCombos.begin(), uniqueCombos.end());
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(2^n \cdot n \log K)$ | Explores $2^n$ subsets and pays set insertion overhead. TLEs for duplicate-heavy inputs. |
| **Space** | $O(2^n \cdot n)$ | Storage for set of unique combinations. |

> **Verdict:** Suboptimal. Sibling duplicate skipping in loop eliminates set overhead.
