## What are we solving?

Given two strings `s` and `p`, return an array of all the **start indices** of `p`'s anagrams in `s`. You may return the answer in any order.

An **Anagram** is a word or phrase formed by rearranging the letters of a different word or phrase, typically using all the original letters exactly once.

```
 s = " c b a e b a b a c d ",  p = " a b c " (length = 3)
 
 Window [0..2]  "cba" -> Anagram of "abc" -> START INDEX 0
 Window [1..3]  "bae" -> Not an anagram
 Window [2..4]  "aeb" -> Not an anagram
 Window [3..5]  "eba" -> Not an anagram
 Window [4..6]  "bab" -> Not an anagram
 Window [5..7]  "aba" -> Not an anagram
 Window [6..8]  "bac" -> Anagram of "abc" -> START INDEX 6
 
 Output: [ 0, 6 ]
```

### Input & Output Contract
- **Input:**
  - `s`: `string` ($1 \le |s| \le 3 \times 10^4$).
  - `p`: `string` ($1 \le |p| \le 3 \times 10^4$).
- **Output:**
  - `vector<int>` containing 0-indexed start positions of all valid anagram windows.

### The Core Challenge
The length of any anagram of $p$ is strictly fixed to $k = |p|$. We must slide a fixed window of size $k$ across $s$, dynamically adding the incoming character $s[i]$ and removing the outgoing character $s[i - k]$ in $O(1)$ time per slide.

---

**Example 1:**
```
Input:  s = "cbaebabacd", p = "abc"
Output: [0,6]
Explanation: The substring with start index = 0 is "cba", which is an anagram of "abc".
The substring with start index = 6 is "bac", which is an anagram of "abc".
```

**Example 2:**
```
Input:  s = "abab", p = "ab"
Output: [0,1,2]
```

**Constraints:**
- $1 \le s.\text{length}, p.\text{length} \le 3 \times 10^4$
- `s` and `p` consist of lowercase English letters.

## Approach 1 — Fixed Sliding Window with Array Comparison

### Intuition
Maintain two fixed-size frequency tables `sCount[26]` and `pCount[26]`. Slide window of size $|p|$ across $s$. If `sCount == pCount`, push `i - |p| + 1` into `result`.

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        int ns = s.length(), np = p.length();
        if (ns < np) return {};
        
        vector<int> pCount(26, 0), sCount(26, 0);
        for (char c : p) pCount[c - 'a']++;
        for (int i = 0; i < np; i++) sCount[s[i] - 'a']++;
        
        vector<int> result;
        if (sCount == pCount) result.push_back(0);
        
        for (int i = np; i < ns; i++) {
            sCount[s[i] - 'a']++;
            sCount[s[i - np] - 'a']--;
            if (sCount == pCount) {
                result.push_back(i - np + 1);
            }
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(26 \cdot n) = O(n)$ | Compares 26-element array at each of the $n$ steps. |
| **Space** | $O(1)$ | 26-element integer vectors. |

## Approach 2 — Sliding Window with Match Count Tracking ✅

### Key Insight
Instead of comparing all 26 elements at every step, maintain a `matches` counter tracking how many of the 26 characters have identical counts in `sCount` and `pCount`:
- When `matches == 26`, the current window is an anagram!
- On adding a character $c$, check if its count transitions to match or diverge from `pCount[c]`.
- On removing a character $c$, update `matches` accordingly.
- Every window slide executes in pure **$O(1)$ arithmetic operations**.

```
s = "cbaebabacd", p = "abc" (len = 3)
pCount: {a:1, b:1, c:1, others:0}

Window [0..2] ("cba"): matches = 26 -> RECORD INDEX 0
Slide 1: Add 'e' (matches--), Remove 'c' (matches--) -> matches = 24
...
Slide 6: Window becomes "bac" -> matches = 26 -> RECORD INDEX 6

Result: [ 0, 6 ] ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        int ns = s.length();
        int np = p.length();
        if (ns < np) return {};
        
        int pCount[26] = {0};
        int sCount[26] = {0};
        
        for (char c : p) pCount[c - 'a']++;
        for (int i = 0; i < np; i++) sCount[s[i] - 'a']++;
        
        int matches = 0;
        for (int i = 0; i < 26; i++) {
            if (sCount[i] == pCount[i]) matches++;
        }
        
        vector<int> result;
        if (matches == 26) result.push_back(0);
        
        for (int i = np; i < ns; i++) {
            int inChar = s[i] - 'a';
            int outChar = s[i - np] - 'a';
            
            // Add incoming character
            sCount[inChar]++;
            if (sCount[inChar] == pCount[inChar]) {
                matches++;
            } else if (sCount[inChar] == pCount[inChar] + 1) {
                matches--;
            }
            
            // Remove outgoing character
            sCount[outChar]--;
            if (sCount[outChar] == pCount[outChar]) {
                matches++;
            } else if (sCount[outChar] == pCount[outChar] - 1) {
                matches--;
            }
            
            if (matches == 26) {
                result.push_back(i - np + 1);
            }
        }
        
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Pure $O(1)$ operations per character slide without 26-element full vector sweeps. |
| **Space** | $O(1)$ | Stack fixed arrays of size 26. |

> **This is the one.** Optimal match counter tracking avoids 26-way equality scans.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **`s.length() < p.length()`** | `s = "a", p = "ab"` | Window initialization underflow | Early check `if (ns < np) return {};` handles cleanly. |
| **Overlapping Matches** | `s = "abab", p = "ab"` | Skipping adjacent indices | Steps forward by 1, correctly yields `[0, 1, 2]`. |
| **All Same Characters** | `s = "aaaa", p = "aa"` | Duplicate tracking | Yields `[0, 1, 2]`. |

## Pattern Takeaways

1. **Fixed Window Frequency Invariant:**  
   When searching for permutations/anagrams of a fixed string $p$, maintain window size $|p|$ and track delta changes at $i$ and $i - |p|$.
