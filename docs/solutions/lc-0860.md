## What are we solving?

At a lemonade stand, each lemonade costs `$5`. Customers are standing in a queue to buy from you and order one at a time (in the order specified by bills). Each customer will only buy one lemonade and pay with either a `$5`, `$10`, or `$20` bill. You must provide the correct change to each customer so that the net transaction is that the customer pays `$5`.

Note that you do not have any change in hand at first.

Given an integer array `bills` where `bills[i]` is the bill the $i$-th customer pays, return `true` if you can provide every customer with the correct change, or `false` otherwise.

**Example 1:**
```
Input:  bills = [5,5,5,10,20]
Output: true
Explanation: From the first 3 customers, we collect three $5 bills.
From the 4th customer, we collect a $10 bill and give back a $5.
From the 5th customer, we give a $10 bill and a $5 bill.
```

**Example 2:**
```
Input:  bills = [5,5,10,10,20]
Output: false
Explanation: From the first two customers in order, we collect two $5 bills.
For the next two customers in order, we collect a $10 bill and give back a $5 bill.
For the last customer, we cannot give change of $15 back because we only have two $10 bills.
```

**Constraints:**
- $1 \le \text{bills.length} \le 10^5$
- `bills[i]` is either `5`, `10`, or `20`.

## Approach 1 — Greedy Change Priority ($10 + $5 over 3x$5) ✅

**Key insight:**
Track counts of `$5` and `$10` bills (we never give `$20` as change).
- When receiving `$5`: `five++`.
- When receiving `$10`: need `$5` change -> if `five > 0`: `five--`, `ten++`; else return `false`.
- When receiving `$20`: need `$15` change.
  - **Greedy choice:** Giving `one $10 + one $5` is ALWAYS strictly better than `three $5` because `$5` bills are more flexible (needed for both `$10` and `$20` change).
  - If `ten > 0 && five > 0`: `ten--`, `five--`.
  - Else if `five >= 3`: `five -= 3`.
  - Else return `false`.

```
bills = [5, 5, 5, 10, 20]
five = 0, ten = 0

bill 5:  five=1
bill 5:  five=2
bill 5:  five=3
bill 10: five=2, ten=1
bill 20: give $10+$5 -> ten=0, five=1

Result: true ✓
```

```cpp
class Solution {
public:
    bool lemonadeChange(vector<int>& bills) {
        int five = 0, ten = 0;
        for (int bill : bills) {
            if (bill == 5) {
                five++;
            } else if (bill == 10) {
                if (five == 0) return false;
                five--;
                ten++;
            } else {
                // bill == 20: prioritize $10 + $5
                if (ten > 0 && five > 0) {
                    ten--;
                    five--;
                } else if (five >= 3) {
                    five -= 3;
                } else {
                    return false;
                }
            }
        }
        return true;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(1)$ |

> **This is the one.** Optimal greedy decision making in linear time.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| First customer pays with $10 or $20 | Immediate failure | `five == 0` check returns `false` |
| $20 change when only $5 bills available | Falling back to 3x$5 | `five >= 3` fallback branch provides valid change |

---

## Pattern Takeaway

Always **preserve the most versatile resource** ($5 bills can satisfy both $10 and $20 requests; $10 bills can only satisfy $20 requests).
