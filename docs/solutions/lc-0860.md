## What are we solving?

At a lemonade stand, each lemonade costs `$5`. Customers are standing in a queue to buy from you and order one at a time. Each customer will only buy one lemonade and pay with either a `$5`, `$10`, or `$20` bill.

You must provide the correct change to each customer so that the net transaction is that the customer pays `$5`. You do not have any change in hand initially.

Return `true` if you can provide every customer with the correct change, or `false` otherwise.

```
 Customers: [ $5, $5, $5, $10, $20 ]
 
 Transaction 1 ($5):  Collect $5        -> Cash: { $5: 1 }
 Transaction 2 ($5):  Collect $5        -> Cash: { $5: 2 }
 Transaction 3 ($5):  Collect $5        -> Cash: { $5: 3 }
 Transaction 4 ($10): Return $5 change  -> Cash: { $5: 2, $10: 1 }
 Transaction 5 ($20): Return $10 + $5   -> Cash: { $5: 1, $10: 0 }
 
 All customers served!
 Output: true
```

### Input & Output Contract
- **Input:**
  - `bills`: `vector<int>` ($1 \le n \le 10^5$, `bills[i]` $\in \{5, 10, 20\}$).
- **Output:**
  - `bool`: `true` if all customers receive correct change; otherwise `false`.

### The Greedy Choice Property
When receiving a **$20 bill**, we must return **$15 in change**:
1. **Option A:** Give one `$10` bill and one `$5` bill.
2. **Option B:** Give three `$5` bills.
- **Why Option A is strictly better:**  
  A `$5` bill is universally versatile (required to make change for both `$10` and `$20` transactions). A `$10` bill can *only* be used to make change for `$20` transactions. Therefore, we should **always greedily exhaust our `$10` bills first!**

---

**Example 1:**
```
Input:  bills = [5,5,5,10,20]
Output: true
```

**Example 2:**
```
Input:  bills = [5,5,10,10,20]
Output: false
Explanation: For the last customer, we cannot give change of $15 back because we only have two $10 bills.
```

**Constraints:**
- $1 \le \text{bills.length} \le 10^5$
- `bills[i]` is either `5`, `10`, or `20`.

## Approach 1 — Greedy Register State Machine ✅

### Key Insight
1. Track two counters: `five = 0`, `ten = 0` (we never use `$20` for change).
2. For each `bill`:
   - If `bill == 5`: `five++`.
   - If `bill == 10`:
     - If `five == 0`, return `false`.
     - `five--`, `ten++`.
   - If `bill == 20`:
     - **Greedy Priority:** If `ten > 0 && five > 0`: `ten--`, `five--`.
     - **Fallback:** Else if `five >= 3`: `five -= 3`.
     - Else: return `false`.
3. If all transactions complete, return `true`.

```
bills = [5, 5, 5, 10, 20]
five = 0, ten = 0

1. bill=5:  five = 1
2. bill=5:  five = 2
3. bill=5:  five = 3
4. bill=10: five = 2, ten = 1
5. bill=20: give $10 + $5 -> ten = 0, five = 1

Result: true ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    bool lemonadeChange(vector<int>& bills) {
        int five = 0;
        int ten = 0;
        
        for (int bill : bills) {
            if (bill == 5) {
                five++;
            } else if (bill == 10) {
                if (five == 0) return false;
                five--;
                ten++;
            } else { // bill == 20
                // Greedily prioritize giving one $10 and one $5 bill
                if (ten > 0 && five > 0) {
                    ten--;
                    five--;
                } else if (five >= 3) {
                    five -= 3;
                } else {
                    return false;
                }
            }
        }
        
        return true;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Single linear pass over $n$ transactions. |
| **Space** | $O(1)$ | Two integer counters. |

> **This is the one.** Clean, space-optimal greedy state simulation.

## Approach 2 — Hash Map Register Tracking

### Intuition
Store bill counts in an `unordered_map<int, int> reg`. On $20 change, check if `reg[10] > 0 && reg[5] > 0` before falling back to `reg[5] >= 3`.

### C++ Implementation
```cpp
class Solution {
public:
    bool lemonadeChange(vector<int>& bills) {
        unordered_map<int, int> reg;
        
        for (int b : bills) {
            if (b == 5) {
                reg[5]++;
            } else if (b == 10) {
                if (reg[5] == 0) return false;
                reg[5]--;
                reg[10]++;
            } else { // 20
                if (reg[10] > 0 && reg[5] > 0) {
                    reg[10]--;
                    reg[5]--;
                } else if (reg[5] >= 3) {
                    reg[5] -= 3;
                } else {
                    return false;
                }
            }
        }
        return true;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Linear scan over bills. |
| **Space** | $O(1)$ | Fixed size map of 2 keys. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **First Customer Pays $10 or $20** | `[10]` or `[20]` | Immediate deficit | `five == 0` check triggers immediate `false`. |
| **Only $10 Bills Available for $20 Change** | `[5, 10, 10, 20]` | Cannot combine two $10s | Correctly evaluates that $10 + $10 $\neq 15$, returning `false`. |
| **All $5 Bills** | `[5, 5, 5, 5]` | Trivial accumulation | Returns `true`. |

1. **Preserving Versatile Resources:**
