## What are we solving?

The **median** is the middle value in an ordered integer list:
- If the size of the list is odd, the median is the middle element.
- If the size of the list is even, there is no single middle value, and the median is the mean (average) of the two middle values.

Design a data structure that supports the following two operations efficiently:
1. `void addNum(int num)`: Adds the integer `num` from the data stream.
2. `double findMedian()`: Returns the median of all elements accumulated so far.

```
 Stream: [ 1 ]             -> Median = 1.0
 Stream: [ 1, 2 ]          -> Median = (1 + 2) / 2.0 = 1.5
 Stream: [ 1, 2, 3 ]       -> Median = 2.0
 Stream: [ 1, 2, 3, 4 ]    -> Median = (2 + 3) / 2.0 = 2.5
```

### Input & Output Contract
- **Operations:**
  - `addNum(int num)`: $-10^5 \le \text{num} \le 10^5$.
  - `findMedian()`: returns `double`. Guaranteed at least one element exists before `findMedian()` is called.
- **Constraints:** Up to $5 \times 10^4$ operations.

### The Core Challenge
If we maintain an array and sort it on every query, `findMedian` is $O(n \log n)$ per query. If we use `lower_bound` with `vector::insert`, insertion is $O(n)$ due to element shifting.  
To support $5 \times 10^4$ real-time stream operations, we need **$O(\log n)$ insertion** and **$O(1)$ median lookup**.

## Approach 1 — Sorted Vector via Binary Insertion

### Intuition
Maintain a sorted dynamic array `nums`. On `addNum(x)`, use `lower_bound` to find the insertion index in $O(\log n)$ and insert in $O(n)$ array shift time. `findMedian()` returns the center element(s) in $O(1)$.

### C++ Implementation
```cpp
class MedianFinder {
private:
    vector<int> data;

public:
    MedianFinder() {}
    
    void addNum(int num) {
        auto it = lower_bound(data.begin(), data.end(), num);
        data.insert(it, num);
    }
    
    double findMedian() {
        int n = data.size();
        if (n % 2 == 1) {
            return data[n / 2];
        }
        return (data[n / 2 - 1] + data[n / 2]) / 2.0;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | `addNum`: $O(n)$, `findMedian`: $O(1)$ | Array shifting on each insertion. |
| **Space** | $O(n)$ | Stores all elements in array. |

## Approach 3 — `multiset` with Two Pointers / Mid Iterators

### Intuition
Maintain a balanced BST (`multiset`) with two iterators pointing to the median element(s), shifting the pointers by at most 1 step after each insertion.

### C++ Implementation
```cpp
class MedianFinder {
private:
    multiset<int> data;
    multiset<int>::iterator low, high;

public:
    MedianFinder() : low(data.end()), high(data.end()) {}
    
    void addNum(int num) {
        int n = data.size();
        data.insert(num);
        
        if (n == 0) {
            low = high = data.begin();
        } else if (n % 2 == 1) {
            if (num < *low) {
                low--;
            } else {
                high++;
            }
        } else {
            if (num > *low && num < *high) {
                low++;
                high--;
            } else if (num >= *high) {
                low++;
            } else {
                low--;
                high = low;
            }
        }
    }
    
    double findMedian() {
        return (*low + *high) / 2.0;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | `addNum`: $O(\log n)$, `findMedian`: $O(1)$ | Red-black tree insertion with iterator adjustments. |
| **Space** | $O(n)$ | Multiset node memory. |

| **Negative Stream Values** | `[-5, -10, -2]` | Sign logic | Max/Min heap comparisons function identically on negative numbers. |

## Pattern Takeaways

1. **The Dual Heap Pivot Pattern:**  
   Whenever an algorithm needs dynamic tracking of the **$p$-th percentile** (median = 50th percentile) in a live data stream, split the stream into two opposing heaps (Max-Heap for $\le P$, Min-Heap for $> P$).
