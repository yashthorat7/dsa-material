## What are we solving?

Given an array of intervals `intervals` where `intervals[i] = [starti, endi]`, return the **minimum number of intervals** you need to remove to make the rest of the intervals non-overlapping.

Note that intervals which only touch at a point are non-overlapping. For example, `[1, 2]` and `[2, 3]` are non-overlapping.

The greedy question is: **how does sorting by end time maximize the number of compatible non-overlapping intervals?**

**Example 1:**
```
Input:  intervals = [[1,2],[2,3],[3,4],[1,3]]
Output: 1
Explanation: [1,3] can be removed and the rest of the intervals are non-overlapping.
```

**Example 2:**
```
Input:  intervals = [[1,2],[1,2],[1,2]]
Output: 2
Explanation: You need to remove two [1,2] to make the rest of the intervals non-overlapping.
```

**Example 3:**
```
Input:  intervals = [[1,2],[2,3]]
Output: 0
```

**Constraints:**
- $1 \le \text{intervals.length} \le 10^5$
- $\text{intervals}[i].\text{length} == 2$
- $-5 \times 10^4 \le \text{start}_i < \text{end}_i \le 5 \times 10^4$

## Approach 1 — Greedy Sort by End Time ✅

**Key insight (Interval Scheduling):**
To minimize removals, maximize the number of kept intervals!
1. Sort intervals by their **end times** in ascending order.
2. Always keep the interval that finishes earliest (leaves maximum time for subsequent intervals).
3. Track `lastEnd`. For each interval `[start, end]`:
   - If `start >= lastEnd`: no overlap! Keep it and update `lastEnd = end`.
   - Else: overlap! Must remove this interval $\rightarrow$ `removals++`.

```
intervals = [[1,2], [2,3], [3,4], [1,3]]
Sorted by end: [[1,2], [2,3], [1,3], [3,4]]
lastEnd = -∞, removals = 0

1. [1,2]: 1 >= -∞ -> keep, lastEnd = 2
2. [2,3]: 2 >= 2  -> keep, lastEnd = 3
3. [1,3]: 1 < 3   -> OVERLAP! removals = 1 (remove [1,3])
4. [3,4]: 3 >= 3  -> keep, lastEnd = 4

Result: 1 removal ✓
```

```cpp
class Solution {
public:
    int eraseOverlapIntervals(vector<vector<int>>& intervals) {
        if (intervals.empty()) return 0;
        sort(intervals.begin(), intervals.end(), [](const auto& a, const auto& b) {
            return a[1] < b[1];
        });
        
        int removals = 0;
        int lastEnd = intervals[0][1];
        
        for (int i = 1; i < intervals.size(); i++) {
            if (intervals[i][0] >= lastEnd) {
                lastEnd = intervals[i][1];
            } else {
                removals++;
            }
        }
        
        return removals;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n \log n)$ | $O(1)$ |

> **This is the one.** Classic Interval Scheduling algorithm.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Touching intervals `[1, 2]` and `[2, 3]` | Overcounting overlap on equal boundaries | `start >= lastEnd` correctly treats touching points as non-overlapping |
| Duplicate intervals `[[1,2], [1,2], [1,2]]` | Duplicate retention | Removes 2 duplicates, keeps 1 |

---

## Pattern Takeaway

**Interval Scheduling Maximization** states: sorting intervals by **earliest finishing time (`end`)** greedily leaves the maximum remaining capacity for future intervals.
