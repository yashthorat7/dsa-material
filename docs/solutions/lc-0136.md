## What are we solving?

Given a **non-empty** array of integers `nums`, every element appears **twice** except for one unique element which appears exactly once. Find and return that **single element**.

```
 Input:  nums = [4, 1, 2, 1, 2]
 
 Pairs:  (1, 1) and (2, 2)
 Unique: (4)
 
 Output: 4
```

### Input & Output Contract
- **Input:**
  - `nums`: `vector<int>` where $1 \le n \le 3 \times 10^4$, $-3 \times 10^4 \le \text{nums}[i] \le 3 \times 10^4$.
- **Output:**
  - `int` representing the lone element appearing only once.
- **Constraints:** Must achieve **$O(n)$ linear runtime** and **$O(1)$ constant extra space**.

### The Core Challenge
While a hash map or sorting can identify the unique element in $O(n)$ space or $O(n \log n)$ time respectively, achieving both $O(n)$ time AND $O(1)$ space requires exploiting the algebraic cancellation properties of bitwise operations.

## Approach 1 — Hash Set (Add / Remove Pairs)

### Intuition
Iterate through `nums`. For each element:
- If it is already in the set, erase it (the pair is now complete).
- If it is not in the set, insert it.
- After visiting all numbers, exactly one element will remain in the set.

### C++ Implementation
```cpp
class Solution {
public:
    int singleNumber(vector<int>& nums) {
        unordered_set<int> seen;
        for (int num : nums) {
            if (seen.count(num)) {
                seen.erase(num);
            } else {
                seen.insert(num);
            }
        }
        return *seen.begin();
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | One pass with $O(1)$ average hash set lookups and insertions. |
| **Space** | $O(n)$ | Stores up to $n/2 + 1$ elements in the set. |

> **Verdict:** Intuitive $O(n)$ time, but violates the $O(1)$ constant space requirement.

## Approach 2 — Math Sum Difference

### Intuition
Every duplicate number appears twice. If we calculate the sum of unique numbers in the set and multiply by 2:
$$2 \times \sum(\text{unique}) - \sum(\text{nums}) = \text{single number}$$

```
nums = [4, 1, 2, 1, 2]
Set of unique elements = {4, 1, 2}
2 * (4 + 1 + 2) = 2 * 7 = 14
Sum of nums = 4 + 1 + 2 + 1 + 2 = 10
Result = 14 - 10 = 4 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int singleNumber(vector<int>& nums) {
        unordered_set<long long> uniqueNums(nums.begin(), nums.end());
        long long setSum = 0;
        for (long long x : uniqueNums) setSum += x;
        
        long long totalSum = 0;
        for (long long x : nums) totalSum += x;
        
        return 2 * setSum - totalSum;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Two passes to sum the set and array. |
| **Space** | $O(n)$ | Set allocates $n/2$ unique elements. |

## Approach 3 — Bitwise XOR Accumulator ✅

### Key Insight
The Bitwise XOR operation ($\oplus$) obeys three fundamental algebraic properties:
1. **Self-Inverse / Cancellation:** $x \oplus x = 0$ (Any number XORed with itself cancels out to 0).
2. **Identity Element:** $x \oplus 0 = x$ (Any number XORed with 0 remains unchanged).
3. **Commutative & Associative:** Order of operations does not matter ($A \oplus B \oplus A = (A \oplus A) \oplus B = 0 \oplus B = B$).

If we compute the cumulative XOR of all elements:
$$(a_1 \oplus a_1) \oplus (a_2 \oplus a_2) \oplus \dots \oplus \text{unique} = 0 \oplus 0 \oplus \dots \oplus \text{unique} = \mathbf{\text{unique}}$$

```
nums = [4, 1, 2, 1, 2]
Initialize: acc = 0

acc = 0 ^ 4 = 4       (0100)
acc = 4 ^ 1 = 5       (0101)
acc = 5 ^ 2 = 7       (0111)
acc = 7 ^ 1 = 6       (0110: 1 cancels out)
acc = 6 ^ 2 = 4       (0100: 2 cancels out)

Result = 4 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int singleNumber(vector<int>& nums) {
        int result = 0;
        for (int num : nums) {
            result ^= num;
        }
        return result;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Single pass visiting each integer in the vector once. |
| **Space** | $O(1)$ | Uses a single integer accumulator variable on the stack. |

> **This is the one.** Strictly optimal $O(n)$ time and $O(1)$ memory.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Single Element Array** | `nums = [1]` | Loop bounds | `0 ^ 1 = 1`, correctly returns 1. |
| **Negative Integers** | `[-1, -1, -2]` | Two's complement representation | Bitwise XOR operates identically on bit level regardless of sign. |
| **Unique is Zero** | `[5, 5, 0]` | Zero identity confusion | `5 ^ 5 ^ 0 = 0 ^ 0 = 0`, returns 0. |
