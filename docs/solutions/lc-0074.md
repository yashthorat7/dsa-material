## What are we solving?

You are given an `m x n` integer matrix `matrix` with the following two structural guarantees:
1. Each row is sorted in strictly non-decreasing order.
2. The first integer of each row is strictly greater than the last integer of the previous row.

Given an integer `target`, return `true` if `target` is in `matrix`, or `false` otherwise.

You must write a solution in **$O(\log(m \cdot n))$ time complexity**.

```
 Matrix (m=3, n=4):
 [  1,   3,   5,   7 ]
 [ 10,  11,  16,  20 ]
 [ 23,  30,  34,  60 ]
 
 Target = 3:
 Flattens to virtual 1D array:
 [ 1, 3, 5, 7, 10, 11, 16, 20, 23, 30, 34, 60 ]
      ^
      Found at index 1 -> row = 1/4 = 0, col = 1%4 = 1 -> Output: true
```

### Input & Output Contract
- **Input:**
  - `matrix`: `vector<vector<int>>` of dimensions $m \times n$ ($1 \le m, n \le 100$, $-10^4 \le \text{matrix}[i][j] \le 10^4$).
  - `target`: `int` search key ($-10^4 \le \text{target} \le 10^4$).
- **Output:**
  - `bool`: `true` if `target` exists in the matrix; otherwise `false`.
- **Constraint:** Must run in $O(\log(m \cdot n))$ time.

### The Core Challenge
Because the last element of row $i$ is smaller than the first element of row $i+1$, the entire $m \times n$ matrix is strictly monotonic. We can treat the 2D matrix as a **virtual 1D array** of length $m \cdot n$ and execute binary search with constant-time coordinate projection.

---

**Example 1:**
```
Input:  matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 3
Output: true
```

**Example 2:**
```
Input:  matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 13
Output: false
```

**Constraints:**
- $m == \text{matrix.length}$
- $n == \text{matrix}[i].\text{length}$
- $1 \le m, n \le 100$
- $-10^4 \le \text{matrix}[i][j], \text{target} \le 10^4$

## Approach 1 — Two Binary Searches (Row Search, then Column Search)

### Intuition
1. Binary search the first column `matrix[r][0]` to identify the unique row $r$ that could potentially contain `target` (where $\text{matrix}[r][0] \le \text{target} \le \text{matrix}[r][n-1]$).
2. Binary search across the $n$ elements in `matrix[r]` for `target`.

### C++ Implementation
```cpp
class Solution {
public:
    bool searchMatrix(vector<vector<int>>& matrix, int target) {
        int m = matrix.size(), n = matrix[0].size();
        
        // Pass 1: Binary search to find candidate row
        int top = 0, bot = m - 1;
        int targetRow = -1;
        
        while (top <= bot) {
            int mid = top + (bot - top) / 2;
            if (target >= matrix[mid][0] && target <= matrix[mid][n - 1]) {
                targetRow = mid;
                break;
            } else if (target < matrix[mid][0]) {
                bot = mid - 1;
            } else {
                top = mid + 1;
            }
        }
        
        if (targetRow == -1) return false;
        
        // Pass 2: Binary search within the identified row
        int left = 0, right = n - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (matrix[targetRow][mid] == target) return true;
            else if (matrix[targetRow][mid] < target) left = mid + 1;
            else right = mid - 1;
        }
        
        return false;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\log m + \log n)$ | Row binary search $O(\log m)$ + Column binary search $O(\log n) = O(\log(m \cdot n))$. |
| **Space** | $O(1)$ | No memory allocated. |

## Approach 2 — Flattened Virtual 1D Binary Search ✅

### Key Insight
Map any 1D index `idx` in range $[0, m \cdot n - 1]$ to its 2D grid coordinates $(r, c)$ in $O(1)$:
$$\text{row} = \lfloor \text{idx} / n \rfloor, \quad \text{col} = \text{idx} \pmod n$$

Execute standard binary search with `low = 0` and `high = m * n - 1`.

```
matrix = [ [1, 3, 5, 7], [10, 11, 16, 20], [23, 30, 34, 60] ] (m=3, n=4, total=12)
target = 3
low = 0, high = 11

Iteration 1:
- mid = 0 + (11 - 0) / 2 = 5
- r = 5 / 4 = 1, c = 5 % 4 = 1 -> matrix[1][1] = 11
- 11 > 3 -> high = mid - 1 = 4

Iteration 2:
- mid = 0 + (4 - 0) / 2 = 2
- r = 2 / 4 = 0, c = 2 % 4 = 2 -> matrix[0][2] = 5
- 5 > 3 -> high = mid - 1 = 1

Iteration 3:
- mid = 0 + (1 - 0) / 2 = 0
- r = 0 / 4 = 0, c = 0 % 4 = 0 -> matrix[0][0] = 1
- 1 < 3 -> low = mid + 1 = 1

Iteration 4:
- mid = 1
- r = 1 / 4 = 0, c = 1 % 4 = 1 -> matrix[0][1] = 3
- 3 == 3 -> MATCH! Return true ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    bool searchMatrix(vector<vector<int>>& matrix, int target) {
        if (matrix.empty() || matrix[0].empty()) return false;
        
        int m = matrix.size();
        int n = matrix[0].size();
        int low = 0;
        int high = m * n - 1;
        
        while (low <= high) {
            int mid = low + (high - low) / 2;
            
            // Map 1D virtual index back to 2D coordinates
            int r = mid / n;
            int c = mid % n;
            
            if (matrix[r][c] == target) {
                return true;
            } else if (matrix[r][c] < target) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        
        return false;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\log(m \cdot n))$ | Halves the $m \cdot n$ virtual space each iteration. |
| **Space** | $O(1)$ | Pure stack index variables. |

> **This is the one.** Cleanest implementation, single loop, strictly optimal time and space.

## Approach 3 — Top-Right Corner Walk (Z-Search)

### Intuition
Start at the top-right corner `(r = 0, c = n - 1)`:
- If `matrix[r][c] == target`, return `true`.
- If `matrix[r][c] > target`, all elements below are also $> \text{target} \rightarrow$ move left: `c--`.
- If `matrix[r][c] < target`, all elements to the left are also $< \text{target} \rightarrow$ move down: `r++`.

### C++ Implementation
```cpp
class Solution {
public:
    bool searchMatrix(vector<vector<int>>& matrix, int target) {
        int m = matrix.size(), n = matrix[0].size();
        int r = 0, c = n - 1;
        
        while (r < m && c >= 0) {
            if (matrix[r][c] == target) return true;
            else if (matrix[r][c] > target) c--;
            else r++;
        }
        
        return false;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(m + n)$ | Moves at most $m$ steps down and $n$ steps left. |
| **Space** | $O(1)$ | Constant extra space. |

> **Verdict:** Generalizes to [LC 240: Search a 2D Matrix II](file:///e:/Projects/dsa-notes/docs/solutions/lc-0240.md), but is $O(m + n)$ rather than $O(\log(m \cdot n))$.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **$1 \times 1$ Matrix** | `matrix = [[5]], target = 5` | Loop bounds | `low = 0, high = 0`, finds element at `mid = 0`. |
| **Target Smaller than Minimum** | `target = 0` | Index underflow | Binary search sets `high = -1`, returns `false`. |
| **Target Larger than Maximum** | `target = 100` | Index overflow | Binary search sets `low = m * n`, returns `false`. |

## Pattern Takeaways

1. **Virtual 1D Coordinate Projection:**  
   Any row-major $M \times N$ matrix can be mapped to 1D index `idx` with `r = idx / N, c = idx % N`.
2. **Difference from Search a 2D Matrix II:**  
   - [LC 74: Search a 2D Matrix](file:///e:/Projects/dsa-notes/docs/solutions/lc-0074.md): Globally sorted $\rightarrow O(\log(m \cdot n))$ via Flattened Binary Search.
   - [LC 240: Search a 2D Matrix II](file:///e:/Projects/dsa-notes/docs/solutions/lc-0240.md): Only individual rows and columns are sorted independently $\rightarrow O(m + n)$ via Top-Right Stepwise Walk.
