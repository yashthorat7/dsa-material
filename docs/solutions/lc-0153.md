## What are we solving?

Suppose an array of length `n` sorted in ascending order is rotated between `1` and `n` times. Given the sorted rotated array `nums` of **unique** elements, return the **minimum element** of this array.

You must write an algorithm that runs in **$O(\log n)$ time**.

**Example 1:**
```
Input:  nums = [3,4,5,1,2]
Output: 1
Explanation: The original array was [1,2,3,4,5] rotated 3 times.
```

**Example 2:**
```
Input:  nums = [4,5,6,7,0,1,2]
Output: 0
Explanation: The original array was [0,1,2,4,5,6,7] and it was rotated 4 times.
```

**Example 3:**
```
Input:  nums = [11,13,15,17]
Output: 11
Explanation: The original array was [11,13,15,17] and it was rotated 4 times.
```

**Constraints:**
- $n == \text{nums.length}$
- $1 \le n \le 5000$
- $-5000 \le \text{nums}[i] \le 5000$
- All the integers of `nums` are unique.

## Approach 1 — Binary Search Against Right Boundary ✅

**Key insight:**
Compare `nums[mid]` with `nums[high]`:
- If `nums[mid] > nums[high]`: the inflection point (minimum) must lie strictly to the right of `mid` -> `low = mid + 1`.
- If `nums[mid] <= nums[high]`: the minimum is at `mid` or to its left -> `high = mid`.
When `low == high`, `nums[low]` is the minimum!

```
nums = [4, 5, 6, 7, 0, 1, 2]
low = 0 (4), high = 6 (2)

1. mid = 3 (val = 7). 7 > 2 -> low = mid + 1 = 4
2. low = 4 (0), high = 6 (2). mid = 5 (val = 1). 1 <= 2 -> high = mid = 5
3. low = 4 (0), high = 5 (1). mid = 4 (val = 0). 0 <= 1 -> high = mid = 4
low == high == 4.

Result: nums[4] = 0 ✓
```

```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int low = 0, high = nums.size() - 1;
        while (low < high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] > nums[high]) {
                low = mid + 1;
            } else {
                high = mid;
            }
        }
        return nums[low];
    }
};
```

| Time | Space |
|:-----|:------|
| $O(\log n)$ | $O(1)$ |

> **This is the one.** Elegant boundary comparison with no extra variables.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Array not rotated (already sorted) `[1, 2, 3]` | High moving past index 0 | `nums[mid] <= nums[high]` repeatedly contracts high to 0, returning `nums[0] = 1` |
| Single element `[1]` | Loop condition `low < high` | Terminates immediately, returns 1 |
| Two elements `[2, 1]` | Off-by-one mid | `mid = 0`, `nums[0] > nums[1]` -> `low = 1`, returns `nums[1] = 1` |

---

## Pattern Takeaway

Comparing `nums[mid]` against **`nums[high]`** reveals which side of the inflection point you are on in a rotated sorted array.
