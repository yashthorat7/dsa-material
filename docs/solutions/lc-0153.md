## What are we solving?

Suppose an array of length $n$ sorted in ascending order with **unique elements** is rotated between $1$ and $n$ times.

Given the sorted rotated array `nums`, return the **minimum element** of this array.

You must write an algorithm that runs in **$O(\log n)$ time**.

```
 Original Sorted: [ 0,  1,  2,  4,  5,  6,  7 ]
 Rotated 4 Times: [ 4,  5,  6,  7,  0,  1,  2 ]
                                    ^
                             Inflection Point (Minimum = 0)
```

### Input & Output Contract
- **Input:**
  - `nums`: `vector<int>` where $1 \le n \le 5000$, $-5000 \le \text{nums}[i] \le 5000$.
  - All integers in `nums` are guaranteed to be unique.
- **Output:**
  - `int` representing the minimum value in `nums`.
- **Constraint:** Must run in strictly $O(\log n)$ time.

### The Core Challenge
In a normally sorted array, every element satisfies $nums[i] < nums[i+1]$. Rotation introduces exactly **one inflection point** where $nums[i] > nums[i+1]$, and the element $nums[i+1]$ is the global minimum. We must pinpoint this inflection point using binary search by comparing `nums[mid]` against the right boundary `nums[high]`.

---

**Example 1:**
```
Input:  nums = [3,4,5,1,2]
Output: 1
Explanation: The original array was [1,2,3,4,5] rotated 3 times.
```

**Example 2:**
```
Input:  nums = [4,5,6,7,0,1,2]
Output: 0
Explanation: The original array was [0,1,2,4,5,6,7] and it was rotated 4 times.
```

**Example 3:**
```
Input:  nums = [11,13,15,17]
Output: 11
Explanation: The original array was [11,13,15,17] and it was rotated 4 times.
```

**Constraints:**
- $n == \text{nums.length}$
- $1 \le n \le 5000$
- $-5000 \le \text{nums}[i] \le 5000$
- All the integers of `nums` are unique.

## Approach 1 — Linear Scan (Brute Force)

### Intuition
Traverse the array from left to right tracking the minimum value seen so far.

### C++ Implementation
```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int minVal = nums[0];
        for (int x : nums) {
            minVal = min(minVal, x);
        }
        return minVal;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Linear scan. |
| **Space** | $O(1)$ | No memory allocated. |

> **Verdict:** Fails the $O(\log n)$ requirement.

## Approach 2 — Binary Search Against Right Boundary ✅

### Key Insight
Compare the middle element `nums[mid]` against the rightmost element `nums[high]`:
1. If **`nums[mid] > nums[high]`**:
   The minimum element *must* lie strictly to the right of `mid` (the drop happens in the right half) $\rightarrow$ `low = mid + 1`.
2. If **`nums[mid] <= nums[high]`**:
   The right half is normally sorted, which means the minimum element is either `mid` itself or lies to the left of `mid` $\rightarrow$ `high = mid` (do **not** do `mid - 1`, because `mid` itself could be the minimum!).
3. When `low == high`, `nums[low]` is guaranteed to be the minimum!

```
nums = [4, 5, 6, 7, 0, 1, 2]
low = 0 (4), high = 6 (2)

Iteration 1:
- mid = 0 + (6 - 0) / 2 = 3 (val = 7)
- 7 > 2 -> drop is to the right -> low = mid + 1 = 4

Iteration 2:
- low = 4 (0), high = 6 (2)
- mid = 4 + (6 - 4) / 2 = 5 (val = 1)
- 1 <= 2 -> drop is at or left of mid -> high = mid = 5

Iteration 3:
- low = 4 (0), high = 5 (1)
- mid = 4 + (5 - 4) / 2 = 4 (val = 0)
- 0 <= 1 -> high = mid = 4

low == high == 4 -> Loop terminates!

Result: nums[4] = 0 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int low = 0;
        int high = nums.size() - 1;
        
        while (low < high) {
            int mid = low + (high - low) / 2;
            
            // Drop occurs in the right half
            if (nums[mid] > nums[high]) {
                low = mid + 1;
            } else {
                // Minimum is at mid or in the left half
                high = mid;
            }
        }
        
        return nums[low];
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\log n)$ | Interval is halved in each step. |
| **Space** | $O(1)$ | Pure stack index variables. |

> **This is the one.** Clean `low < high` template with no special cases.

## Approach 3 — Explicit Inflection Point Detection

### Intuition
If the array is already sorted (`nums[low] < nums[high]`), return `nums[low]` immediately.  
Otherwise, inside the binary search:
- If `nums[mid] > nums[mid + 1]`, return `nums[mid + 1]`.
- If `nums[mid - 1] > nums[mid]`, return `nums[mid]`.

### C++ Implementation
```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int n = nums.size();
        if (n == 1) return nums[0];
        
        int low = 0, high = n - 1;
        if (nums[high] > nums[0]) return nums[0]; // Already sorted
        
        while (low <= high) {
            int mid = low + (high - low) / 2;
            
            if (mid < n - 1 && nums[mid] > nums[mid + 1]) {
                return nums[mid + 1];
            }
            if (mid > 0 && nums[mid - 1] > nums[mid]) {
                return nums[mid];
            }
            
            if (nums[mid] > nums[0]) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        
        return nums[0];
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(\log n)$ | Logarithmic search with early exit. |
| **Space** | $O(1)$ | Constant extra space. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Array Already Sorted (No Rotation)** | `[11, 13, 15, 17]` | `high` collapsing past 0 | `nums[mid] <= nums[high]` repeatedly moves `high = mid` until `low == high == 0`, returns 11. |
| **Single Element** | `[1]` | `low < high` (0 < 0 is false) | Loop never executes, returns `nums[0] = 1`. |
| **Two Elements** | `[2, 1]` | Mid index calculation | `mid = 0`, `nums[0] > nums[1]` -> `low = 1`, loop terminates, returns `nums[1] = 1`. |

---

## Pattern Takeaways

1. **Comparing against `nums[high]` vs `nums[low]`:**  
   Always compare `nums[mid]` against **`nums[high]`** when looking for the minimum in a rotated sorted array. If you compared against `nums[low]`, an already-sorted array would mislead the pointer.
2. **The `high = mid` Invariant:**  
   When the target condition could be true at `mid` itself, use `while (low < high)` with `high = mid` to prevent skipping the candidate answer.
