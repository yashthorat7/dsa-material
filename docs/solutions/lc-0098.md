## What are we solving?

Given the `root` of a binary tree, determine if it is a **valid Binary Search Tree (BST)**.

A **valid BST** is defined as follows:
1. The left subtree of a node contains only nodes with keys **strictly less than** the node's key.
2. The right subtree of a node contains only nodes with keys **strictly greater than** the node's key.
3. Both the left and right subtrees must also be binary search trees.

```
 Valid BST:                Invalid BST:
       (5)                       (5)
      /   \                     /   \
    (1)   (7)                 (1)   (4)  <-- 4 is in right subtree of 5!
         /   \                     /   \
       (6)   (9)                 (3)   (6)
```

### Input & Output Contract
- **Input:**
  - `root`: `TreeNode*` pointing to the root of a binary tree ($1 \le \text{node count} \le 10^4$, $-2^{31} \le \text{Node.val} \le 2^{31} - 1$).
- **Output:**
  - `bool`: `true` if every node in the tree strictly satisfies BST invariants; otherwise `false`.

### The Core Challenge
Checking only local parent-child relationships (e.g. `node->left->val < node->val`) is **insufficient**. In an invalid tree like `[5, 1, 6, null, null, 3, 7]`, child `3` is less than parent `6` locally, but violates the global constraint of being in the right subtree of root `5`. Every node must be strictly bounded by an **inherited valid interval $(\text{minVal}, \text{maxVal})$**.

---

**Example 1:**
```
Input:  root = [2,1,3]
Output: true
```

**Example 2:**
```
Input:  root = [5,1,4,null,null,3,6]
Output: false
Explanation: The root node's value is 5 but its right child's value is 4 (4 <= 5).
```

**Constraints:**
- The number of nodes in the tree is in the range $[1, 10^4]$.
- $-2^{31} \le \text{Node.val} \le 2^{31} - 1$

## Approach 1 — Recursive DFS with Bounded Range $(-\infty, +\infty)$ ✅

### Key Insight
Pass a valid value range `(minVal, maxVal)` down the recursion:
- Root node starts with range `(LONG_MIN, LONG_MAX)` (using 64-bit integers to safely accommodate `INT_MIN` and `INT_MAX` node values).
- When branching **Left**, the upper bound shrinks to `node->val`: `(minVal, node->val)`.
- When branching **Right**, the lower bound rises to `node->val`: `(node->val, maxVal)`.
- If `node->val <= minVal || node->val >= maxVal`, the tree is immediately invalid!

```
Tree: [5, 1, 4, null, null, 3, 6]

validate(5, -∞, +∞)
 ├─ validate(1, -∞, 5): valid (-∞ < 1 < 5) ✓
 └─ validate(4, 5, +∞): 4 <= 5 -> VIOLATION! Returns false ✗

Output: false ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    bool isValidBST(TreeNode* root) {
        return validate(root, LONG_MIN, LONG_MAX);
    }

private:
    bool validate(TreeNode* node, long long minVal, long long maxVal) {
        if (node == nullptr) return true;
        
        // Check strict BST interval boundaries
        if (node->val <= minVal || node->val >= maxVal) {
            return false;
        }
        
        // Left subtree must be < node->val, Right subtree must be > node->val
        return validate(node->left, minVal, node->val) &&
               validate(node->right, node->val, maxVal);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Visits every node at most once; early exit on first violation. |
| **Space** | $O(h)$ | Recursion stack depth equals tree height $h$ ($O(\log n)$ balanced, $O(n)$ skewed). |

> **This is the one.** Clean, robust range propagation with 64-bit boundaries.

## Approach 2 — In-Order Traversal with Previous Value Tracking

### Intuition
An in-order traversal (Left $\rightarrow$ Root $\rightarrow$ Right) of any valid BST must visit node values in **strictly monotonically increasing order**.  
Maintain a pointer to `prevNode`. For each visited node, verify `prevNode == nullptr || node->val > prevNode->val`, then update `prevNode = node`.

### C++ Implementation
```cpp
class Solution {
private:
    TreeNode* prev = nullptr;
public:
    bool isValidBST(TreeNode* root) {
        return inOrder(root);
    }

private:
    bool inOrder(TreeNode* node) {
        if (node == nullptr) return true;
        
        if (!inOrder(node->left)) return false;
        
        if (prev != nullptr && node->val <= prev->val) {
            return false;
        }
        prev = node;
        
        return inOrder(node->right);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Linear in-order traversal. |
| **Space** | $O(h)$ | Recursion stack depth $h$. |

## Approach 3 — Iterative In-Order Traversal with Stack

### Intuition
Convert the in-order traversal into an explicit stack loop. Track the last popped value to ensure strictly increasing order.

### C++ Implementation
```cpp
class Solution {
public:
    bool isValidBST(TreeNode* root) {
        stack<TreeNode*> st;
        TreeNode* curr = root;
        TreeNode* prev = nullptr;
        
        while (curr != nullptr || !st.empty()) {
            while (curr != nullptr) {
                st.push(curr);
                curr = curr->left;
            }
            
            curr = st.top();
            st.pop();
            
            if (prev != nullptr && curr->val <= prev->val) {
                return false;
            }
            prev = curr;
            
            curr = curr->right;
        }
        
        return true;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Pushes and pops each node once. |
| **Space** | $O(h)$ | Stack size bounded by height $h$. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **`INT_MIN` / `INT_MAX` Node Values** | `[INT_MIN]` or `[INT_MAX]` | 32-bit boundary overflow | `LONG_MIN` / `LONG_MAX` bounds prevent integer overflow. |
| **Duplicate Values** | `[2, 2, 2]` | Non-strict comparison | Strict inequality `<= minVal || >= maxVal` correctly flags duplicates as invalid. |
| **Single Node** | `[1]` | Null children checks | Evaluates to `true` immediately. |

## Pattern Takeaways

1. **The BST In-Order Invariant:**  
   $\text{In-Order}(\text{BST}) \equiv \text{Strictly Ascending Sequence}$. This property is also used to find $K$-th smallest elements ([LC 230](file:///e:/Projects/dsa-notes/docs/solutions/lc-0230.md)) and recover swapped nodes ([LC 99](file:///e:/Projects/dsa-notes/docs/solutions/lc-0099.md)).
2. **Global Range Propagation:**  
   Always propagate `(minVal, maxVal)` intervals downward when validating tree-wide constraints.
