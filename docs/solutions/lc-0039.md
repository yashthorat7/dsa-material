## What are we solving?

Given an array of **distinct** integers `candidates` and a target integer `target`, return a list of all **unique combinations** of `candidates` where the chosen numbers sum to `target`. You may return the combinations in any order.

The **same number may be chosen from `candidates` an unlimited number of times**. Two combinations are unique if the frequency of at least one of the chosen numbers is different.

```
 candidates = [2, 3, 6, 7], target = 7
 
 Combinations summing to 7:
 1. [2, 2, 3]  (2 + 2 + 3 = 7)
 2. [7]        (7 = 7)
 
 Output: [[2, 2, 3], [7]]
```

### Input & Output Contract
- **Input:**
  - `candidates`: `vector<int>` containing distinct positive integers ($1 \le n \le 30$, $2 \le \text{candidates}[i] \le 40$).
  - `target`: `int` positive target sum ($1 \le \text{target} \le 40$).
- **Output:**
  - `vector<vector<int>>` containing all unique combinations.

### The Core Challenge
Because numbers can be reused indefinitely, the search tree can grow deep (max depth is $\text{target} / \min(\text{candidates}) = 40 / 2 = 20$). We must prevent generating permuted duplicate combinations (e.g. `[2, 3, 2]` vs `[2, 2, 3]`) while aggressively pruning branches that overshoot the remaining target sum.

---

**Example 1:**
```
Input:  candidates = [2,3,6,7], target = 7
Output: [[2,2,3],[7]]
Explanation: 
2 and 3 are candidates, and 2 + 2 + 3 = 7 (2 is used multiple times).
7 is a candidate, and 7 = 7.
These are the only two combinations.
```

**Example 2:**
```
Input:  candidates = [2,3,5], target = 8
Output: [[2,2,2,2],[2,3,3],[3,5]]
```

**Example 3:**
```
Input:  candidates = [2], target = 1
Output: []
```

**Constraints:**
- $1 \le \text{candidates.length} \le 30$
- $2 \le \text{candidates}[i] \le 40$
- All elements of `candidates` are **distinct**.
- $1 \le \text{target} \le 40$

## Approach 1 — Binary Choice Backtracking (Take or Skip)

### Intuition
At index `i`, we make two distinct recursive choices:
1. **Take `candidates[i]`:** Add `candidates[i]` to `current`, subtract from `target`, and stay at index `i` (to allow reuse).
2. **Skip `candidates[i]`:** Move to `i + 1` without choosing `candidates[i]`.

```
                       (idx=0, remain=7)
                      /                 \
        Take 2: (idx=0, remain=5)     Skip 2: (idx=1, remain=7)
               /        \                       /       \
  Take 2: (0, 3)     Skip 2: (1, 5)        Take 3: (1, 4) ...
```

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<int>> combinationSum(vector<int>& candidates, int target) {
        vector<vector<int>> result;
        vector<int> current;
        dfs(0, target, candidates, current, result);
        return result;
    }

private:
    void dfs(int i, int remain, const vector<int>& candidates, 
             vector<int>& current, vector<vector<int>>& result) {
        if (remain == 0) {
            result.push_back(current);
            return;
        }
        if (i >= candidates.size() || remain < 0) {
            return;
        }
        
        // Choice 1: Take candidates[i] (stay at index i)
        current.push_back(candidates[i]);
        dfs(i, remain - candidates[i], candidates, current, result);
        current.pop_back(); // Backtrack
        
        // Choice 2: Skip candidates[i] (advance to i + 1)
        dfs(i + 1, remain, candidates, current, result);
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(2^{\text{target}/\min})$ | Binary decision tree branching at every step. |
| **Space** | $O(\text{target}/\min)$ | Call stack depth bounded by $\text{target}/\min(\text{candidates})$. |

## Approach 2 — Sorted Loop Backtracking with Early Pruning ✅

### Key Insight
1. **Sort `candidates` ascending** first.
2. In the `for` loop starting from `start` index:
   - If `candidates[i] > remain`, **`break` immediately**! (Since the array is sorted, every subsequent candidate will also exceed `remain`, eliminating entire dead subtrees).
   - Recurse with `backtrack(i, remain - candidates[i])` — passing `i` instead of `i + 1` allows unlimited reuse of the current element.

```
candidates = [2, 3, 6, 7], target = 7

backtrack(start=0, remain=7):
 ├─ i=0 (val 2): current=[2] -> backtrack(start=0, remain=5)
 │   ├─ i=0 (val 2): current=[2,2] -> backtrack(start=0, remain=3)
 │   │   ├─ i=0 (val 2): current=[2,2,2] -> backtrack(start=0, remain=1)
 │   │   │   └─ i=0 (val 2 > 1): BREAK!
 │   │   └─ i=1 (val 3): current=[2,2,3] -> remain=0 ==> MATCH: [2,2,3]
 │   └─ i=1 (val 3): current=[2,3] -> backtrack(start=1, remain=2)
 │       └─ i=1 (val 3 > 2): BREAK!
 ├─ i=1 (val 3): current=[3] -> backtrack(start=1, remain=4)
 │   └─ i=1 (val 3): current=[3,3] -> remain=1 -> i=1 (val 3 > 1): BREAK!
 └─ i=3 (val 7): current=[7] -> remain=0 ==> MATCH: [7]

Output: [[2, 2, 3], [7]] ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<int>> combinationSum(vector<int>& candidates, int target) {
        sort(candidates.begin(), candidates.end()); // Crucial for early pruning
        vector<vector<int>> result;
        vector<int> current;
        backtrack(0, target, candidates, current, result);
        return result;
    }

private:
    void backtrack(int start, int remain, const vector<int>& candidates, 
                  vector<int>& current, vector<vector<int>>& result) {
        if (remain == 0) {
            result.push_back(current);
            return;
        }
        
        for (int i = start; i < candidates.size(); i++) {
            // Early pruning: candidates are sorted, so all subsequent elements are too large
            if (candidates[i] > remain) {
                break;
            }
            
            current.push_back(candidates[i]);
            // Pass i (not i + 1) to permit reuse of the same element
            backtrack(i, remain - candidates[i], candidates, current, result);
            current.pop_back(); // Backtrack
        }
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(N^{\frac{\text{target}}{M}})$ | Where $N$ is candidate count and $M = \min(\text{candidates})$. Pruning heavily reduces actual executed states. |
| **Space** | $O(\frac{\text{target}}{M})$ | Maximum recursion depth is $\text{target} / \min(\text{candidates})$. |

> **This is the one.** Clean, fast, with early loop pruning and zero duplicate permutations.

## Approach 3 — Dynamic Programming (Unbounded Knapsack Style)

### Intuition
Maintain a DP table `dp[t]` where each entry holds a list of all valid combinations summing to `t`. For each candidate `c`, update all `dp[t]` from `c` to `target`.

### C++ Implementation
```cpp
class Solution {
public:
    vector<vector<int>> combinationSum(vector<int>& candidates, int target) {
        vector<vector<vector<int>>> dp(target + 1);
        dp[0] = {{}}; // Base case: 1 way to form 0 (empty combination)
        
        for (int c : candidates) {
            for (int t = c; t <= target; t++) {
                for (auto combo : dp[t - c]) {
                    combo.push_back(c);
                    dp[t].push_back(combo);
                }
            }
        }
        
        return dp[target];
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(N \cdot \text{target} \cdot K)$ | Copies combinations across DP state transitions. |
| **Space** | $O(\text{target} \cdot K)$ | Stores intermediate combinations for all values from $0$ to `target`. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Target Smaller than Min Element** | `candidates = [5], target = 3` | Pointless recursion | `candidates[0] > remain` breaks immediately on first iteration, returns `[]`. |
| **Exact Candidate Match** | `candidates = [7], target = 7` | Overshooting bounds | Matches `remain == 0`, records `[7]`. |
| **Deep Monolithic Combinations** | `candidates = [2], target = 40` | Deep recursion | Recursion reaches depth 20, correctly collects twenty 2s `[2, 2, ..., 2]`. |

## Pattern Takeaways

1. **Unlimited Reuse Invariant:**  
   Passing **`i` (current index)** into the recursive call allows unlimited reuse of element `candidates[i]` while strictly forbidding looking backward to elements $< i$, thereby preventing duplicate permutations like `[3, 2, 2]` vs `[2, 2, 3]`.
2. **Comparison with Combination Sum II:**  
   - [LC 39: Combination Sum](file:///e:/Projects/dsa-notes/docs/solutions/lc-0039.md): Elements can be reused $\rightarrow$ recurse with `i`.
   - [LC 40: Combination Sum II](file:///e:/Projects/dsa-notes/docs/solutions/lc-0040.md): Each element used once $\rightarrow$ recurse with `i + 1` and skip duplicate values.
