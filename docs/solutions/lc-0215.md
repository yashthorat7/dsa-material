# 215. Kth Largest Element in an Array

## What are we solving?

Given an integer array `nums` and an integer `k`, return the $k$-th largest element in the array. Note that it is the $k$-th largest element in the sorted order, not the $k$-th distinct element.

Can you solve it without sorting in **$O(n)$ average time**?

**Example 1:**
```
Input:  nums = [3,2,1,5,6,4], k = 2
Output: 5
```

**Example 2:**
```
Input:  nums = [3,2,3,1,2,4,5,5,6], k = 4
Output: 4
```

**Constraints:**
- $1 \le k \le \text{nums.length} \le 10^5$
- $-10^4 \le \text{nums}[i] \le 10^4$

## Approach 1 — Min-Heap of Size K ✅

**Key insight:**
Maintain a min-heap of size $k$.
For each element `x` in `nums`:
- Push `x` into heap.
- If `heap.size() > k`, pop the smallest element.
At the end, the heap contains the $k$ largest elements of the array, with the $k$-th largest at `heap.top()`!

```
nums = [3, 2, 1, 5, 6, 4], k = 2
min-heap:

x=3: [3]
x=2: [2, 3]
x=1: [1, 2, 3] -> size > 2 -> pop 1 -> [2, 3]
x=5: [2, 3, 5] -> pop 2 -> [3, 5]
x=6: [3, 5, 6] -> pop 3 -> [5, 6]
x=4: [4, 5, 6] -> pop 4 -> [5, 6]

Top of min-heap = 5 ✓
```

```cpp
class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        priority_queue<int, vector<int>, greater<int>> minHeap;
        for (int x : nums) {
            minHeap.push(x);
            if (minHeap.size() > k) {
                minHeap.pop();
            }
        }
        return minHeap.top();
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n \log k)$ | $O(k)$ |

> **This is the one.** Clean, robust $O(n \log k)$ streaming solution.

## Approach 2 — Quickselect (Hoare's Selection)

Partition array around pivot like QuickSort. If pivot index equals target index $n - k$, return `nums[pivot]`. Otherwise recurse into only the relevant half.

```
Average recurrence: T(n) = T(n/2) + O(n) = O(n) average runtime.
```

```cpp
class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        int target = nums.size() - k;
        int left = 0, right = nums.size() - 1;
        while (left <= right) {
            int pivotIdx = left + rand() % (right - left + 1);
            int p = partition(nums, left, right, pivotIdx);
            if (p == target) return nums[p];
            else if (p < target) left = p + 1;
            else right = p - 1;
        }
        return -1;
    }
private:
    int partition(vector<int>& nums, int l, int r, int pIdx) {
        int pivotVal = nums[pIdx];
        swap(nums[pIdx], nums[r]);
        int store = l;
        for (int i = l; i < r; i++) {
            if (nums[i] < pivotVal) {
                swap(nums[i], nums[store++]);
            }
        }
        swap(nums[store], nums[r]);
        return store;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ average, $O(n^2)$ worst case | $O(1)$ |

> Theoretical $O(n)$ average, but min-heap is simpler and deterministic in interviews.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| `k = 1` | Max element | Min-heap of size 1 tracks max element |
| `k == nums.length` | Min element | Returns smallest element |
| All identical elements `[1, 1, 1, 1], k = 2` | Deduplication | Returns 1 (duplicate values counted individually) |

---

## Pattern Takeaway

A **Min-Heap of size K** acts as a filter where smaller elements are constantly discarded, leaving the $K$-th largest at the top.
