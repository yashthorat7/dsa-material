## What are we solving?

Assume you are an awesome parent and want to give your children some cookies. But, you should give each child at most one cookie. Each child `i` has a greed factor `g[i]`, which is the minimum size of a cookie that the child will be content with; and each cookie `j` has a size `s[j]`. If `s[j] >= g[i]`, we can assign the cookie `j` to the child `i`, and the child `i` will be content. Your goal is to maximize the number of your content children and return the maximum number.

The question is: **how to greedily match the smallest capable cookie to the least greedy child?**

**Example 1:**
```
Input:  g = [1,2,3], s = [1,1]
Output: 1
Explanation: You have 3 children and 2 cookies. The greed factors of 3 children are 1, 2, 3. And even though you have 2 cookies, since their size is both 1, you could only make the child whose greed factor is 1 content.
```

**Example 2:**
```
Input:  g = [1,2], s = [1,2,3]
Output: 2
Explanation: You have 2 children and 3 cookies. You can satisfy all 2 children.
```

**Constraints:**
- $1 \le g.\text{length} \le 3 \times 10^4$
- $0 \le s.\text{length} \le 3 \times 10^4$
- $1 \le g[i], s[j] \le 2^{31} - 1$

## Approach 1 — Greedy with Two Pointers (Sorted) ✅

**Key insight:** Sort both the greed array `g` and cookie size array `s`. Always satisfy the child with the smallest greed factor using the smallest possible cookie that meets their requirement. This leaves larger cookies available for greedier children.

```
g = [1, 2, 3], s = [1, 1]
Sorted: g = [1, 2, 3], s = [1, 1]
child = 0, cookie = 0

cookie 0 (1) >= g[0] (1) -> satisfied! child = 1, cookie = 1
cookie 1 (1) < g[1] (2)  -> too small! cookie = 2 (out of cookies)

Result: child = 1 content child ✓
```

```cpp
class Solution {
public:
    int findContentChildren(vector<int>& g, vector<int>& s) {
        sort(g.begin(), g.end());
        sort(s.begin(), s.end());
        int child = 0, cookie = 0;
        while (child < g.size() && cookie < s.size()) {
            if (s[cookie] >= g[child]) {
                child++; // child is content
            }
            cookie++; // move to next cookie regardless
        }
        return child;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n \log n + m \log m)$ | $O(1)$ |

> **This is the one.** Greedy matching via sorted two-pointer traversal.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| No cookies `s = []` | Accessing empty vector | Loop condition `cookie < s.size()` terminates immediately, returns 0 |
| Cookies too small for everyone | Infinite loop | Cookie index increments and loop ends safely |
| Abundant large cookies | Skipping satisfied children | Each child gets matched greedily until all children satisfied |

---

## Pattern Takeaway

When both consumers and resources have continuous capacity requirements, **sorting both arrays and matching greedily** guarantees optimal utilization without backtracking.
