## What are we solving?

Assume you are an awesome parent and want to give your children some cookies. Each child can receive at most one cookie.

Each child $i$ has a **greed factor** `g[i]`, which is the minimum size of a cookie that the child will be content with. Each cookie $j$ has a size `s[j]`. If `s[j] >= g[i]`, we can assign cookie $j$ to child $i$, making child $i$ content.

Your goal is to **maximize the number of content children** and return the maximum count.

```
 Children Greed:  g = [ 1, 2, 3 ]
 Cookie Sizes:    s = [ 1, 1 ]
 
 Greedy Matching:
 - Cookie 1 (size 1) -> Child 1 (greed 1) -> SATISFIED!
 - Cookie 2 (size 1) < Child 2 (greed 2)  -> TOO SMALL!
 
 Maximum Content Children: 1
 Output: 1
```

### Input & Output Contract
- **Input:**
  - `g`: `vector<int>` ($1 \le |g| \le 3 \times 10^4$, $1 \le g[i] \le 2^{31} - 1$).
  - `s`: `vector<int>` ($0 \le |s| \le 3 \times 10^4$, $1 \le s[j] \le 2^{31} - 1$).
- **Output:**
  - `int`: Maximum number of satisfied children.

### The Greedy Choice Property
To maximize the total count of content children:
- We should satisfy the **least greedy child** using the **smallest capable cookie** ($s[j] \ge g[i]$).
- Wasting a large cookie on a low-greed child reduces the chances of satisfying greedier children later.

---

**Example 1:**
```
Input:  g = [1,2,3], s = [1,1]
Output: 1
Explanation: You have 3 children and 2 cookies. The greed factors are 1, 2, 3.
You can only make the child with greed 1 content.
```

**Example 2:**
```
Input:  g = [1,2], s = [1,2,3]
Output: 2
Explanation: You have 2 children and 3 cookies. You can satisfy both children.
```

**Constraints:**
- $1 \le g.\text{length} \le 3 \times 10^4$
- $0 \le s.\text{length} \le 3 \times 10^4$
- $1 \le g[i], s[j] \le 2^{31} - 1$

## Approach 1 — Smallest Cookie to Least Greedy Child (Ascending Sort) ✅

### Key Insight
1. **Sort both arrays** `g` and `s` in ascending order.
2. Initialize `child = 0`, `cookie = 0`.
3. While `child < g.size() && cookie < s.size()`:
   - If `s[cookie] >= g[child]`: the current smallest cookie satisfies the current least-greedy child $\implies$ advance `child++`.
   - In all cases, the current cookie has been used or is too small $\implies$ advance `cookie++`.
4. Return `child` (which equals the number of content children).

```
g = [1, 2, 3], s = [1, 1]
Sorted: g = [1, 2, 3], s = [1, 1]

Step 1: cookie 0 (1) >= g[0] (1) -> Satisfied! child = 1, cookie = 1
Step 2: cookie 1 (1) < g[1] (2)  -> Too small! cookie = 2 (Exhausted!)

Result: child = 1 ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    int findContentChildren(vector<int>& g, vector<int>& s) {
        sort(g.begin(), g.end());
        sort(s.begin(), s.end());
        
        int child = 0;
        int cookie = 0;
        
        while (child < g.size() && cookie < s.size()) {
            if (s[cookie] >= g[child]) {
                child++; // Child is content, move to next child
            }
            cookie++; // Move to next cookie
        }
        
        return child;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n \log n + m \log m)$ | Sorting $g$ and $s$ dominates runtime; two-pointer scan is $O(n + m)$. |
| **Space** | $O(1)$ auxiliary | In-place sorting. |

> **This is the one.** Standard, optimal greedy resource allocation.

## Approach 2 — Largest Cookie to Most Greedy Child (Descending Sort)

### Intuition
Sort both arrays in descending order. Try to satisfy the greediest child with the largest available cookie. If the largest cookie cannot satisfy the greediest child, that child cannot be satisfied by any cookie.

### C++ Implementation
```cpp
class Solution {
public:
    int findContentChildren(vector<int>& g, vector<int>& s) {
        sort(g.rbegin(), g.rend());
        sort(s.rbegin(), s.rend());
        
        int child = 0, cookie = 0, contentCount = 0;
        while (child < g.size() && cookie < s.size()) {
            if (s[cookie] >= g[child]) {
                contentCount++;
                cookie++;
            }
            child++;
        }
        
        return contentCount;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n \log n + m \log m)$ | Sorting + single two-pointer pass. |
| **Space** | $O(1)$ auxiliary | In-place sorting. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Zero Cookies** | `s = []` | Accessing empty array | `cookie < s.size()` is false immediately, returns 0. |
| **All Cookies Too Small** | `g = [5, 6], s = [1, 2, 3]` | Loop underflow | `cookie` reaches end, returns 0. |
| **More Cookies than Children** | `g = [1], s = [1, 2, 3]` | Overcounting | `child < g.size()` terminates once all children satisfied, returns 1. |

## Pattern Takeaways

1. **Greedy Resource Allocation Invariant:**  
   Sort both demands and supplies; matching the lowest compatible supply to the lowest demand preserves large supplies for larger demands.
