## What are we solving?

Given a string `s` consisting only of the characters `'('`, `')'`, `'{'`, `'}'`, `'['` and `']'`, determine if the input string is **valid**.

An input string is valid if and only if:
1. Every open bracket is closed by the same type of closing bracket.
2. Open brackets are closed in the correct, innermost-first order.
3. Every close bracket corresponds to an existing open bracket.

```
 Valid:    ( [ { } ] )          Valid: ()[]{}
           | | +-+ | |
           | +-----+ |
           +---------+
           
 Invalid:  ( [ ) ]              Invalid: (]
             ^-^ Interleaved!
```

### Input & Output Contract
- **Input:**
  - `s`: `string` containing parentheses characters (`'('`, `')'`, `'{'`, `'}'`, `'['`, `']'`) with length $1 \le n \le 10^4$.
- **Output:**
  - `bool`: `true` if all bracket pairs match in valid nested order; otherwise `false`.

### The Core Challenge
Parentheses follow a **Last-In, First-Out (LIFO)** nesting structure: the most recently opened bracket must be the first one to be closed. When an odd-length string or misordered closing bracket is encountered, we must reject it immediately in linear time $O(n)$.

---

**Example 1:**
```
Input:  s = "()"
Output: true
```

**Example 2:**
```
Input:  s = "()[]{}"
Output: true
```

**Example 3:**
```
Input:  s = "(]"
Output: false
```

**Example 4:**
```
Input:  s = "([])"
Output: true
```

**Constraints:**
- $1 \le s.\text{length} \le 10^4$
- `s` consists of parentheses only `'()[]{}'`.

## Approach 1 — Iterative Substring Replacement (Simulation)

### Intuition
If a string is valid, it must contain at least one adjacent matching pair: `"()"`, `"{}"`, or `"[]"`. Repeatedly remove these adjacent pairs from the string until no more pairs can be found. If the final string is empty `""`, it was valid.

### C++ Implementation
```cpp
class Solution {
public:
    bool isValid(string s) {
        if (s.length() % 2 != 0) return false;
        
        while (true) {
            size_t pos1 = s.find("()");
            if (pos1 != string::npos) { s.erase(pos1, 2); continue; }
            
            size_t pos2 = s.find("{}");
            if (pos2 != string::npos) { s.erase(pos2, 2); continue; }
            
            size_t pos3 = s.find("[]");
            if (pos3 != string::npos) { s.erase(pos3, 2); continue; }
            
            break; // No more matching pairs to remove
        }
        
        return s.empty();
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n^2)$ | Up to $n/2$ iterations, each performing string search and deletion in $O(n)$. |
| **Space** | $O(n)$ | Modifies and shrinks string copies. |

> **Verdict:** Conceptual first instinct, but quadratically slow for long strings ($n = 10^4$).

## Approach 2 — Stack with Map Lookup

### Intuition
Use an explicit stack `stack<char>` to track opening brackets. When a closing bracket arrives, look up its matching opening bracket in a hash map and check if the top of the stack matches.

```
s = "([])"
1. '(' -> open bracket -> push '(' onto stack: ['(']
2. '[' -> open bracket -> push '[' onto stack: ['(', '[']
3. ']' -> close bracket -> top is '[' == match! -> pop
4. ')' -> close bracket -> top is '(' == match! -> pop
Stack empty -> valid! ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    bool isValid(string s) {
        if (s.length() % 2 != 0) return false;
        
        stack<char> st;
        unordered_map<char, char> matching = {
            {')', '('},
            {'}', '{'},
            {']', '['}
        };
        
        for (char c : s) {
            if (matching.count(c)) {
                // Closing bracket: verify stack top
                if (st.empty() || st.top() != matching[c]) {
                    return false;
                }
                st.pop();
            } else {
                // Opening bracket: push to stack
                st.push(c);
            }
        }
        
        return st.empty();
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Single pass through $n$ characters with $O(1)$ stack and map operations. |
| **Space** | $O(n)$ | Stack stores up to $n$ characters. |

## Approach 3 — Stack Pushing Expected Closers ✅

### Key Insight
Instead of pushing opening brackets and mapping them when closing brackets arrive, **push the expected closing character immediately** when an open bracket is seen:
- If `'('` $\rightarrow$ push `')'`
- If `'{'` $\rightarrow$ push `'}'`
- If `'['` $\rightarrow$ push `']'`

When a closing character arrives, the check simplifies to a single direct comparison:
$$\text{if } (\text{st.empty()} \parallel \text{st.top()} \neq c) \rightarrow \text{return false;}$$

```
s = " ( [ { } ] ) "
1. '(' -> push ')' -> stack: [')']
2. '[' -> push ']' -> stack: [')', ']']
3. '{' -> push '}' -> stack: [')', ']', '}']
4. '}' -> st.top() == '}' -> match! pop -> stack: [')', ']']
5. ']' -> st.top() == ']' -> match! pop -> stack: [')']
6. ')' -> st.top() == ')' -> match! pop -> stack: []

Stack is empty -> return true ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    bool isValid(string s) {
        // Odd length strings can never be balanced
        if (s.length() % 2 != 0) return false;
        
        stack<char> st;
        
        for (char c : s) {
            if (c == '(') {
                st.push(')');
            } else if (c == '{') {
                st.push('}');
            } else if (c == '[') {
                st.push(']');
            } else {
                // c is a closing bracket: must match the expected closer at the top
                if (st.empty() || st.top() != c) {
                    return false;
                }
                st.pop();
            }
        }
        
        // Valid only if all opened brackets were successfully matched and popped
        return st.empty();
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n)$ | Single pass. Every character is pushed and popped at most once. |
| **Space** | $O(n)$ | Stack holds at most $n/2$ elements for a valid string (or $n$ for all opening brackets). |

> **This is the one.** Eliminates map overhead and branch complexity with direct expected-char matching.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Odd Length** | `s = "((("` | Impossible to balance | `s.length() % 2 != 0` exits immediately in $O(1)$. |
| **Leading Closer** | `s = "]"` | Stack underflow on `st.top()` | Guard `st.empty()` checked before `st.top()`, returning `false`. |
| **Mismatched Types** | `s = "(]"` | Correct nesting order but wrong bracket type | `st.top() == ')' != ']'` fails equality, returns `false`. |
| **Unclosed Openers** | `s = "(()"` | Stack non-empty at termination | Final `return st.empty()` evaluates to `false`. |

## Pattern Takeaways

1. **The LIFO Nesting Invariant:**  
   Any problem requiring innermost-first matching (e.g. HTML/XML tags, nested function calls, mathematical expressions) is fundamentally solvable with a **Stack**.
2. **Push-the-Expected Pattern:**  
   Pushing expected counterpart values simplifies comparison logic across parser and syntax validation problems.
