## What are we solving?

Given a string `s` containing just the characters `'('`, `')'`, `'{'`, `'}'`, `'['` and `']'`, determine if the input string is valid.

An input string is valid if:
1. Open brackets must be closed by the same type of brackets.
2. Open brackets must be closed in the correct order.
3. Every close bracket has a corresponding open bracket of the same type.

The question is: **how does LIFO stack matching verify nested bracket balance in $O(n)$ time?**

**Example 1:**
```
Input:  s = "()"
Output: true
```

**Example 2:**
```
Input:  s = "()[]{}"
Output: true
```

**Example 3:**
```
Input:  s = "(]"
Output: false
```

**Example 4:**
```
Input:  s = "([])"
Output: true
```

**Constraints:**
- $1 \le s.\text{length} \le 10^4$
- `s` consists of parentheses only `'()[]{}'`.

## Approach 1 — Stack Push Matching Closer ✅

**Key insight:**
When encountering an opening bracket, push its expected **closing bracket** onto the stack:
- If `'('` $\rightarrow$ push `')'`
- If `'{'` $\rightarrow$ push `'}'`
- If `'['` $\rightarrow$ push `']'`
When encountering a closing bracket:
- If stack is empty or `st.top() != c`, it's invalid $\rightarrow$ return `false`.
- Pop matching bracket.
At the end, string is valid if and only if `st.empty()`.

```
s = "([{}])"
1. '(' -> push ')' -> stack: [')']
2. '[' -> push ']' -> stack: [')', ']']
3. '{' -> push '}' -> stack: [')', ']', '}']
4. '}' -> top is '}' -> pop -> stack: [')', ']']
5. ']' -> top is ']' -> pop -> stack: [')']
6. ')' -> top is ')' -> pop -> stack: []
Stack is empty -> return true ✓
```

```cpp
class Solution {
public:
    bool isValid(string s) {
        stack<char> st;
        for (char c : s) {
            if (c == '(') st.push(')');
            else if (c == '{') st.push('}');
            else if (c == '[') st.push(']');
            else {
                if (st.empty() || st.top() != c) return false;
                st.pop();
            }
        }
        return st.empty();
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(n)$ |

> **This is the one.** Pushing expected closing characters makes matching branch-free and clean.

---

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Odd length string | Parentheses cannot be paired | Stack will not be empty at the end, returns `false` |
| Starts with closing bracket `"]"` | Stack underflow | `st.empty()` check returns `false` |
| Unclosed opening brackets `"(("` | Checking stack emptiness | `st.empty()` returns `false` |

---

## Pattern Takeaway

Pushing the **expected closing delimiter** rather than opening delimiter simplifies character matching to a direct equality check `st.top() == c`.
