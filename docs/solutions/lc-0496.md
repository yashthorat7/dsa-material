## What are we solving?

The **next greater element** of some element $x$ in an array is the **first greater element** to its right in the same array.

You are given two **distinct** 0-indexed integer arrays `nums1` and `nums2`, where `nums1` is a subset of `nums2`.

For each `0 <= i < nums1.length`, find the index $j$ such that `nums1[i] == nums2[j]` and determine the next greater element of `nums2[j]` in `nums2`. If there is no next greater element, then the answer for this query is `-1`.

Return an array `ans` of length `nums1.length` containing the answers.

```
 nums1 = [ 4, 1, 2 ]
 nums2 = [ 1, 3, 4, 2 ]
 
 In nums2:
 - Next greater for 1 is 3
 - Next greater for 3 is 4
 - Next greater for 4 is None (-1)
 - Next greater for 2 is None (-1)
 
 Queries from nums1:
 - 4 -> -1
 - 1 ->  3
 - 2 -> -1
 
 Output: [ -1, 3, -1 ]
```

### Input & Output Contract
- **Input:**
  - `nums1`: `vector<int>` ($1 \le n_1 \le n_2 \le 1000$).
  - `nums2`: `vector<int>` (all elements unique, $0 \le \text{nums}[i] \le 10^4$).
- **Output:**
  - `vector<int>` of length $n_1$ containing next greater elements.

---

**Example 1:**
```
Input:  nums1 = [4,1,2], nums2 = [1,3,4,2]
Output: [-1,3,-1]
Explanation: The next greater element for each value of nums1 is:
- 4: in nums2 [1,3,4,2], there is no next greater element -> -1.
- 1: in nums2 [1,3,4,2], next greater is 3.
- 2: in nums2 [1,3,4,2], there is no next greater element -> -1.
```

**Example 2:**
```
Input:  nums1 = [2,4], nums2 = [1,2,3,4]
Output: [3,-1]
```

**Constraints:**
- $1 \le \text{nums1.length} \le \text{nums2.length} \le 1000$
- $0 \le \text{nums1}[i], \text{nums2}[i] \le 10^4$
- All integers in `nums1` and `nums2` are unique.
- All the integers of `nums1` also appear in `nums2`.

## Approach 1 — Brute Force Nested Search ($O(n_1 \cdot n_2)$)

### Intuition
For each element $x$ in `nums1`, find its position $j$ in `nums2`, and scan to the right from $j + 1 \dots n_2 - 1$ for the first value greater than $x$.

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> nextGreaterElement(vector<int>& nums1, vector<int>& nums2) {
        vector<int> ans;
        int n2 = nums2.size();
        
        for (int x : nums1) {
            int foundIdx = -1;
            for (int j = 0; j < n2; j++) {
                if (nums2[j] == x) {
                    foundIdx = j;
                    break;
                }
            }
            
            int nextGreater = -1;
            for (int k = foundIdx + 1; k < n2; k++) {
                if (nums2[k] > x) {
                    nextGreater = nums2[k];
                    break;
                }
            }
            ans.push_back(nextGreater);
        }
        
        return ans;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n_1 \cdot n_2)$ | Nested loops scanning `nums2` for each query in `nums1`. |
| **Space** | $O(1)$ auxiliary | Output vector memory only. |

> **Verdict:** Suboptimal. Monotonic stack precomputes all next greater elements in $O(n_2)$ linear time.

## Approach 2 — Monotonic Decreasing Stack + Hash Map ✅

### Key Insight
Precompute the next greater element for **all elements in `nums2`** in a single $O(n_2)$ pass using a monotonic stack:
1. Maintain a stack `st` storing values in strictly decreasing order.
2. For each number `x` in `nums2`:
   - While `!st.empty() && st.top() < x`:
     - The incoming number `x` is the **first greater element** for `st.top()`!
     - Record `nextGreater[st.top()] = x`.
     - Pop `st.pop()`.
   - Push `st.push(x)`.
3. Any elements remaining in `st` have no greater right neighbor $\implies \text{nextGreater}[st] = -1$.
4. Populate `result` by looking up each query `nums1[i]` in `nextGreater` in $O(1)$.

```
nums2 = [1, 3, 4, 2], nums1 = [4, 1, 2]
st = [], nextGreater = {}

x=1: push 1 -> st = [1]
x=3: 3 > 1 -> nextGreater[1] = 3, pop 1 -> push 3 -> st = [3]
x=4: 4 > 3 -> nextGreater[3] = 4, pop 3 -> push 4 -> st = [4]
x=2: 2 < 4 -> push 2 -> st = [4, 2]

Remaining in stack: nextGreater[4] = -1, nextGreater[2] = -1.

Map: {1: 3, 3: 4, 4: -1, 2: -1}
Query nums1 [4, 1, 2] -> [ -1, 3, -1 ] ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> nextGreaterElement(vector<int>& nums1, vector<int>& nums2) {
        unordered_map<int, int> nextGreater;
        stack<int> st; // Monotonic decreasing stack
        
        // Pass 1: Resolve next greater element for all items in nums2
        for (int x : nums2) {
            while (!st.empty() && st.top() < x) {
                nextGreater[st.top()] = x;
                st.pop();
            }
            st.push(x);
        }
        
        // Unresolved elements in stack have no greater element to the right
        while (!st.empty()) {
            nextGreater[st.top()] = -1;
            st.pop();
        }
        
        // Pass 2: Query results for nums1 in O(1) time each
        vector<int> ans;
        ans.reserve(nums1.size());
        for (int x : nums1) {
            ans.push_back(nextGreater[x]);
        }
        
        return ans;
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(n_1 + n_2)$ | Each element of `nums2` pushed and popped at most once ($O(n_2)$); query pass is $O(n_1)$. |
| **Space** | $O(n_2)$ | Hash map and stack store $n_2$ elements. |

> **This is the one.** Clean, robust, foundational Next Greater Element pattern.

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Strictly Decreasing Array** | `nums2 = [5, 4, 3, 2, 1]` | Stack never pops during loop | Stack drain loop assigns `-1` to all elements. |
| **Strictly Increasing Array** | `nums2 = [1, 2, 3, 4, 5]` | Stack size | Every element pops immediately, stack holds at most 1 element. |

## Pattern Takeaways

1. **Monotonic Stack Invariant:**  
   $$\text{Current Element } x > \text{Stack Top} \implies x \text{ is the Next Greater Element for } \text{Stack Top}$$
