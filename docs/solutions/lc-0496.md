## What are we solving?

The **next greater element** of some element `x` in an array is the **first greater** element to its right in the same array.

You are given two **distinct** 0-indexed integer arrays `nums1` and `nums2`, where `nums1` is a subset of `nums2`. For each `0 <= i < nums1.length`, find the index `j` such that `nums1[i] == nums2[j]` and determine the next greater element of `nums2[j]` in `nums2`. If there is no next greater element, then the answer for this query is `-1`.

Return an array `ans` of length `nums1.length` such that `ans[i]` is the next greater element as described above.

**Example 1:**
```
Input:  nums1 = [4,1,2], nums2 = [1,3,4,2]
Output: [-1,3,-1]
Explanation: The next greater element for each value of nums1 is:
- 4: in nums2 [1,3,4,2], there is no next greater element -> -1.
- 1: in nums2 [1,3,4,2], next greater is 3.
- 2: in nums2 [1,3,4,2], there is no next greater element -> -1.
```

**Example 2:**
```
Input:  nums1 = [2,4], nums2 = [1,2,3,4]
Output: [3,-1]
```

**Constraints:**
- $1 \le \text{nums1.length} \le \text{nums2.length} \le 1000$
- $0 \le \text{nums1}[i], \text{nums2}[i] \le 10^4$
- All integers in `nums1` and `nums2` are unique.
- All the integers of `nums1` also appear in `nums2`.

## Approach 1 — Monotonic Stack + Hash Map ✅

**Key insight:**
Use a **monotonic decreasing stack** to find the next greater element for all items in `nums2` in a single pass:
1. Iterate through `nums2`. While `!st.empty() && st.top() < x`:
   - `x` is the next greater element for `st.top()`!
   - Store `nextGreater[st.top()] = x`.
   - `st.pop()`.
2. Push `x` onto `st`.
3. For elements remaining in stack, their next greater is `-1`.
4. Answer queries for `nums1` in $O(1)$ from the map.

```
nums2 = [1, 3, 4, 2], nums1 = [4, 1, 2]
stack = [], nextGreater = {}

x = 1: push 1 -> stack: [1]
x = 3: 3 > 1 -> nextGreater[1] = 3, pop 1 -> push 3 -> stack: [3]
x = 4: 4 > 3 -> nextGreater[3] = 4, pop 3 -> push 4 -> stack: [4]
x = 2: 2 < 4 -> push 2 -> stack: [4, 2]
Remaining in stack (4, 2) get -1.

Map: {1: 3, 3: 4, 4: -1, 2: -1}
Query nums1: [4, 1, 2] -> [-1, 3, -1] ✓
```

```cpp
class Solution {
public:
    vector<int> nextGreaterElement(vector<int>& nums1, vector<int>& nums2) {
        unordered_map<int, int> nextGreater;
        stack<int> st;
        
        for (int x : nums2) {
            while (!st.empty() && st.top() < x) {
                nextGreater[st.top()] = x;
                st.pop();
            }
            st.push(x);
        }
        
        while (!st.empty()) {
            nextGreater[st.top()] = -1;
            st.pop();
        }
        
        vector<int> ans;
        for (int x : nums1) {
            ans.push_back(nextGreater[x]);
        }
        return ans;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n_1 + n_2)$ | $O(n_2)$ |

> **This is the one.** Standard monotonic stack precomputation.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| Strictly decreasing array `[5, 4, 3, 2, 1]` | No elements popped during scan | Post-loop assigns `-1` to all entries |
| Strictly increasing array `[1, 2, 3, 4, 5]` | Stack emptying | Every element immediately pops previous element |

---

## Pattern Takeaway

A **Monotonic Decreasing Stack** resolves the 'Next Greater Element' for all elements in a single $O(n)$ pass.
