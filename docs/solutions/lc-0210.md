## What are we solving?

There are a total of `numCourses` courses you have to take, labeled from `0` to `numCourses - 1`. You are given an array `prerequisites` where `prerequisites[i] = [ai, bi]` indicates that you must take course `bi` first if you want to take course `ai` ($b_i \rightarrow a_i$).

Return the **ordering of courses** you should take to finish all courses.
- If there are multiple valid topological orderings, return **any of them**.
- If it is impossible to finish all courses (a cycle exists), return an **empty array `[]`**.

```
 Prerequisites: [ [1, 0], [2, 0], [3, 1], [3, 2] ]
 
 Dependency Graph:
           (1)
          /   \
        (0)    (3)
          \   /
           (2)
           
 Valid Linear Orders: [0, 1, 2, 3] or [0, 2, 1, 3]
```

### Input & Output Contract
- **Input:**
  - `numCourses`: `int` number of vertices ($1 \le V \le 2000$).
  - `prerequisites`: `vector<vector<int>>` where $[a_i, b_i]$ represents directed edge $b_i \rightarrow a_i$ ($0 \le E \le V(V-1)$).
- **Output:**
  - `vector<int>` of size $V$ containing a valid linear sequence, or `[]` if deadlocked by a cycle.

### The Core Challenge
Beyond simply detecting cycles as in Course Schedule I, we must reconstruct the actual **Topological Sort Order**. In a valid DAG, every directed edge $u \rightarrow v$ guarantees that $u$ appears before $v$ in the output sequence.

---

**Example 1:**
```
Input:  numCourses = 2, prerequisites = [[1,0]]
Output: [0,1]
Explanation: There are a total of 2 courses to take. To take course 1 you should have finished course 0. So the correct course order is [0,1].
```

**Example 2:**
```
Input:  numCourses = 4, prerequisites = [[1,0],[2,0],[3,1],[3,2]]
Output: [0,2,1,3]
Explanation: [0,1,2,3] is also a valid answer.
```

**Example 3:**
```
Input:  numCourses = 1, prerequisites = []
Output: [0]
```

**Constraints:**
- $1 \le \text{numCourses} \le 2000$
- $0 \le \text{prerequisites.length} \le \text{numCourses} \times (\text{numCourses} - 1)$
- $\text{prerequisites}[i].\text{length} == 2$
- $0 \le a_i, b_i < \text{numCourses}$
- All the pairs `[ai, bi]` are distinct.

## Approach 1 — Kahn's Algorithm (BFS In-Degree Queue) ✅

### Intuition
1. Build adjacency list `adj[u]` ($b \rightarrow a$) and calculate in-degrees `inDegree[u]`.
2. Enqueue all courses with `inDegree == 0` into a FIFO queue.
3. As courses are dequeued, append each course `u` to our `order` result vector.
4. For each dependent neighbor `v` in `adj[u]`, decrement `inDegree[v]--`. When `inDegree[v] == 0`, enqueue `v`.
5. If `order.size() == numCourses`, return `order`. If `order.size() < numCourses`, a cycle prevented remaining nodes from ever reaching 0 in-degree $\rightarrow$ return `{}`.

```
numCourses = 4, prereqs = [[1,0],[2,0],[3,1],[3,2]]
inDegree: {0:0, 1:1, 2:1, 3:2}
q = [0], order = []

1. Dequeue 0: order = [0]. inDegree[1]=0, inDegree[2]=0 -> q = [1, 2]
2. Dequeue 1: order = [0, 1]. inDegree[3]=1
3. Dequeue 2: order = [0, 1, 2]. inDegree[3]=0 -> q = [3]
4. Dequeue 3: order = [0, 1, 2, 3]

order.size() == 4 == numCourses -> returns [0, 1, 2, 3] ✓
```

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> findOrder(int numCourses, vector<vector<int>>& prerequisites) {
        vector<vector<int>> adj(numCourses);
        vector<int> inDegree(numCourses, 0);
        
        for (const auto& edge : prerequisites) {
            int course = edge[0];
            int prereq = edge[1];
            adj[prereq].push_back(course);
            inDegree[course]++;
        }
        
        queue<int> q;
        for (int i = 0; i < numCourses; i++) {
            if (inDegree[i] == 0) {
                q.push(i);
            }
        }
        
        vector<int> order;
        order.reserve(numCourses);
        
        while (!q.empty()) {
            int u = q.front();
            q.pop();
            order.push_back(u);
            
            for (int v : adj[u]) {
                inDegree[v]--;
                if (inDegree[v] == 0) {
                    q.push(v);
                }
            }
        }
        
        // If graph has a cycle, order.size() will be less than numCourses
        if (order.size() == numCourses) {
            return order;
        }
        return {};
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(V + E)$ | Graph construction takes $O(E)$; each node and edge is processed once. |
| **Space** | $O(V + E)$ | Adjacency list takes $O(V + E)$, inDegree array and queue take $O(V)$. |

> **This is the one.** Clean, robust BFS with natural in-order sequence generation.

## Approach 2 — DFS Post-Order with 3-State Cycle Detection

### Intuition
Perform DFS on the graph. A node can be added to the topological order once **all its descendants have been fully explored**.  
Because a node is finished *after* its children, appending to `order` produces a reversed topological sort. We reverse `order` at the end!  
State tracking:
- `0`: Unvisited
- `1`: Visiting (active on current DFS branch $\rightarrow$ encountering this indicates a cycle)
- `2`: Visited

### C++ Implementation
```cpp
class Solution {
public:
    vector<int> findOrder(int numCourses, vector<vector<int>>& prerequisites) {
        vector<vector<int>> adj(numCourses);
        for (const auto& edge : prerequisites) {
            adj[edge[1]].push_back(edge[0]);
        }
        
        vector<int> state(numCourses, 0);
        vector<int> order;
        bool hasCycle = false;
        
        for (int i = 0; i < numCourses; i++) {
            if (state[i] == 0) {
                dfs(i, adj, state, order, hasCycle);
                if (hasCycle) return {};
            }
        }
        
        // Reverse post-order to get valid topological ordering
        reverse(order.begin(), order.end());
        return order;
    }

private:
    void dfs(int u, const vector<vector<int>>& adj, vector<int>& state,
             vector<int>& order, bool& hasCycle) {
        if (hasCycle) return;
        
        state[u] = 1; // Visiting
        
        for (int v : adj[u]) {
            if (state[v] == 1) {
                hasCycle = true;
                return;
            }
            if (state[v] == 0) {
                dfs(v, adj, state, order, hasCycle);
            }
        }
        
        state[u] = 2; // Visited
        order.push_back(u); // Post-order collection
    }
};
```

### Complexity Analysis
| Metric | Complexity | Explanation |
|:-------|:-----------|:------------|
| **Time** | $O(V + E)$ | Each vertex and edge traversed once. |
| **Space** | $O(V + E)$ | Recursion stack depth $V$ + graph storage. |

## Edge Cases to Watch

| Case | Input Example | Trap | How it's handled |
|:-----|:--------------|:-----|:-----------------|
| **Graph has Cycle** | `[[1, 0], [0, 1]]` | Returning partial ordering | `order.size() < numCourses` triggers, returning empty array `{}`. |
| **Single Course, No Prereqs** | `numCourses = 1, []` | Empty return | `inDegree[0] = 0`, dequeues and returns `[0]`. |
| **Disconnected Components** | `4 courses, [[1, 0]]` | Missing unlinked nodes | Courses 2 and 3 start with `inDegree = 0`, queued and returned in sequence. |

## Pattern Takeaways

1. **Kahn's Sequence Property:**  
   The sequence in which nodes are popped from the queue in Kahn's algorithm is mathematically a valid **Topological Sort**.
2. **Reverse Post-Order Duality:**  
   Topological sort can be achieved either by **Forward BFS with In-Degrees** or **Reverse DFS Post-Order**.
