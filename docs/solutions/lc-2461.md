## What are we solving?

You are given an integer array `nums` and an integer `k`. Find the maximum subarray sum of all the subarrays of `nums` that meet the following conditions:
1. The length of the subarray is `k`, and
2. All the elements of the subarray are **distinct**.

Return the maximum subarray sum of all the subarrays that meet the conditions. If no subarray meets the conditions, return `0`.

The core challenge is: **how do we maintain a fixed-size window of length `k` while tracking both the running sum and element uniqueness in $O(1)$ per step?**

**Example 1:**
```
Input:  nums = [1,5,4,2,9,9,9], k = 3
Output: 15
Explanation: The subarrays of nums with length 3 are:
- [1,5,4] which meets the requirements and has a sum of 10.
- [5,4,2] which meets the requirements and has a sum of 11.
- [4,2,9] which meets the requirements and has a sum of 15.
- [2,9,9] does not meet requirements because element 9 is repeated.
- [9,9,9] does not meet requirements.
Return 15 because it is the maximum subarray sum of all valid subarrays.
```

**Example 2:**
```
Input:  nums = [4,4,4], k = 3
Output: 0
Explanation: The subarrays of nums with length 3 are [4,4,4] which does not meet requirements. Return 0.
```

**Constraints:**
- $1 \le k \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^5$

## Approach 1 — Fixed Sliding Window with Hash Map / Frequency Count ✅

**Key insight:** Maintain a running window of size `k`.
- Track the running sum in a 64-bit integer (`long long`).
- Use an `unordered_map<int, int>` (or frequency array) to count occurrences of elements in the current window.
- When `right` advances: add `nums[right]` to `runningSum` and increment its frequency.
- When window size exceeds `k` (i.e. `right - left + 1 > k`): subtract `nums[left]` from `runningSum`, decrement frequency (remove key if count hits 0), and advance `left`.
- When window size is exactly `k` and `freqMap.size() == k` (meaning all `k` elements are distinct): update `maxSum = max(maxSum, runningSum)`.

```
nums = [1, 5, 4, 2, 9, 9, 9], k = 3
window = [], runningSum = 0, freq = {}, maxSum = 0

right=0 (1): sum=1, freq={1:1}
right=1 (5): sum=6, freq={1:1, 5:1}
right=2 (4): sum=10, freq={1:1, 5:1, 4:1}. size=3, unique=3 -> maxSum = 10
right=3 (2): remove nums[0]=1 -> sum=10-1+2=11, freq={5:1, 4:1, 2:1}. unique=3 -> maxSum = 11
right=4 (9): remove nums[1]=5 -> sum=11-5+9=15, freq={4:1, 2:1, 9:1}. unique=3 -> maxSum = 15
right=5 (9): remove nums[2]=4 -> sum=15-4+9=20, freq={2:1, 9:2}. unique=2 (< 3) -> skip
right=6 (9): remove nums[3]=2 -> sum=20-2+9=27, freq={9:3}. unique=1 (< 3) -> skip

Result: 15 ✓
```

```cpp
class Solution {
public:
    long long maximumSubarraySum(vector<int>& nums, int k) {
        long long maxSum = 0, runningSum = 0;
        unordered_map<int, int> freq;
        int left = 0;
        
        for (int right = 0; right < nums.size(); right++) {
            runningSum += nums[right];
            freq[nums[right]]++;
            
            if (right - left + 1 > k) {
                runningSum -= nums[left];
                freq[nums[left]]--;
                if (freq[nums[left]] == 0) {
                    freq.erase(nums[left]);
                }
                left++;
            }
            
            if (right - left + 1 == k && freq.size() == k) {
                maxSum = max(maxSum, runningSum);
            }
        }
        return maxSum;
    }
};
```

| Time | Space |
|:-----|:------|
| $O(n)$ | $O(k)$ |

> **This is the one.** Clean fixed-size sliding window with $O(1)$ amortized map updates.

## Edge Cases to Watch

| Case | Trap | How it's handled |
|:-----|:-----|:-----------------|
| No valid distinct subarray `[4, 4, 4], k = 3` | Returning non-zero sum | `freq.size() == k` condition fails on all steps, returns 0 |
| `k = 1` | Single element subarrays | Every element is trivially distinct, returns maximum single element |
| Sum overflows 32-bit `nums[i] = 10^5, k = 10^5` | Integer overflow | Use `long long` for `runningSum` and `maxSum` |

---

## Pattern Takeaway

When a problem demands a **fixed-size window with uniqueness constraints**, combining a **fixed sliding window** with a **frequency map size check** ensures clean, linear execution without redundant hashing.
